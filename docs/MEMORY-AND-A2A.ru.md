# Документация: конвейер памяти `dsh-pamyat` и межагентская почта (A2A)

> **Оригинал — русский.** Английская редакция — [`MEMORY-AND-A2A.md`](MEMORY-AND-A2A.md), перевод с русского.
> Правка вносится **парой**: изменил один файл — измени второй в том же коммите.
> **Версия документа: 2026-09-04 (ред. 4 — §5.1.6 alpha.28 принята; ред. 3 — alpha.26/alpha.27; ред. 2 — §6.1 сторона отправителя, §5.1.6 alpha.25).** Описано по коду репозитория на эту дату; версии пакетов —
> в таблице §1.3. Всё, что зависит от состояния реестра npm (метки `latest`/`alpha`), в документе
> **не** считается устойчивым — см. §7 «Установка» и §8 «Порядок выпуска».

Этот документ — про **устройство**: какие пакеты составляют конвейер, за какие швы платформы
они цепляются, какие службы друг другу дают, какими настройками управляются, как отказывают и
как проверяются. Как **установить** каждый пакет — в README пакета; здесь только то, что
понимаешь, лишь увидев все части рядом.

Терминология. Имена служб, настроек, классов и исходов даны **как в коде** — транслитерацией
русского (`pamyat`, `nudzh`, `byudzhet`, `zapisat`, `obyavlennyj`). Словарь — в приложении Б.
«Платформа» = [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness); «шов» —
событие или хук платформы, за который цепляется плагин; «крик» — строка, которую пакет печатает в
`stderr` при отказе или на подъёме.

## 1. Что здесь и для кого

### 1.1. Две части

**Память** — семейство `dsh-pamyat`, семь пакетов. Платформа сжимает длинный разговор в сводку
(компакцию), и эта сводка живёт только в процессе: перезапуск — и её нет. Семейство даёт агенту
память, переживающую компакцию и перезапуск, и делит работу на слои, каждый из которых делает
одно и **вслух говорит, чего не умеет**.

**Межагентская почта (A2A)** — способ агентам на одной машине, живущим под разными системными
пользователями, писать друг другу, не ломая изоляции. Две части: `a2a-bus` (спул-каталог,
почтальон от `root`, таймер) и читающая сторона в `telegram-multiagent` (опрос ящика, подача письма
в ход агента, ответ в чат владельца).

Части независимы: память работает без почты, почта — без памяти. Вместе они дают то, ради чего
всё писалось: агент, который после перезапуска помнит, что делал, и может спросить соседа.

### 1.2. Кому читать

- Тому, кто **ставит** конвейер на свой узел — §2 (карта), §7 (установка), §9 (проверка).
- Тому, кто **пишет соседний плагин** и хочет звать службы памяти — §3 (швы), §4 (службы).
- Тому, кто **выпускает** новые версии — §8 (порядок выпуска и приёмки).
- Тому, кто **разбирает отказ** — раздел «Отказы» в карточке каждого пакета (§5) и §6.

## 2. Карта конвейера

### 2.1. Жизнь одной сессии

```
 старт процесса
   │
   ├─ подъём плагинов: каждый печатает строку «подъём: …» с версией и настройками
   │
   ├─ первый шаг после старта ──► restore (слой C): брифинг из памяти под бюджет byudzhet,
   │                               не чаще welcomeInterval на сессию (отметка на диске)
   │
   ├─ ход за ходом:
   │     assistant/message ──► nudzh: учесть usage, пересчитать занятость окна
   │     agent/pre-step   ──► nudzh: если занятость ≥ predel×dolyaTrevogi — ОДНА вставка
   │                          «пора сжимать» (source.kind = plugin)
   │     /compact-status  ──► telegram-multiagent: сколько токенов и далеко ли до порога
   │
   ├─ компакция платформы (по её порогу или по /compact):
   │     compaction/summary ──► secretary: сводка + verbatim-ссылка на затенённый диапазон
   │                              → pamyat.zapisat({klass:'svodka-kompakcii', …})
   │                              → core: фильтр входа → политика → SQLite → журнал
   │                              → (если смонтирован omega) очередь долговременного слоя
   │                            ──► nudzh: учесть usage сводки
   │     compaction/end     ──► restore (слой B): на ПЕРВОМ шаге после — поднять запись
   │                              класса svodka-kompakcii обратно в контекст
   │
   └─ перезапуск процесса ──► всё, что в контексте, пропало; всё, что в SQLite, — нет.
                              Следующий старт начинается с брифинга (слой C).
```

Три вещи, которые на карте не видны, но которые важнее самой карты:

1. **Ядро (`core`) ничего не слушает.** Оно не знает о компакции. Единственный его шов — `dispose`
   (закрыть базу). Всё, что попадает в память, попадает через вызов `pamyat.zapisat(...)` из
   другого пакета или плагина.
2. **Слои читают друг друга через службы**, а не через события: `restore` зовёт `pamyat` и
   `byudzhetPamyati`; `secretary` зовёт `pamyat`; `core` зовёт `pamyatDolgovremennaya`, если она
   есть. Кто что даёт и как берёт — §4.
3. **Отказ — вслух, не молча.** Каждый слой на подъёме печатает строку с версией и настройками, а
   при отказе — что именно не получилось. Ноль строк на подъёме означает, что пакет **не
   смонтирован**, а не что «всё тихо».

### 2.2. Что где лежит

| Что | Где | Кто пишет | Кто читает |
|---|---|---|---|
| записи памяти (`zapisi`), очередь долговременного слоя (`ochered_dolgovremennogo`), журнал решений (`zhurnal`) | один файл SQLite, путь `putBazy` (настройка `core`) | `core` | `core`; через службу — `restore`, `secretary` |
| отметки «когда давался брифинг» | JSON `{ [sid]: timestamp }`, путь `welcomeOtmetki` (настройка `restore`), по умолчанию `~/.dsh-pamyat-welcome-otmetki.json` | `restore` | `restore` |
| журнал сессии платформы | путь `putZhurnala` (настройка `secretary`) | платформа | `secretary` (только при дистилляции) |
| внешнее хранилище знаний | адрес `adres` (настройка `omega`), MCP по HTTP | `omega` | `omega` (перечитывание для подтверждения) |
| письма A2A | `/var/spool/a2a/<пользователь>` (умолчание `A2A_KOREN`), либо `<a2aDir>/in`, `<a2aDir>/out` | отправитель, почтальон | `telegram-multiagent` |

## 3. Швы платформы, за которые цепляется конвейер

Точные имена — из кода; «водопад» означает, что хук сначала зовёт `next()` и правит **результат**,
а не подменяет его.

| Шов | Кто | Что делает | Где в коде |
|---|---|---|---|
| `session/event` тип `compaction/summary` | `secretary` | разбирает `summary`, `shadowedSeqs`, `shadowedTokenCount`, `compactionId`; пишет сводку в `pamyat` с источником `<сессия>#<первый>-<последний>`; при включённой дистилляции — отдельный заход | `secretary/src/index.js` |
| `session/event` типы `assistant/message`, `compaction/summary` | `nudzh` | берёт `event.data.usage`, считает вход последнего вызова и сумму | `nudzh/src/index.js` |
| `session/event` тип `compaction/end` | `restore` | запоминает, что был компакт (по `session.id`, `compactionId`); сама вставка — на следующем `agent/pre-step` | `restore/src/index.js` |
| `agent/pre-step` (водопад, `prepend: true`) | `restore` | слой B: первый шаг после `compaction/end` — вставить сводку; слой C: первый шаг после старта процесса — брифинг под бюджет | `restore/src/index.js` |
| `agent/pre-step` (водопад) | `nudzh` | при переходе порога — одна вставка-напоминание; при `decision.kind === 'reject'` или отменённом сигнале — ничего | `nudzh/src/index.js` |
| `dispose` | `core` | закрыть базу | `core/src/index.js` |
| `session/event` типы `goal/change`, `turn/start`, `turn/end`, `assistant/message` | `telegram-multiagent` | доставка ответов в чат/канал, снятие вопроса из очереди, причина ошибки хода | `telegram-multiagent/src/index.js` |
| `command/run` (через реестр `commands`) | `telegram-multiagent` | `/compact` → штатная компакция; `/compact-status` → сводка занятости | там же |

**Чего в этой таблице нет — и это не пропуск.** `core`, `byudzhet` и `omega` не слушают ни одного
события: они работают по вызову. Отдельных событий `PreCompact`/`PostCompact` у платформы нет —
компакция видна только через `compaction/summary` и `compaction/end` в `session/event`.
`telegram-multiagent` **не** слушает события компакции вовсе: команду `/compact` он лишь
разворачивает в имя штатной команды платформы, а её исполнение — дело платформы.

**Вставка в контекст — только штатной фабрикой.** И `restore`, и `nudzh` вставляют сообщение через
`createUserMessage` из `@deepseek-ai/dsh-llm/message` с `source.kind = 'plugin'`: `restore` кладёт
опознаватели поднятых записей в `source.sections` именами `dsh-pamyat-restore#zapis-<id>`; `nudzh`
— `form: 'snapshot'`. Прямой записи в сессию ни у кого нет.

## 4. Службы: кто что даёт и кто берёт

### 4.1. Таблица служб

| Служба (`ctx.provide`) | Даёт | Методы | Берут |
|---|---|---|---|
| `pamyat` | `core` | `dostupna()`, `pochemuNedostupna()`, `reshit(klass)`, `istolkovat(ishod, kanalEst)`, `zapisat({klass, soderzhim, istochnik?, podtverzhdenie?, vera?}) → id`, `otmetitOtkaz({klass, priroda, pochemu, istochnik?})`, `prochitat({klass?, skolko?})`, `svodka()`, `ocheredDostavki()`, `dostavitOtlozhennoe({predelPopytok = 5})` | `secretary` (через `inject`), `restore` (через `ctx.get`) |
| `pamyatDolgovremennaya` | `omega` | `dostupna()`, `pochemuNedostupna()`, `sohranit({soderzhim, tip = 'memory', metadannye = {}, kto = null}) → {sostoyanie, id, pochemu}`, `proverit({id, obrazec = null}) → {sostoyanie, pochemu}` | `core` (через `ctx.get`, необязательно) |
| `nudzhPamyati` | `nudzh` | `uchest(usage)`, `itog()`, `raskhodVyzova(usage)`, `hvatitLi()` | пока никто из семейства; открыто для соседей |
| `byudzhetPamyati` | `byudzhet` | `edinicy()`, `ocenit(zapis)`, `sverit({nashe, platformennoe})`, `otobrat({zapisi, predel, poryadok, porogVery}) → {podnyato, otbrosheno, svodka}` | `restore` (через `ctx.get`, слой C) |

### 4.2. `inject` против `ctx.get` — правило семейства

Платформа даёт два способа взять службу. Объявить её в `inject` — значит, что плагин **не
поднимется**, пока службы нет; взять `ctx.get(имя)` — значит, что плагин поднимется и сам решит,
что делать при её отсутствии. Семейство пользуется обоими, и выбор осознанный:

- `secretary` объявляет `inject = ['pamyat']`: без ядра секретарю делать нечего, и лучше не
  подняться, чем подняться и молча терять сводки.
- `restore` и `nudzh` объявляют `inject = ['agents']`, а память берут `ctx.get('pamyat')`: если
  ядра нет, слой поднимается и **кричит** на каждом шаге, где должен был вставить, — это виднее,
  чем отсутствие плагина в списке.
- `core` берёт `ctx.get('pamyatDolgovremennaya')`: долговременный слой необязателен по замыслу.
- `telegram-multiagent` **намеренно не объявляет** в `inject` ни `compaction`, ни `tokenMeter`:
  объявление вгоняло копию платформы в состояние `pending: waiting for service: compaction`, и связь с
  владельцем не поднималась вовсе. Службы берутся `ctx.get(...)`.

Ловушка, записанная в коде: обращение `ctx.<служба>` без `inject` бросает
`cannot get property "…" without inject`. Читать нужно `ctx.get('…')`.

### 4.3. Что службы гарантируют и чего нет

- `pamyat.zapisat` возвращает `id` **решения о записи**, не факт доставки в долговременный слой.
  Что осталось недоставленным — отвечает `ocheredDostavki()`.
- `pamyatDolgovremennaya.sohranit` подтверждает доставку **перечитыванием** записи по опознавателю,
  а не ответом «принято». Но перечитывание идёт тем же интерфейсом, что и запись: подмену пустого
  хранилища бодрым интерфейсом оно не ловит.
- `nudzhPamyati.hvatitLi()` **никогда** не отвечает «хватает» — только `porog-pereyden` или
  `neizvestno`. Молчание нуджа не означает запаса.
- `byudzhetPamyati.otobrat` считает **своей** мерой (`оценка наша`, 4 знака на единицу), не
  токенами платформы. Сменится оценщик у платформы — пределы поедут молча.

## 5. Пакеты памяти — по одному

Каждая карточка — по одной схеме: назначение → швы и службы → настройки → отказы → границы →
проверка. Установка — в README пакета; здесь только устройство и контракт.

### 5.1. `dsh-pamyat-core` — хранилище, журнал, политика, фильтр входа

**Назначение.** Оперативная память агента: локальное хранилище на `node:sqlite`, журнал решений
о записи (включая отказы и их природу), политика «какие классы записей требуют подтверждения» и
фильтр входа, не пускающий секреты в память. Ноль внешних зависимостей рантайма; Node ≥ 22.

**Швы и службы.** Слушает только `dispose` (закрыть базу). Даёт `pamyat` (§4.1). Берёт
`ctx.get('pamyatDolgovremennaya')`, если смонтирован `dsh-pamyat-omega`. Ничего не вставляет в
контекст, не ходит в сеть, не объявляет инструментов модели.

#### 5.1.1. Настройки

| Ключ | Тип | Умолчание | Смысл |
|---|---|---|---|
| `putBazy` | string | обязателен | путь к файлу SQLite |
| `agent` | string | обязателен | имя агента (пишется в журнал и в записи) |
| `sprashivat` | string[] | `[]` → фактически `['ogranichenie','navyk']` | классы, требующие подтверждения. **Пустой список не отключает спрашивание** — берётся умолчание политики |
| `klassyZnaniy` | string[] | `['reshenie','urok','vyvod','ogranichenie','oshibka','poryadok','nablyudenie','fakt']` | классы, которые уходят в долговременный слой (если он есть) |
| `chtenieSkolko` | number | `20` | сколько записей отдаёт `prochitat` по умолчанию |
| `zhurnalSkolko` | number | `20` | сколько строк журнала отдаёт `svodka` |
| `otvechayushchegoNet` | boolean | `false` | на узле некому подтверждать: `ask`-классы пишутся с отметкой в записи, а не отклоняются |

Что настройкой **не** является (и почему): имена таблиц и схема базы; буквальные исходы
подтверждения платформы (`rejected`/`cancelled`/`unavailable`); поведение при отказе — «нет
источника → не пишем и кричим». Настраиваемый fail-closed был бы выключаемой защитой.

#### 5.1.2. Что лежит в базе

Один файл SQLite, три таблицы:

- `zapisi` — записи: `klass`, `soderzhim`, `istochnik`, `vera`, `sozdano`, плюс два поля-пометки
  `podozrenie` (JSON `{klass, pozicia}` — фильтр нашёл похожее на секрет, но записал) и `ochistka`
  (JSON — из текста вычищены невидимые знаки). Оба разбираются при чтении в объекты.
- `ochered_dolgovremennogo` — что ещё не доставлено в долговременный слой; читается
  `ocheredDostavki()`, разгребается `dostavitOtlozhennoe()`.
- `zhurnal` — `kogda, agent, klass, ishod, priroda, pochemu, istochnik`. Исходы: `zapisano`,
  `otkloneno`, `ostalos-v-operativnom`, `ne-udalos-proverit`, `ne-otpravleno`,
  `moglo-dojti-bez-id`, `dostavleno`, `snyato-s-ocheredi`.

Журнал фиксирует **решение**, не доставку. «Дошло ли до долговременного слоя» — вопрос к очереди.

#### 5.1.3. Политика записи

`reshit(klass)` → `{reshenie: 'auto' | 'ask', pochemu}`. Классы из `sprashivat` требуют
подтверждения; при `otvechayushchegoNet: true` такая запись пишется с отметкой «подтверждать
некому», иначе без подтверждения — отказ с кодом `PAMYAT_TREBUET_PODTVERZHDENIYA`.
`istolkovat(ishod, kanalEst)` переводит исход подтверждения платформы в решение
`{zapisyvat, priroda, pochemu}`; неизвестный исход — отказ `PAMYAT_NEIZVESTNYJ_ISHOD`, не догадка.

#### 5.1.4. Фильтр входа: классы, режимы, порядок

Фильтр (`src/filtr-vhoda.js`, функция `najti_sekret(tekst)`) гоняется при **каждой** записи и
возвращает `{klass, pozicia}` либо `null`. Значение или фрагмент он **не возвращает никогда** —
чтобы находка не попала в журнал.

**Два режима, и режим выбирается однозначностью признака.** Признак, который не бывает ничем,
кроме секрета, — **запирает** (запись отклоняется, в журнал идёт `otkloneno` с природой
`sekret-na-vhode`, наружу — отказ `PAMYAT_SEKRET_NA_VHODE`). Признак, который может быть и
секретом, и чем-то ещё, — **помечает** (запись проходит с полем `podozrenie`, в журнал —
`zapisano` с природой `podozrenie-na-sekret`). В обоих случаях печатаются только класс и позиция.

| Класс | Признак | Режим |
|---|---|---|
| `strukturnyj:PEM` | заголовок `-----BEGIN … PRIVATE KEY-----` | запирает |
| `strukturnyj:JWT` | три base64url-части через точки, начиная с `eyJ` | запирает |
| `strukturnyj:sk-`, `:github`, `:aws`, `:slack` | префиксы вендорских ключей (`sk-`, `gh?_`, `AKIA`, `xox?-`) | запирает |
| `strukturnyj:dsn` | `postgres://user:pass@`, `mysql://`, `mongodb://` с паролем | запирает |
| `uuid-obyavlennyj` | UUID, перед которым в окне 40 знаков стоит слово-объявление | запирает |
| `obyavlennyj` | слово-объявление (`password`, `token`, `secret`, `api_key`, `key`, `пароль`, `ключ`, …) вплотную перед `:`/`=` и значением ≥ 6 знаков | запирает |
| `hex-bez-obyavleniya` | шестнадцатеричная строка длиной 24…128, **кроме** 32/40/64 (это хеши) | запирает — **известное отступление**, см. ниже |
| `entropiya` | ≥ 20 знаков, ≥ 3 классов алфавита, энтропия ≥ 3,5 бит/знак | помечает |

Порядок проверки: структурные → uuid после объявления → по каждому кандидату
`[A-Za-z0-9_]{6,}`: пропуск путей → объявление → hex → энтропия. Порядок важен: раз hex стоит
раньше энтропии, шестнадцатеричная находка не может «уйти в энтропию» и потеряться в пометках.

**Отступление от основания, известное на дату документа.** Класс `hex-bez-obyavleniya`
запирает, хотя его собственный комментарий в коде говорит «хеш и ключ неотличимы по виду», —
то есть признак неоднозначен и по основанию должен помечать. Перевод в помечающие включён в
состав следующего выпуска. На живом корпусе (3661 запись) класс дал 0 срабатываний, и
достижимость класса при этом проверена подставными пробами: ноль означает «предмета нет», а не
«правило не работает».

Пороги, которые не настройка, а константы кода: `DLINA_ENTROPIJNOJ = 20` (помечено «не
поднимать»: живой ключ ровно 20 знаков), `ENTROPIYA_PORog = 3.5`, `DLINA_OBYAVLENNOGO = 6`,
`OKNO_OBYAVLENIYA = 40`. Канарейка: при каждой записи фильтр прогоняет заведомый секрет и
заведомо-невидимые знаки; если сам себя не ловит — отказ `PAMYAT_FILTR_NEISPRAVEN`, запись не
идёт.

#### 5.1.5. Граница слова в перечне объявлений — просмотр назад, не `\b`

Перечень объявлений — один регулярный шаблон с флагами `iu`, в конце `\s*[:=]\s*["']?$`
(объявление должно стоять **вплотную** к значению). Слева от слова нужна граница, иначе `monkey=`
и `hotkey=` читаются как `key=`, а `отключ=` — как `ключ=`.

**Почему не `\b`.** В JavaScript `\b` определён через `\w = [A-Za-z0-9_]`. Перед кириллическим
словом «границы» нет никогда — `\b` молча выключает четыре русских слова перечня (`пароль`,
`ключ`, `токен`, `секрет`), и стенд с латинскими пробами этого не покажет. Поэтому граница —
отрицательный просмотр назад по классам Unicode:

```js
// alpha.24 (реестр):            (?<![\p{L}\p{N}])   — буква или цифра любого алфавита
// alpha.22–alpha.23 (в дереве): (?<![\p{L}\p{N}_])  — то же плюс подчёркивание — ДЕФЕКТ
```

Пример, почему подчёркивание в классе исключения — дефект: имя `OPENAI_API_KEY=` содержит
`API_KEY`, но перед `API` стоит `_`; если `_` запрещён, совпадения нет, и все имена вида
`ИМЯ_API_KEY=`, `ИМЯ_TOKEN=`, `ИМЯ_SECRET=` проходят в память без следа. Пример, почему граница
всё же нужна: в живых конфигах туннелей `PublicKey =` (публичный, ловить нельзя) и
`PresharedKey =` (общий ключ, ловить обязательно) отличаются только словом внутри; без границы
голое `key` запирает оба.

**Второе следствие границы — склейка с приставкой.** Граница перед всем перечнем режет и живые
имена, где слово приклеено без разделителя: `cftoken=`, `authtoken=`, `dbpassword=` — со слабым
значением уходят в память **молча** (`null`), с сильным — в пометку. Разделитель спасает
(`CF_TOKEN=` ловится), склейка убивает. Отсюда состав следующего выпуска: граница
**избирательно** — только перед `key`/`api-key`/`apikey`/`pin`/`psk` и четырьмя русскими словами
(у них есть живые омонимы); перед `token`/`secret`/`password`/`passwd`/`pwd`/`credential` границы
нет (омонимов в живых именах не нашлось, а приставки есть) — плюс `preshared[-_ ]?key` в
перечень. Это основание должно стоять **в коде рядом с перечнем**: несимметричный список без
объяснения следующий читатель выправит «для единообразия».

**Правило для тех, кто пишет о фильтре.** Объяснение дефекта неотличимо от дефекта: запись в
памяти или письмо, где стоит образец «слово-объявление = правдоподобное значение», фильтр
отвергнет. В образцах — только явная заглушка вида `<значение>`.

### 5.2. `dsh-pamyat-secretary` — сводка до того, как её затрут

**Назначение.** Ловит `compaction/summary` и кладёт сводку в память с verbatim-ссылкой на
затенённый диапазон — `<сессия>#<первый seq>-<последний seq>` — чтобы знание можно было
проверить по журналу сессии. Дополнительно (выключено по умолчанию) дистиллирует с того же среза
**знания** отдельной дешёвой моделью и пишет каждое своим классом.

**Швы и службы.** `session/event` с фильтром `event.type === 'compaction/summary'`; читает из
события `summary`, `shadowedSeqs`, `shadowedTokenCount`, `provider`, `model`, `compactionId`.
`inject = ['pamyat']` — без ядра не поднимается. Ничего не предоставляет. При дистилляции читает
файл журнала сессии (`putZhurnala`) и ходит по сети к API модели (`POST …/v1/messages`).

### 5.3. `dsh-pamyat-restore` — сводка обратно и брифинг на старте

**Назначение.** Читающая сторона. Слой B: на первом шаге после `compaction/end` поднять запись
класса `klassSvodki` обратно в контекст. Слой C: на первом шаге после старта процесса — брифинг
из памяти под бюджет `byudzhetPamyati`, не чаще `welcomeInterval` на сессию (отметка на диске).

**Швы и службы.** `session/event` (`compaction/end`) и `agent/pre-step` (водопад, `prepend:
true`). `inject = ['agents']`; память — `ctx.get('pamyat')`, бюджет — `ctx.get('byudzhetPamyati')`
(оба необязательны на подъёме; отсутствие — крик на каждом шаге, где должна была быть вставка).
Защита от повторного монтажа: `globalThis.__pamyatRestore`.

#### Решение по записи

`decide(record, config, now)` → `{decision: 'use' | 'verify' | 'ignore', reason}`. Вера и время
читаются **явной веткой до всякого сравнения**: отсутствующее число никогда не становится нулём.
Порядок: время записи неизвестно → `verify`; старше `ignoreAfterMs` → `ignore`; вера не
измерялась → `verify` (не «ниже порога» — `null < 0.7` дало бы `true`, и число соврало бы); вера
ниже `useVeraThreshold` → `verify`; иначе `use`. Основание печатается всегда и не отключается.

#### Настройки

| Ключ | Тип | Умолчание | Смысл |
|---|---|---|---|
| `restoreEnabled` | boolean | `true` | слой B |
| `welcomeEnabled` | boolean | `true` | слой C |
| `welcomeBudget` | number | `800` | бюджет брифинга в знаках |
| `welcomeInterval` | number, мс | `86400000` | не чаще раза в сутки на сессию |
| `welcomeOtmetki` | string | `~/.dsh-pamyat-welcome-otmetki.json` | где помнить, когда брифинг давался |
| `ignoreAfterMs` | number, мс | `604800000` (7 суток) | старше — `ignore` |
| `useVeraThreshold` | number | `0.7` | ниже — `verify` |
| `klassSvodki` | string | `'svodka-kompakcii'` | класс, под которым ищется сводка (= `klass` секретаря) |

README пакета на дату документа называет пять ключей из восьми (нет `welcomeInterval`,
`welcomeOtmetki`, `klassSvodki`) — расхождение известно.

#### Отказы

Единственный путь — `stderr`, формат `[dsh-pamyat-restore <версия>] …`. Строка подъёма:
`подъём: restore=… welcome=… бюджет=… ignoreAfterMs=… useVera=…`. Своих исключений и `e.code`
нет — все беды переводятся в крик и `return`. Ключевые: `🔴 служба памяти недоступна … — инъекция
пропущена`; `компакт был, но записи класса «…» в памяти нет — вставлять нечего`; `🔴 бюджет
отказал (…) — брифинг строится БЕЗ предела`; `отметка о брифинге НЕ сохранена … — следующий
подъём даст брифинг снова`.

Из CHANGELOG: до alpha.14 крючок welcome (`turn === 1 && step === 1`) на живой сессии,
переживающей перезапуски, срабатывал один раз в жизни — брифинг не давался **ни разу**; лечение —
предел по времени и дисковая отметка. alpha.16: опознаватели поднятых записей перенесены в
`source.sections` (`dsh-pamyat-restore#zapis-<id>`), потому что `data.id` — id сообщения, не записи,
а лишнее поле в `source` может быть срезано молча.

**Границы.** Не делает и не отменяет компакт; не гарантирует, что модель учтёт вставку; в слое B
бюджет не зовётся намеренно (сводка поднимается целиком). **Проверка:** `npm test` — три стенда
(`stend-restore`, `stend-readme`, `stend-krik-zvuchit`); первому нужны переменные окружения
`DSH_PERSIST` и `DSH_SESSION` с путями к модулям платформы, без них — слепота, код `2`.

### 5.4. `dsh-pamyat-byudzhet` — входящий бюджет

**Назначение.** Отбирает записи под предел и говорит, чего вызывающий лишился. Считает
**своей** мерой — «оценка наша», 4 знака на единицу (`Math.max(1, ceil(len/4))` по
`soderzhim + klass + istochnik`), — не токенами платформы. Расход контекста — не его дело.

**Швы и службы.** Ничего не слушает, работает по вызову. Даёт `byudzhetPamyati` (§4.1). Зовёт
`restore` в слое C.

#### Настройки

| Ключ | Тип | Умолчание | Смысл |
|---|---|---|---|
| `predel` | number | `2000` | предел подъёма в единицах своей меры; `0` — не поднимать ничего (законно, но крик) |
| `poryadok` | string | `'svezhest'` | важность: `svezhest` или `vera`; неизвестное значение — отказ с перечнем, не тихий откат |
| `porogVery` | number | `0.5` | ниже — вера считается низкой; **только для объяснения** отброса, не для отбора |

Не настройка: сама мера (константа `SIMVOLOV_NA_EDINICU = 4`); набор порядков; «тепло» записи.

#### Тепло — прибор, не правило

Пакет считает «тепло» записи (полураспад 14 суток, порог холодной 0,25) и печатает распределение
при каждом отборе, но **на отбор оно не влияет**. Это заявлено гипотезой: два замера показали,
что порядок по теплу тождествен свежести, а порог не отсекает ничего. Цифры печатаются, чтобы
гипотеза когда-нибудь была проверена на живом корпусе, а не чтобы по ним решать.

#### Что возвращает `otobrat`

`{podnyato, otbrosheno, svodka}`, где `svodka` содержит `prosili`, `podnyato`, `otbrosheno`,
`cena`, `predel`, `poryadok`, `edinicy: 'оценка наша'`, `prichiny[]` (почему отброшено: «не
влезают целиком» — цена одной записи больше предела; «не поместились в остаток по порядку»),
`svoystva[]` (с низкой верой; с неизмеренной верой — **это не ноль**; холодных; с неизмеренным
теплом — **это не холод**) и `teplo{…}`. Причина отделена от свойства намеренно: «отброшено по
вере» и «среди отброшенных есть с низкой верой» — разные утверждения.

#### Отказы

Формат `[dsh-pamyat-byudzhet <версия>] …`. Подъём: `подъём: предел <N> ед., порядок «<P>», порог
веры <V>. Тепло считается и печатается, но на отбор НЕ ВЛИЯЕТ (прибор, не правило).` При
отбросе: `поднято НЕ ВСЁ: просили <A>, подняли <B>, отброшено <C> — ПРИЧИНЫ: … Цена подъёма
<cena> из <predel> — единицы «оценка наша», НЕ токены платформы.` Своих `e.code` нет — голые
`Error` с текстом. Замер на живой базе (2026-09-04): 7 из 23 отброшенных — сводки компакции
ценой 4008…4841 при пределе 2000, то есть сводка целиком в брифинг не влезает по построению.

**Границы.** `sverit({nashe, platformennoe})` возвращает расхождение и **не правит** меру.
Сменится оценщик у платформы — пределы поедут молча. **Проверка:** `npm test` — четыре стенда
(`stend-mery`, `stend-otbora`, `stend-readme`, `stend-krik-zvuchit`), 39 проб.

### 5.5. `dsh-pamyat-nudzh` — расходный учёт и подталкивание

**Назначение.** Считает **занятость окна** (вход последнего вызова) и сумму расхода по сессии; при
переходе порога — одна вставка-напоминание в контекст. Что поднимать обратно — не его дело.

**Швы и службы.** `session/event` (`assistant/message`, `compaction/summary` — из обоих берётся
`event.data.usage`); `agent/pre-step` (водопад). Даёт `nudzhPamyati`. Вставка — `createUserMessage`
с `source: {kind: 'plugin', plugin, form: 'snapshot', sections}`.

#### Арифметика — почему занятость, а не сумма

`вход = inputTokens + cacheReadTokens + cacheWriteTokens`; `reasoningTokens` — не слагаемое
(справочно `izNihRassuzhdenie`). Порог сравнивается с **входом последнего вызова**, а не с суммой
по сессии: сумма растёт без предела, и компакция её не уменьшает — на боевом случае это дало
«НЕ МЕНЬШЕ 1 255 120 из 1 000 000» при двух вызовах (CHANGELOG alpha.7). `usage` без числа
(`undefined`/`null`) считается отдельно (`bezChisla`), не как ноль.

Оговорка из кода: сразу после компакции занятость показывает **старое высокое** число — вход
`compaction/summary` снят до сжатия. Лечить нечем, знать надо.

#### Настройки

| Ключ | Тип | Умолчание | Смысл |
|---|---|---|---|
| `predel` | number | `0` | предел контекста в токенах провайдера; `0` — предел неизвестен: расход считается, тревоги и вставки **нет** |
| `dolyaTrevogi` | number | `0.8` | доля предела, после которой пора подталкивать |

Не настройка: состав суммы; несимметричность ответа (`hvatitLi()` никогда не скажет «хватает»);
однократность подталкивания.

#### Отказы

Формат `[dsh-pamyat-nudzh <версия>] …`. Подъём: `подъём: предел <N> ток., доля тревоги <D>
(порог <…> ток.). Числитель — занятость ПОСЛЕДНЕГО вызова, не сумма за сессию.` При
`predel: 0` — отдельная строка «предел контекста НЕ ЗАДАН … Это настройка, а не поломка». Тревога
называет единицу рядом с числом; снятие тревоги — «занятость вернулась под порог … похоже,
компакт прошёл». Своих `e.code` нет.

**Границы.** Молчание нуджа не означает запаса. Счёт один на плагин — сессии не различаются:
напоминание уйдёт в ту сессию, чей шаг случится первым (верно по числу, неверно по адресу).
**Проверка:** `npm test` — четыре стенда; пятый, `stend-vstavki.mjs` (6 проб про вставку), на
диске есть, но в `scripts.test` не включён — известное расхождение. `@deepseek-ai/dsh-llm` в
`peerDependencies`, но не в `devDependencies`: без ручной установки стенды дадут код 2.

### 5.6. `dsh-pamyat-omega` — долговременный слой поверх MCP (необязательный)

**Назначение.** Пишет знание во внешнее хранилище, доступное по MCP, и **подтверждает доставку
перечитыванием** записи по опознавателю, а не отчётом об отправке. Не поставил — нет ни кода, ни
настроек, ни обещаний: ядро работает без него.

**Швы и службы.** Ничего не слушает. Даёт `pamyatDolgovremennaya` (§4.1); берёт её `core`.
Сеть: `POST config.adres`, JSON-RPC 2.0 `tools/call`, ответ — поток событий (`data: {…}`),
таймаут `AbortSignal.timeout(tajmautMs)`. Два инструмента хранилища: запись и чтение похожих по
опознавателю; имена инструментов — чужой протокол, не настройка.

#### Пять состояний доставки

`sohranit()` возвращает `sostoyanie ∈ dostavleno | ne-najdeno | ne-otpravleno |
moglo-dojti-bez-id | moglo-dojti-id-est`. Правило: **«не знаю» ≠ «не доставлено»** — если ответ
пришёл, но опознаватель не разобран, состояние «могло дойти», и запись остаётся в очереди ядра до
разбора, а не теряется и не дублируется вслепую. `proverit({id, obrazec})` сверяет первые 40
знаков нормализованного содержимого; **без `obrazec` она никогда не ответит `est`** — названный
отказ, не дефект.

#### Настройки

| Ключ | Тип | Умолчание | Смысл |
|---|---|---|---|
| `adres` | string | обязателен | адрес точки хранилища; **завершающий слэш обязателен** (иначе `OMEGA_ADRES_BEZ_SLESHA`) |
| `tajmautMs` | number | `10000` | предел ожидания ответа, мс |

Не настройка: имена инструментов хранилища; признак «записи нет» в ответе; правило «не знаю ≠ не
доставлено»; сверка содержимого при подтверждении (при `false` подтверждение отвечало
«доставлено» на чужую запись).

#### Отказы

Формат `[dsh-pamyat-omega <версия>] …`. Подъём: `подъём: адрес <adres|НЕ ЗАДАН>, предел ожидания
<N> мс` (+ ` — связь НЕ создана, см. строку выше`). Коды: `OMEGA_NET_ADRESA`,
`OMEGA_ADRES_BEZ_SLESHA` (оба переводят службу в `dostupna() === false`, `sohranit` отвечает
`ne-otpravleno`), `OMEGA_PUSTOE_ZNANIE` (единственный `throw` наружу).

**Границы.** Подтверждение идёт тем же интерфейсом, что и запись: оно ловит потерю при передаче
и отказ службы, но не случай, когда интерфейс отвечает бодро при пустом хранилище. Внешний контракт
разметки ответа — если он сменится, шаблон разбора надо перемерить живым ответом; **стенд об этом
молчит по построению**. **Проверка:** `npm test` — пять стендов, 40 проб; сети не нужно, транспорт
подменяется параметром.

### 5.7. `dsh-pamyat` — имя набора

**Назначение.** Кода нет. Объявляет, какие **шесть** пакетов собраны и проверены вместе, в каких
точно версиях и чем это проверено. Устанавливается одним именем и тянет шесть точных версий.

**Версии точные, диапазонов нет.** Дословно из README: «Имя, за которым у разных людей
оказываются разные наборы, хуже отсутствия имени: расходятся такие наборы молча». В
`dependencies` — голые версии без `^`, `~`, `>=`, `*`; отдельная проба стенда краснеет при любом
диапазоне.

**Как проверяется состав.** Инструмент `summa-predmeta` (bash, едет внутри метапакета) считает
сумму предмета: `состав = npm pack --dry-run --json → files[].path`; порядок `LC_ALL=C sort`; строка
на файл `"<путь> <sha256>\n"`; итог — sha256 всех строк, первые 16 знаков. Режим `--kontrol` —
контроль зрячести: сумма обязана меняться от правки байта и от переименования файла. `sostav.json`
хранит по каждому члену `paket`, `versiya`, `predmet` (сумма), `faylov`, `prob`, плюс сумму самого
инструмента (`summa_instrumenta`) и способ (`kak_schitano`). Стенд `test/stend-sostava.mjs`
сверяет: сумму инструмента; версии `dependencies` = `sostav.json`; отсутствие диапазонов; **суммы
предметов против того, что лежит в реестре** под заявленной версией (`npm pack` → распаковка →
`summa-predmeta`); версии соседей на диске; README.md и README.en.md против состава поимённо и
поверсионно в обе стороны.

**Что «сошлось» означает и чего не означает.** «Учёт сходится» — объявленное совпало с
действительным. **Годность** каждого члена стенд не проверяет и проверить не может: набор,
объявляющий негодное ядро, сойдётся так же, как набор с годным. Инструмент менять только под
**новым именем файла**, никогда на месте: сумма инструмента входит в проверку.

**Проверка.** `npm test` = `node test/stend-sostava.mjs`; коды `0` / `1` расхождение по существу /
`2` слепота (дерево семейства не найдено — «отказ ПРОВЕРКИ, а не пакета»). Реестровой пробе нужна
сеть; без неё — слепота с названной причиной, не «сошлось». Прогон обязан проходить в трёх
раскладках: мастерская (репозиторий), плоский ящик поставки, установленное у получателя.

## 6. Межагентская почта (A2A)

Две части с разной ответственностью: `a2a-bus` переносит письмо между ящиками системных
пользователей и **не читает** его; `telegram-multiagent` забирает письмо из ящика и подаёт его в
ход агента. Ни одна из них не доставляет письмо «в модель» сама по себе — только связка.

### 6.1. `a2a-bus` — ящики, почтальон, таймер

**Что это.** Не npm-пакет и не плагин: спул-каталог на агента, почтальон от `root` и таймер
systemd. Девять файлов: `sbin/a2a-pochtalon.py`, `sbin/a2a-zavesti`, `sbin/a2a-proba-novichka`,
`bin/a2a-send`, `bin/tell-owner`, `bin/agent-registry`,
`systemd/a2a-pochtalon.service`, `systemd/a2a-pochtalon.timer`, README. Ставится руками
(`install -m 0755 …`). Строго одна машина: транспорта между хостами у шины нет.

**Ящик.** Один на агента: `/var/spool/a2a/<системный-пользователь>`, режим `1730`, владелец
`<пользователь>:<группа шины>`. Смысл режима: отправитель (член группы) имеет `w`+`x` — положить и
пройти, но не `r` — перечислить чужой ящик нельзя. Умолчание группы в коде — `a2a-pochta`; README
называет `a2a-post` — расхождение известно, верить коду.

**Письмо.** Сырой текст без заголовков. Имя файла: `ГГГГММДДTЧЧММССZ-<отправитель>-<хвост>.txt`;
порядок разбора — лексикографический, при такой метке времени = хронологический. Файлы с точки
пропускаются (временные самого почтальона). Заголовка `From:` в ящике нет намеренно.

**Почтальон.** Не `chown`, а **перепись в новый inode**: смена владельца оставила бы отправителю
открытый дескриптор и возможность подменить содержимое после проверки. Последовательность:
`open(O_RDONLY|O_NOFOLLOW)` → `fstat` (только обычные файлы) → чтение кусками по 65 536 байт →
временный файл `.<имя>.perenos-<pid>` с `O_EXCL|O_NOFOLLOW` и `0600` → `fchown`/`fchmod`/`fsync`
**по дескриптору** → `os.replace` атомарно → **отдельная проверка после замены** (uid и размер).
Группа письма ставится в личную группу получателя, не в группу шины. Уведомление владельцу —
строка `← от <имя>: <текст>`, где имя берётся **по владельцу файла**, а не из текста, и
переводится в кличку через реестр; текст идёт через `stdin`, не аргументом (иначе виден в
`/proc/<pid>/cmdline` и журнале sudo).

**Настройки** (переменные окружения):

| Ключ | Умолчание | Смысл |
|---|---|---|
| `A2A_KOREN` | `/var/spool/a2a` | корень ящиков |
| `A2A_GRUPPA` | `a2a-pochta` | группа шины (членство нужно отправителю) |
| `A2A_TELL_BIN` | `/usr/local/bin/tell-owner` | чем сказать владельцу в чат |
| `A2A_REESTR_BIN` | `/usr/local/bin/agent-registry` | реестр «пользователь ↔ кличка» |
| `A2A_PREDEL_V_CHAT` | `900` | сколько знаков письма показать в чате; сверх — обрезка с явной подписью |
| `A2A_PREDEL_UVEDOMLENIYA_S` | `15` | таймаут уведомления, с |
| `A2A_PREDEL_BAJT` | `1048576` | предел размера письма; крупнее — не переносим, не удаляем, кричим |
| `A2A_PREDEL_PISEM` | `100` | писем за один прогон |

Таймер: `OnUnitInactiveSec=5s`, `OnBootSec=30s` — один юнит на машину. Служба: `Type=oneshot`,
`User=root`, `ProtectSystem=strict`, `ProtectHome=true`, `PrivateTmp=true`, `NoNewPrivileges=true`,
`ReadWritePaths=/var/spool/a2a`.

**Коды выхода почтальона.** `0` — отказов нет; `1` — были отказы, письма **оставлены на месте**;
`2` — слепота: не root, корень не читается, ни одного ящика. Отказ переноса печатается как
`🔴 <ящик>/<имя>: <причина> — письмо ОСТАВЛЕНО, не потеряно`; отказ уведомления — `письмо
ДОСТАВЛЕНО, но копия владельцу НЕ ушла`. `a2a-zavesti` (заведение ящика, идемпотентно): `0`/`1`
отказы/`2` аргументы/`3` нет в реестре или в системе/`4` не root. `a2a-proba-novichka` (приёмка):
10 проверок + канарейка числа проверок; при наличии соседа ожидается 11, иначе 7 — несовпадение →
`2`. Приёмка не пишет человеку ни разу: подставляет заглушку вместо `A2A_TELL_BIN`.

**Чего шина не делает.** Не доставляет письмо в ход агента; не читает содержимое; не фильтрует;
не защищает от члена группы, кладущего письмо (это замысел); работает только с обычными файлами;
не идёт по симлинкам и не выходит за корень; не удаляет и не ротирует; не даёт метки «тихо» —
уведомление получателю уходит всегда; не является границей против враждебного локального root.

**Безопасность.** Имя отправителя в имени файла — подсказка, не удостоверение: подделка
тривиальна, настоящее происхождение — владелец файла до переноса; **права по этому имени раздавать
нельзя**. Двоичное письмо в чат не показывается (`(двоичное вложение, N Б)`). Шина защищает от
чужого любопытства, не от собственной небрежности: файл, который владелец сам сделает читаемым
всем, прочтёт вся группа.

**Сторона отправителя — `bin/a2a-send`, `bin/tell-owner`, `bin/agent-registry`** (опубликованы
2026-09-04 как работают в бою; до этого README ссылался на них как на внешние). `a2a-send
<получатель> ["текст"]` кладёт письмо в ящик под именем с точки и переименовывает атомарно
(почтальон точки пропускает — полуписьмо не подхватит), ставит `umask 077` только вокруг записи,
и показывает владельцу строку «→ кому» через `tell-owner`. **Приватный текст — через stdin, не
аргументом:** аргумент виден всем пользователям машины в `/proc/<pid>/cmdline`; текст длиннее
`A2A_PREDEL_ARGV` (500) аргументом отвергается; ключа `-f` нет намеренно. **Если у вас инструкция с `-f` или пределом
3500 знаков — это другой курьер под тем же именем** (собственный инструмент фермы на другой
машине): одно имя, один путь, разные машины, разные интерфейсы. Имя и путь предмет не опознают —
опознаёт содержимое (размер, сумма, наличие ключа). Коды: `0` доставлено и
владелец увидел · `1` не доставлено · `3` ошибка вызова/получателя · `4` доставлено, видимость не
ушла; `--bez-kopii` — без копии владельцу. `tell-owner` пишет владельцу от **своего** бота: бот
выбирается по вызвавшему пользователю (`/etc/agent-tell/<user>.conf`: `TOKEN_FILE`, `CHAT_ID`),
чужим именем написать нельзя даже случайно; нет настройки — код `1` и громкая строка.
`agent-registry` — читатель реестра агентов машины, ничего не меняет и не угадывает (нет поля —
громкий отказ, не умолчание); подкоманды `list`, `sluzhby`, `pole`, `mashina` (только пути, никогда
значения секретов), `obshchee`, `pokrytie`, `fakt`, `verify` (расхождение → `1`, слепота → `2`).

### 6.2. Читающая сторона в `telegram-multiagent`

Два независимых источника входящих с разными правилами:

| | канал `a2aDir` | ящик шины `spoolDir` |
|---|---|---|
| где | `<a2aDir>/in/*.txt`, ответ в `<a2aDir>/out/*.txt` | плоский каталог, обычно `/var/spool/a2a/<агент>` |
| отправитель | первая строка `From: <инстанс>/<папка>` | из **имени файла** `…-<отправитель>-…` |
| `/goal` из письма | принимается по списку `goalA2ASenders` | **не принимается вовсе** |
| префикс в диалоге | `[служебный канал, от координатора <sender>]` | `[служебный канал, от агента <who>]` (+ пометка возраста); пачка — `[служебный канал, N писем из ящика одной пачкой]` |

Заголовок `From:` в письме из ящика **не сработает**: отправитель возьмётся из имени файла, без
ошибки и без отказа. Берутся только `.txt` и `.md`; прочее не глотается — имя названо в журнале
ровно один раз.

**Доставка в ход.** `agentFor(a2aSession)` → постановка вопроса → `agent.send(createUserMessage({…,
source: {kind: 'a2a'}}), 'next-turn', true)` → побудка до подтверждения (бюджет 120 с шагом
0,5 с) → **только потом** `unlink`. Пометка канала ставится кодом доставки, не отправителем, и
перед постановкой из текста вырезается всё похожее на неё (`stripMark`).

`source.kind: 'a2a'`, а не `'user'` — сознательный размен, последствия перечислены в коде:
`hasDirectHumanInput → false`; бюджет пробуждений не обнуляется; тело скилла не подтягивается;
заголовок сессии не строится. Личный чат владельца остаётся `source.kind: 'user'`.

**Опрос.** Не событие и не таймер: `loop()` подряд зовёт `pollA2A()`, `pollSpool()`, затем долгий
опрос Telegram на 25 с — он и задаёт период (~25 с). Пачка: больше `spoolBatchCount` писем — одним
ходом; старше `spoolStaleHours` — приписка «письмо пролежало в ящике N ч — возможно, устарело».

**Настройки, относящиеся к A2A.**

| Ключ | Умолчание | Смысл |
|---|---|---|
| `a2aDir` | `null` | каталог обмена; `in/` и `out/` создаются сами; не задан — канала нет |
| `a2aSession` | `'a2a'` | идентификатор служебной сессии |
| `spoolDir` | `null` | ящик шины; не задан — не читается |
| `spoolBatchCount` | `5` | больше — подать пачкой одним ходом |
| `spoolStaleHours` | `12` | старше — пометка возраста |
| `mergeChatIntoA2A` | `null` | слить личный чат владельца и служебный канал в одну память |
| `goalA2ASenders` | `[]` (отказ всем) | кто вправе `/goal` из канала `a2aDir` |
| `settingsFile` | `<tokenFile>.json` | режим доставки копий владельцу: `personal` (умолчание) / `broadcast` / `owner-all`; перечитывается по `mtime` |

Куда уходит ответ агента, решает **происхождение хода**, а не последнее сообщение:
`turnAsk.origin ?? lastOrigin ?? (chatId === a2aSession ? 'a2a' : 'tg')`. Предел постановок
цели — 3 за скользящий час на канал.

### 6.3. Команды контекста: `/compact` и `/compact-status`

| Команда | Алиас | Что |
|---|---|---|
| `/compact` | `/ccc` | штатная компакция платформы (`dsh-command-compact`) |
| `/compact-status` | `/cs` | своя: сколько токенов занято и далеко ли до порога |

Алиасы разворачиваются **в имя штатной команды**, а не в свою реализацию — ради события
`command/run`. Концевой якорь `(\s|$)` в шаблоне обязателен: без него `/compactstatus` сматчится
как `/compact` и молча сожмёт историю.

`/compact-status` печатает: `Контекст: занято <N> токенов.` (источник — `tokenMeter.measure`, то
же число, которым платформа решает, пора ли сжимать); опору замера в **трёх** состояниях (с 1.5.0):
опора свежая — `(числа провайдера)`, расстояние до порога печатается; опора устарела — `🔴 ЧИСЛА СНЯТЫ
ДО КОМПАКТА`, расстояние **не** печатается вовсе (вырезанное вычтено по эвристике «4 знака = 1 токен», на
кириллице она занижает в разы — расстояние не «примерно», а неизвестно); свежесть снять не удалось —
`⚠️ свежесть снять НЕ МОГУ (причина)`. Свежесть определяется по событиям журнала сессии
(`session.events` либо `eventAt()` + `seq` — по факту установленной платформы; иная сигнатура → «не знаю»),
а не по `baseline.kind`: тот говорит об **источнике** опоры, не о её актуальности. Окно — из
`llm.resolveModelInfo(provider, model).context.contextWindow`; если окна нет, умолчание **не
подставляется** — печатается `🔴 Окно контекста недоступно (<причина>) — расстояние до порога
сказать НЕ МОГУ`. Множитель `0.8` — умолчание платформы; если compaction смонтирован со своим
`thresholdRatio`, число в ответе неверно, и стенд этого не поймает — оговорка записана в README.

## 7. Установка: явные номера, не метки

Состояние меток `latest`/`alpha` в реестре **не считается устойчивым**: на дату документа за один
день ядро выпускалось девять раз, и метка дважды указывала на версию с известным дефектом
фильтра (§5.1.6). Поэтому:

1. Ставить **по явному номеру**, не по метке. Набор — одной строкой с номером:
   `npm i dsh-pamyat@0.1.0-alpha.29` (ядро alpha.25 — принято приёмкой; в реестре `latest` — alpha.28, см. §5.1.6. Остаток по именам уточнён замером 04.09: дословная
   форма `ИМЯ_SECRET=` запирается; проходят формы, где слово-объявление стоит НЕ вплотную к разделителю (`ИМЯ_SECRET_2=`, `SECRET_KEY_ID=`,
   `PIN_CODE=`) — перечнем имён это не чинится (на двух корпусах 27 из 28 и ~176 таких имён — не секреты: `secretary`, `maxTokens`, `ping`),
   лечение — по значению справа, вместе с дырой значений со знаками, alpha.29). Старшие наборы, если нужны для сравнения:
   alpha.26 (ядро alpha.21: ложные отказы на омонимах `key`), alpha.28 (ядро alpha.24: пропуски
   `PresharedKey=` и склеенных имён). Что годно **вам** — по §5.1.6 и по вашим живым формам имён.
2. Состояние меток проверять самим, командой, а не по документу:
   `npm view dsh-pamyat-core dist-tags --json` и `npm view dsh-pamyat dist-tags --json`.
   **Метка не есть годность.** Метку переводит приёмка, а не выпуск (§8), но между выпуском и
   приёмкой она может стоять где угодно.
3. Проверить, что реестр отдаёт **тот** состав: `npm pack dsh-pamyat-core@<версия>` из чистого
   каталога, распаковать, сверить `summa-predmeta` с `sostav.json` набора. Сумма — имя состава;
   номер версии — только адрес.
4. После установки — `npm test` в каждом пакете (§9) и строки подъёма в журнале процесса: ноль
   строк подъёма = пакет не смонтирован.

Свежевыпущенная версия отдаётся реестром **не мгновенно**: 404 на тарбол в первые минуты после
публикации — незавершённая раздача, не отказ. Перемерить через 15 минут; 404 после пятнадцати
минут — настоящий.

## 8. Порядок выпуска и приёмки

Правила, которые стоили дня работы, и потому записаны здесь, а не только в переписке.

1. **Выпуск в реестр и перевод метки — разные действия.** Версия без метки никому не вредит:
   выпускать можно свободно, под любыми номерами. Метка `latest`/`alpha` — раздача всем, кто не
   назвал номер, и её переводит **приёмка**, не выпуск.
2. **Номер выпуска — не имя состава.** Два человека, договорившиеся «выпускаем alpha.N», могут
   собрать под ним разные составы. Имя состава — сумма предмета (`summa-predmeta`), записанная в
   `sostav.json`. Перед подъёмом на узел сверять версию **в момент** подъёма, а не по памяти:
   «диск обогнал реестр» случалось четырежды за день.
3. **Приёмка — числами, на чужом наборе.** Набор проб у автора всегда подобран под находку;
   приёмка гоняет свой набор, включая формы, которых у автора не было, и живой корпус с
   разбивкой по классам (§5.1.4). «Ноль промахов» ничего не говорит, пока не назван состав
   набора. Ноль срабатываний класса засчитывается только с проверкой достижимости класса
   подставными пробами.
4. **Тарбол — чужой рукой.** Перед переводом метки убедиться, что `npm pack <пакет>@<версия>`
   берётся из чистого каталога на другой машине.
5. **Основание правил — в код, рядом с правилом.** Несимметричный перечень (граница перед `key`,
   но не перед `token`) без объяснения в комментарии следующий читатель выправит «для
   единообразия». Переписка через месяц недоступна; комментарий — доступен.
6. **Стенд, который не может проверить, выходит с `2`, не с `0`.** Во всём семействе: `0` —
   сошлось, `1` — расхождение, `2` — «проверить нечем». Ноль проверок не должен выглядеть как
   «проверки прошли». Прогонщик стендов обходит каталог, а не список имён рукой: три стенда из
   девяти однажды не запускались при зелёном `npm test`.

## 11. Как поддерживать этот документ

- Два файла — один документ. Правка — **парой**, в одном коммите; в шапке обоих — дата версии.
- Что перепроверять при каждом выпуске пакета семейства: таблицу §1.3 (версии), таблицу §3
  (швы — если пакет стал слушать новое событие), таблицу §4.1 (методы служб), таблицу настроек
  в карточке пакета, §5.1.6 (история фильтра), §9 (число стендов), §10 (расхождения — снять
  закрытые, добавить новые).
- Числа в документ — только подстановкой из вывода прогона, не по памяти. Образцы секретов —
  только с явной заглушкой `<значение>`: иначе документ сам станет предметом фильтра.
- Ничего частного: имён людей, машин, путей вне умолчаний пакетов, имён записей хранилищ
  секретов. Репозиторий публичный.
