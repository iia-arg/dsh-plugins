# Справочный учёт R

Root-таймер вызывает collect-team-usage.py → runtime_receipt_source.prepare → owner Reader. Читатель хранит приватный SQLite на источник рядом с output: runtime-readers/<uid>/<hash-path>.sqlite. Один BEGIN IMMEDIATE сохраняет прочитанные факты и offset; суммы заново получаются из этих фактов и уникальных responseId/messageId G/native, отдельного неатомарного прибавления нет. Повторный тик или повтор R-факта не прибавляет токены второй раз. Ключ запроса — (uid,recipient,requestGeneration,requestId); uid/recipient зафиксированы источником, SDK-generation входит в ключ SQLite и кеша. Ключ turn — (uid,recipient,sessionId,sessionCreated,turn), снимок обновляется. R generation/seq не определяют единицу расхода. Private-пакет использует составные SDK-ID для всех запросов; физический G не переписывается.

R читается только для OPEN-прогонов. Idle не открывает R и не создаёт cursor. Читаются новые полные строки до LF; неполный хвост остаётся с прежним offset. Новый inode или size < offset сбрасывают offset в 0, сохраняя учтённые факты и успешные привязки. Негодные JSON/непригодные записи пропускаются. В квитанции по каждому источнику видны skippedLines и unboundRecords; это накопленные негодные строки и число уникальных запросов без однозначной привязки, не токены и не вычет из других заданий.

Привязка только по удостоверенным delivery→run/job и точной операторской session/turn регистрации. Если один зарегистрированный ход (sessionId, sessionCreated, turn) заявлен несколькими RUN/job и среди меток есть текущий RUN, участник получает MIXED_JOB_TURN до использования cache. Глобальный unboundRecords сам по себе остаётся диагностикой. Разные turn одной DSH-сессии считаются независимо, каждый в своё задание. Другие задания и обычная работа не входят в расход текущего задания. JSON из R не назначает run/job самостоятельно.

При обрезке «удалить и начать новый» теряется хвост между последним тиком и обрезкой (≤ одного тика при исправном таймере). При задержке/сбое коллектора интервал потери больше. В квитанции одна пометка о возможной потере, status из-за обрезки не превращается в incomplete. Уже прочитанные факты остаются. Если удалить сам SQLite-state, после ранее выполненной обрезки восстановить прежние факты нельзя.

Единственный общий policy: /etc/dsh-telegram-multiagent/usage-runtime-policy.json, root:root 0644. Формат Альфы: {"schemaVersion":1,"fileMaxBytes":33554432,"recordMaxBytes":65536}; кандидат SHA256 c752def41ba4676fa6ee704ac0bd97e38331529a05de1bc93eeead038b669643. Reader и writer принимают только обычный root-owned single-link файл без записи группы/прочих, до16КиБ, с ровно тремя неповторяющимися декодированными ключами и безопасными целыми числами (schemaVersion1, 0<recordMaxBytes<=fileMaxBytes). Отсутствие даёт «R не читается: policy отсутствует»; негодный/нечитаемый файл — «R не читается: policy негодна (<причина>)». В обоих случаях R не открывается и запасного лимита нет. Уже сохранённые факты и отдельное чтение G/raw продолжают считаться; новые привязки без R не выдумываются. В квитанции видна пометка. Штатная порция — доfileMaxBytes; исключение только для пропуска повреждённой завершённой строки: reader доходит доLF малыми кусками, skippedLines+1, следующая исправная строка читается в следующей порции. Хвост безLF оставляет offset на начале строки. policySHA256 относится к текущему принятому файлу. Монтаж policy/writer — рука координатора; второго policy пакет не несёт. Проверки writer/сторожа принадлежат Альфе/Заре.

Убраны полный перечит R, producer seq/generation/WM/proof/canonical как повторные условия тика, общий wall30/35с как отказ R. Метаданные/G/native по-прежнему имеют свои проверки и лимиты; арифметика токенов и прежние ошибки G не ослаблены. Учёт не управляет заданиями. Монтаж, приёмка и живые службы этим кандидатом не исполняются.

Новые Root-регистрации сохраняют runtimeOperator вместе с записью прогона, чтобы проверка неоднозначного хода учитывала CLOSED-историю. Для прежних записей без поля используется ещё сохранённая reservation; уже утраченный операторский ключ старой CLOSED-регистрации из времени не восстанавливается.

Список источников R для читателя и сторожа: `/var/lib/autopilot-usage/source-profile.json` → `participants[].runtimeSource.raw` (имя `participants[].name`, UID `participants[].uid`, служба TG `participants[].tgService`, например `master.service`). Стандартный usage-unit использует этот профиль; при явном root CLI `--profile` сторожу передаётся тот же принятый путь. Root-регистрация сохраняет выбранные профили участников в `index.json` → `runs[].record` → `participants[].runtimeSource.raw`. Список не входит в policy. Жёлтого R-порога/warningPercent, reset-record и ноябрьского срока в этом механизме нет; для реализации сторожа Заре задано также правило «писатель молчит»: systemctl is-active для tgService даёт active, а mtime R старше 300 секунд (ровно 300 не старше). Неактивная служба сама по этому правилу не даёт красного. Сторож принадлежит Заре; читатель systemctl не вызывает.

Поле tgService обязательно у каждого участника source-profile, в том числе при idle-валидации. Это непустой unit-token длиной до 255 символов с суффиксом .service; пути, пробелы и CLI-ключи не принимаются. tgService не копируется в immutable billing-record: физические источники, их идентичность и расчёт расходов от состояния службы не зависят. Никакой автоподстановки имени по participant.name нет; реальные службы задаёт назначенная рука при подготовке профиля.

Первый bind читает ledger/native отдельным Meter с16МиБ/3с на owner-проход; конечные пределы действуют и на ошибках. bindingBytes/bindingSeconds/bindingError видны в runtimeCursor; превышение исключает неподтверждённые привязки со счётчиком и видимой пометкой ledger/native. Это время, чтение R и индекс/однократная миграция не вычитаются из metadata-срока G/raw. Противоречивые claims/deliveryIds пропускаются как негодные строки, не добавляют labels и не снимают доказанный расход. Миграция SQLite v1→v2 один раз удаляет старые непригодные снимки и пересобирает labels из сохранённых пригодных фактов, сохраняя offset/валидные факты/кэш.

Известная граница, не исправляемая этим выпуском: при удалении только текущего Root delivery-map сохранённый bind не используется без его удостоверенной postal-метки; на owner/core-копии100→0→100 при удалении/возврате mapping. Это не доказанный исход полного Root retention (он может раньше дать JOBSET_INCOMPLETE).

Подписка Codex справочная и не блокирует токены: годный engine-account-read с доступной root-картой имеет приоритет; иначе используется один сохранённый на момент хода switcher-point (authLinkTargetAtStart либо legacy auth.subscription), не нынешнее HOME. subscriptionSource=engine-account-read/switcher; при отсутствии обоих subscription=unknown/source=unknown, отдельная bySubscription.unknown входит в общий итог. Панель пишет «по переключателю» или «подписка не определена». authEpoch и proof не обязательны для токенов Codex. Несколько источников метки в одной итоговой строке обозначаются mixed/«в т.ч. по переключателю». Негодная/недоступная карта не обнуляет расход; её необязательное чтение имеет отдельные65536Б/3с и subscriptionBytes/subscriptionSeconds в owner/runtimeReads, без расходования времени metadata/G. Процессная регистрация и проверки чисел/привязки задания сохраняются. Учёт субагентов новым кодом этого выпуска не добавляется.

## Исторические G

Старые G до 0.1.12 у Claude сохраняют GATEWAY_USAGE_MISMATCH навсегда: producer записывал промежуточный usage; это не новый дефект. Финальные значения нельзя восстановить из native под видом независимой сверки.

Кандидат 0.1.12 разделён на reader/exporter dsh-autopilot и producer/streaming в dsh-subscription-gateway. Дочерний учёт в эту базу не входит.


## 0.1.13: source gap и покрытие текущего RUN

Private SQLite reader-state получает schema3/source_status. При обновлении старого cursor R-префикс пересматривается один раз в обычном окне policy.fileMaxBytes/recordMaxBytes; пока старый EOF не проверен, owner-export возвращает R_SOURCE_REPLAY_PENDING. Новые/пропущенные строки прежнего префикса не пересчитываются повторно, фактические readBytes остаются видимыми. Cached binding и SQL facts сохраняются. Старый reader при откате не понимает новый gap-status и теряет именно эти новые проверки.

source_gap не исчезает при повторном чтении EOF; исходная именованная причина даёт incomplete участника, не measured0. Корректная новая source generation или физическая замена/обрезание R заново устанавливает состояние; malformed watermark его не снимает. Проверяются envelope и integer at. Каждый G-запрос в окне startedAt RUN ≤ at ≤ cut требует своего точного R SDK-key/session/created/turn: иначе R_REQUEST_UNPROVEN. G с at<startedAt RUN исключён из этой проверки в legacy и segmented ветках; at==startedAt и at==cut включены, время обоих краёв сравнивается без округления микросекунд. Доверенный start приходит из root record через operator.runStartedAt; прямой legacy вызов без operator сохраняет прежнюю строгую проверку до cut. Отсутствие RUN-метки внутри окна не доказывает, что G без R является ordinary. Обычная работа вне RUN с существующим R в оплату не входит и measured не ломает. Это не восстанавливает R-данные, которые stopped writer не записал; Починка самого R-писателя Совы передана Бете решением координатора10:26:02Z, AP отсутствующий R не дорисовывает.

Глобальный unboundRecords остаётся диагностикой. Успешный export требует unresolvedRequests текущего RUN=0 и покрытия каждой acked task-доставки этого RUN/получателя R-запросом помеченного ею хода. Пропуск даёт DELIVERY_UNBOUND. Для master требуется точный operator-claim текущего RUN. Смешанные RUN/job метки проверяются до использования cached binding. ACK берётся из canonical messages; принятая граница и страховка GC описаны ниже.

Cut оператора064af3c4 Беты включён без изменений. Phase=final вынесен из0.1.13 решением координатора на отдельный пункт0.1.14; код phase не менялся.


## Протокол покрытия доставок0.1.13

По решению координатора20.10.2026 11:44:38Z и воротам Вениамина: «покрытие доставок полно, пока RUN закрыт не позже 48 ч после завершения его последнего task».

Это именованная операционная граница для почты0.1.10, не обещание observed или полных чисел. Незавершённый task не получает retention_at при ACK; завершённый становится доступен GC только после completion и возрастных/count порогов. Ранний task длинного RUN всё же может быть pruned до истечения48ч от последнего task; описанная ниже страховка обязана отметить это и внутри окна.

Root читает tombstones из того же проверенного snapshot почты. Если kind=task, recipient входит в зафиксированный состав RUN и created>=startedAt RUN, этот участник получает incomplete/TASK_PRUNED_DURING_RUN и totals=null, доказанные числа остальных сохраняются. created — Unix seconds, startedAt переводится из ISO в seconds; равенство включено. Tombstone до старта, иной kind или получатель вне состава RUN не влияют. Отсутствующая таблица поддерживается как legacy без tombstones; существующая повреждённая таблица/дата не считаются пустой историей.

Это консервативный alarm, не доказательство принадлежности pruned task именно этому RUN: недавний tombstone другого RUN у того же участника также может дать неполноту. При удалении последнего task участник остаётся в roster для именованного отказа. Guard применяется до owner_export, не маскируется пустым ledger/состоянием; список pruned заново создаётся для каждого RUN. Публичный формат receipt и phase не расширяются.

Решение переводит прежний GC Important в принятую именованную границу со страховкой. После48ч либо при TASK_PRUNED нельзя объявлять полные доставки/числа только по оставшимся messages; неизвестный расход не записывается измеренным нулём. Монтаж и полный caller acceptance остаются внешними воротами.

## Raw cursor/index for the 0.1.14 component

The owner exporter uses the same DB4 connection and shared Reader lock for R and raw namespaces. Raw records are metering/identity/ancestry projections; prompt text and tool input are discarded by a resumable streaming decoder. Public receipt v4, phase and its partial-reason allowlist are integrated by Alpha. This component returns private childReason: only a pure missing-witness diagnostic gets CHILD_VERSION_WITNESS_UNAVAILABLE; additional native/capture faults keep CHILD_INCOMPLETE.

Each owner pass reads at most 4 MiB raw bytes, including up to 8192 control bytes, with 64 KiB read blocks. A fixed snapshot goal is retained until ingest catches it. Unchanged warm input reads zero raw bytes; append continues the checkpoint. Inode replacement, truncate or detected control changes start a new epoch and return RAW_REPLAY_PENDING. Time exhaustion commits safe progress and keeps the current participant incomplete/null. No old receipt numbers are carried to a new cut. SQLite projections, repeated identity/ancestry reads and the resumed cursor/checkpoint count as serialized UTF-8 metadata bytes in the shared Meter; this is logical materialization, not filesystem page IO. Non-raw owner metadata is capped at4MiB and the existing combined budget remains16MiB. A metadata refusal keeps budgetScope=metadata.

Limits: JSON depth64, serialized projection256KiB including partial state, checkpoint512KiB, owner view8MiB aggregate, active UID index128MiB, private UID directory1GiB including bounded journal/backup headroom. Before writes, statvfs f_bavail*f_frsize must be at least1073741824 bytes. This check reserves no global space and cannot prevent other services filling the filesystem. No root quota pool, admission registry or tokens are used. One UID-directory .reader.lock is held before DB creation through R/raw writes and commit. Contention stops after250ms as RAW_INDEX_BUSY; retry belongs to the next normal collector tick.

Raw facts retain byte-end and event-time versions; ancestry is not cut at RUN start or age. Epochs/leases are retained conservatively; this component never evicts OPEN evidence to satisfy a cap. No autonomous GC without authoritative root lease-close input is introduced. A capacity/disk/decoder/view refusal is named and never becomes measured0. Partial raw input remains pending, including a child file.

Synthetic exemption is limited to the inspected Claude2.1.299 rate-limit API-error form: true flag, exact error/model, UUID message ID, zero billing/tool counters and no tool-use. Known nullable SDK metadata fields are allowed only as null; unknown/positive fields refuse exemption. The node remains in ancestry, while provider IDs/calls/usage exclude it consistently. Real provider-ID and usage equality stay strict.
