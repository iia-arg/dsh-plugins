# Child metering contract, AP 0.1.12 unified wire

Implements accepted wire `ab58161aed88ca9dd8befb05a936530e8dcb466c936e73e0d436d3b5bbd97d0f`. The owner path remains `runtime_receipt_source.prepare` → protected prepared cut → `team_usage.iteration/read_public`. No physical R, model call or registration is invented. The rollout order is AP reader before the separately delivered gateway producer; this package does not install that producer.

Each root observer must carry one consistent `source_version` with the loaded-process witness, a full five-field sourceVersion, `sourceVersionKey=sv1:SHA256(compactJSON([1,engine,cliVersion,sdkVersion,sdkEntrySha256,profile]))`, and the engine-specific versionProof. Native/disk versions never replace this witness. Codex uses `codex_initialize_user_agent` and null SDK fields; Claude uses `claude_system_init_and_import_cache` and the loaded SDK fingerprint. Source/process/R identity remains independently checked. Unknown keys/profiles and missing witness preserve root numbers with CHILD_INCOMPLETE.

Supported profiles are data in sibling `child-source-versions.json`: schemaVersion1, sourceVersions (full sourceVersion objects), nativeFormats (profile → fixed native-format enum). Only `codex-multi-agent-v2` and `claude-jsonl-v1` exist; JSON cannot select executable decoder code. Native Codex CLI must agree with the witness and multi_agent_version must be v2. The default has one supported real profile per engine. Trusted in-process configuration `runtime_receipt_source.CHILD_SOURCE_MANIFEST` can select another checked manifest; owner CLI defaults to its immutable sibling. This is not an env variable or a field accepted from R/G/native. A test can register its explicitly authorized synthetic second profile mapped to the same native format, then unknown must refuse. It does not attest a real second installed CLI.

The supported accounting depth is exactly1 for both engines. Codex native parent_thread_id plus parent/root turn attribution joins a child to a unique root request. A matching own-request child_edge and protocol_usage/turn_terminal independently prove the source and numbers, bounded by observer close and R/job/cut. Protocol proof from another excluded observer is never borrowed. Native nested descendants and unproved spawns make the root incomplete while preserving proven parent/depth1 charges.

Claude uses `(agentId,runId)` for the execution and `(taskId,runId)` for terminal lookup inside the original root/process envelope. Task/agent must agree for local_agent; spawnDepth1 and the root parentThreadId must agree, and an explicit parentTaskId contradicts this depth. Parent provider message.id, actual Agent/Task/SendMessage tool ID and nearest native user.promptId by a checked parentUuid chain must all agree. A hook callback UUID cannot replace provider toolUseId. Native final message-ID usage supplies all six metrics; child_usage is optional independent cross-checking, and SDK notification total_tokens never bills. Native usage cannot precede its parent tool-call. Arrival order may be terminal-before-start; explicit IDs and native timing still have to prove the execution.

`child_capture_end` is required for complete status on both engines, including zero children. It proves observer.close; `engine_process_closed` only proves source-process exit and never substitutes for that end or cuts off later valid delivery before it. When end is present, no child terminal/edge/protocol proof beyond it is accepted. Sequence order within the observer also bounds proof when observedAt timestamps tie in the same millisecond; repeated late facts cannot reopen capture. End counters are checked against own-observer lifecycle/child-turn records; native graph is checked separately, so zero counters never prove child-free by themselves. A missing end makes completeness unknown; independently proved native/G completed-execution costs inside R/job/cut remain numeric as CHILD_INCOMPLETE. The accounting cut limits such partial proof without inventing an observer.close fact. Late terminal keeps the original start/envelope/key. Native nested or unknown/unbound evidence preserves proven parent/depth1 as incomplete. Root engine end, process exit and observer close are distinct; R/job/cut guards remain unchanged.

Every owner pass rebuilds the child join from current snapshots, including R readBytes0. Supplier has no cross-pass parser cache. Persistent R attribution cache is version-neutral. Consumer native parser-cache namespace includes the verified sourceVersionKeys; changing the namespace forces a native reread. Provider candidates are deduplicated within `(sourceVersionKey,uid,thread,providerId)`. One physical native record with contradictory source versions refuses instead of producing a second charge. Returned totals replace prior totals rather than incrementing them.

Limits: at most128 derived child executions per root observer,128 native files and the existing owner byte/time budgets; new child records are bounded to4096 serialized bytes, ASCII IDs1–256, diagnostics32. Invalid child payload and child overflow stop that child capture/read locally and preserve root. Root file, identity, origin, R/job or usage mismatches retain their hard refusals. No child retries or extra wait are added. These limits do not prove delivery by SDK, protect against forged same-UID journals/compromised G producer, or support nested/remote/workflow billing.

Canonical paths retain strict version-format templates, NOFOLLOW walks, owner/type/nlink/prefix and identity checks. Public schema3 contains no private version, path, run/task/agent/process ID, topology or subreason. Proven parent+depth1 totals include child subset once; incomplete rows retain numbers and measured/missing coverage overlap. Null means no proven contribution. Capture/public privacy and actual production delivery remain separate gates.

Independent M11–M15 oracle belongs to Alpha. Beta may supply a separately checksummed data-only fixture adapter through the published harness interface; the source suite and numerical oracle remain unchanged. Full AP and independent code review precede candidate handoff. No test or this document authorizes mounting, live collection or migration of old pins.
