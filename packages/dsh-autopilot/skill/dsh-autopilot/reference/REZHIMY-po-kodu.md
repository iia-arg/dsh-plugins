## 4. Как он отдаёт работу исполнителям

**Встроенного запускателя нет.** `ap.py` не вызывает моделей и процессов, кроме `git`, `http.server` и самого себя
[код] (`subprocess` только в `S/tools/ap.py:589,625`, а также `git mv` и `git -C`). Исполнителей запускает модель-
оркестратор средствами своего движка [док] `S/phases/5-subagents.md:33`: «one subagent call per ticket, in the
background». В Claude Code это вызов Agent с `model: "sonnet"` для обычной модели [док] `:27`.

Устройство обмена [док] `S/phases/5-subagents.md`:
- **Что уходит** (`:11–25`) — пути, а не содержимое:
  - `prompts/executor.md` по пути от `skillDir` (обязательное чтение);
  - файл таска, нужные разделы `spec.md` по заголовкам, `interfaces.md`, `notes.md`, `reference.md`;
  - команда проверки, зона таска и чужие зоны;
  - имена переменных, без значений.
- **Что возвращается** (`:44–59`) — блок до 25 строк, без кода и диффов: `STATUS: DONE | DONE_WITH_CONCERNS | BLOCKED |
  NEEDS_CONTEXT`, `FILES`, `TESTS`, `REDPROOF`, `INTERFACES`, `REQUIREMENTS`, `CONCERNS`, `BLOCKERS`.
- **Ожидание волны = конец хода оркестратора**: фоновый субагент сам будит его по возвращении. Ждать циклом
  запрещено (`:40`).
- **Одно рабочее дерево на всех** исполнителей. Каждый трогает только свою зону, коммитит оркестратор по зоне,
  один коммит на таск (`:42,71–78`).
- **После каждого таска** — девять шагов в строгом порядке (`:61–82`): разбор блока, проверка «ничего вне зоны»,
  интерфейсы, полная проверка, точечное ревью, починка, коммит вместе с `ticket NN done`, учёт, одна строка
  пользователю.
- **Починка** [док] `S/phases/5-repair.md:11–17`:
  - недоделку отдают тому же исполнителю сообщением в его живой контекст (дозапрос);
  - отказ — свежему контексту на сильной модели.
  - Если движок не умеет продолжить субагента — свежий контекст с полным таском, но никогда не руками оркестратора
    (`S/phases/5-repair.md:33–34`).
