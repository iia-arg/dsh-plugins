# dsh-compact-outcomes — расширение наблюдателя (A-N-675; номер пакета — заголовок CHANGELOG)

Расширение существующего наблюдателя, не второй таймер. Старый collector/classify сохраняет прежнюю проверку подтверждённых компактов, связь DSH/Codex UUID, суточные и недельный отчёты. К ней добавлены turn-sensor.mjs и turn_watch.py.

## Что было и чего не было

0.1.0 считает события compacted и start/summary/end, НЕ ходы. Падение без compacted уже правильно считает неизвестным сигналом. Нет измерения tokenMeter.measure на границе каждого хода, нет лога порога, нет agent-alert для таких падений. Его DONE завершает недельный опыт. В бою этот механизм работает, несмотря на устаревшую шапку прежнего README «не смонтирован».

## Датчик в платформе

Датчик подключается блоком профиля, а не файлом пакета: блок `compact-outcomes-turns` под условием `@@ESLI COMPACT_OUTCOMES@@` в шаблоне реестра `/etc/agent-registry/shablony-raskladki/codex/A.tmpl` (см. раздел «Установка», п. 5, в README корня пакета). Отдельных файлов `profile-*.patch.yml` в пакете нет. appDir каждой платформы задаётся в `config` блока. При подъёме агенту доступен turn-sensor.mjs из этого пакета; exports name/inject/apply, сервисы tokenMeter и llm. Блоки профилей требуют обычных ворот выпуска/подъёма, не начинают работать от наличия файла.

В agent/pre-step считывается scoped our/compaction-status и информация окна той же выбранной модели; modelPolicies имеют приоритет над общей thresholdRatio, как у compaction-basic. Снижение Альфой .95 → .90 не требует правки датчика. Запрос метаданных ограничен 1000 мс; ошибки наблюдателя не обрывают ход. Число снимается непосредственно tokenMeter.measure(session).totalTokens на событии turn/end, включая завершения с ошибкой. Это НЕ inputTokens, НЕ baseline.tokens и НЕ размер файла / 4. Ошибка измерения/метаданных записывается явно, null не равен нулю.

Одна строка JSON на turn/end: Unix-ms time, agent, session+createdAt, turn, seq, phase, tokens, threshold, window, auto, model, baseline kind, uuid, platform_seq, error. UUID берётся read-only из карты того же агента по ключу первого сообщения, не выбирается самый свежий rollout. Разрешены только alfa/beta/gamma. Тексты сообщений и секреты не пишутся.

Логи /opt/coders/alfa/pamyat/compact-outcomes/turns/{alfa,beta,gamma}.jsonl. Для каждого 8 МиБ + 5 архивов; общая верхняя оценка около 144 МиБ плюс небольшие строки. Пишет coders; каталог 0700, файлы 0600. Убитый до turn/end процесс НЕ оставит окончательного среза своего незавершённого хода. После монтажа прежние ходы не восстанавливаются задним числом. Номер пропущенного хода разрывает сравнение. Одновременные два живых процесса одного агента этим датчиком не поддержаны: монтажник должен исключить такую раскладку.

## Сборщик и сигнал

Тот же collector, опции --turn-log-dir, --alert (умолчание /usr/local/bin/agent-alert), --drop-ratio (умолчание 0.5). Сравниваются только последовательные turn одного agent/session/createdAt/UUID, при том же model/window и известных данных. Ровно половина НЕ тревожит: требуется after < before*ratio. Порог в тревоге — снимок ДО падения, нынешние настройки не подставляются задним числом.

Если между срезами изменился последний seq compaction/start/summary/end/prune, отдельная запись «платформа» в turn-alerts.jsonl, без тревоги, даже если падение меньше половины. Это событие платформы, не утверждение об успешном завершении сжатия. Без такого события сильное падение → agent-alert «признак “сжал Codex”: было N → стало M, порог платформы P». Причина ПО ОДНОМУ падению не доказана: текст прямо говорит, что compacted не подтверждён этим признаком. Подтверждённые compacted по-прежнему проверяет старый observer. Не смешиваем гипотезу и подтверждение.

Состояние turn-watch-state.json отдельно от недельного state.json. Сначала сохраняется pending, затем вызов канала; при падении между успешной отправкой и сохранением возможен повтор. Не более 2 вызовов за проход, timeout 15 секунд каждый, максимум 3 попытки для события; окончательный отказ печатается в turn-alerts.jsonl как failed-after-3. Журнал решений также 8 МиБ + 5 архивов. Неполная последняя строка входа ждёт следующего прохода, битый JSON даёт отказ, не нулевой итог. Ротация быстрее опроса может потерять строки; разрыв ходов не сравнивается.

## Единицы systemd и срок

Кандидат service сохраняет нынешний ExecStart с двумя новыми опциями, повышает TimeoutStartSec 55 → 90 и убирает ConditionPathExists=!…/DONE. Новый collector проверяет turn-log ДО выхода по DONE: недельная часть по-прежнему заканчивается, монитор ходов продолжает работать тем же таймером. timer меняет только описание, период 60 секунд после окончания предыдущего запуска сохранён. Задержка тревоги — опрос плюс длительность прохода, не мгновенная. ReadWritePaths прежний каталог compact-outcomes уже покрывает новые файлы; права профилей/каталога обеспечить до подъёма.

## Монтаж после ворот

Сначала страховки файлов пакета и обоих юнитов; установить новые/изменённые файлы и подготовить logDir. Затем добавить блоки в три профиля, сверить фактическую загрузку датчика и согласованно поднять процессы (рука координатора). Убедиться: очередной настоящий turn/end каждого даёт строку, threshold равен /compact-status на той же модели/настройке. Затем установить collector/unit, daemon-reload и проверить тот же таймер. Старые state.json/DONE не удалять. Новый turn-watch-state.json должен начинаться пустым; не переносить туда тестовое состояние. Нельзя заявить монтаж датчика только по его файлу.

Откат: вернуть юниты и collector/observer по страховкам, убрать только новые блоки профилей и поднять затронутые процессы по порядку; накопленные логи не удалять.

## Пробы и границы

python3 -m unittest -v test_turn_watch test_observer
node test_turn_sensor.mjs

Новые пробы: рост без падения, строгое пересечение половины, платформа вместо тревоги, падение без платформы с числами и следом заглушки, повторный проход без повторной отправки, смена UUID/сессии/пропущенный ход/неизвестные данные не дают ложной тревоги; DONE не гасит монитор; датчик берёт totalTokens при намеренно другом baseline.tokens, scoped порог .90, SQLite UUID, один срез на событие, ротация active+5. Снятие классификации в mutation-копии ломает пробы, возврат восстанавливает.

Полный запуск трёх платформ с этим плагином НЕ выполнен. Подключение и живой признак — обязательная приёмка после монтажа; unit-тест с контекстом не доказывает регистрацию в рабочих профилях. Потери между COMMIT событий и вызовом датчика, ошибки диска, смена схемы API, повторный процесс и ротация вне окна покрытия не превращаются в доказанный компакт. Бой этим тактом не менялся.
