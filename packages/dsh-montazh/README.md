# dsh-montazh — монтаж, страховки, выпуск метками, суммы предмета, сводки приёмки

**Версия:** 3.1.24

Служебный софт машины sadik: чем монтируют выпуски и файлы в бой, страхуют прежнее состояние, ставят метки
выпусков, считают сумму предмета пакета, собирают сводку состояния и вердикты приёмки, проверяют публикуемое
перед выпуском наружу. Сторожа: срок страховок, страхование модулей, живая версия общих носителей, метки мимо ворот
выпуска.

**Временное правило (Вениамин, 07.10.2026):** пока у новых пакетов нет читателя «бой ↔ метка», любой файл пакета
меняется только вместе с новым номером пакета в том же окне.

Пакет — исходники без `package.json`: каталоги `bin/`, `sbin/`, `libexec/` повторяют пути под `/usr/local/`,
юниты и drop-in — в `systemd/` (пути под `/etc/systemd/system/`). Номер — заголовок CHANGELOG и метка
`dsh-montazh-v<номер>`. Перенос с боя: сумма каждого файла в дереве равна сумме боя.

С 1.0.20 `bin/vorota-obezlichivaniya` — ворота СЕКРЕТОВ (слово владельца 09.10.2026): образцов настоящих адресов в нём нет, прежняя строка «заменить образец адреса до публикации» снята вместе с классом адресов.

Снят: `tri-stolbca` (сторож трёх столбцов) — снят 07.10.2026, B-N-1717 (юнит снят, скрипт в бою оставлен), в пакет не входит.

## Установка и снятие (руками root)

Установка файла: `install -o root -g root -m <режим из таблицы> <файл в пакете> <путь на диске>`; в бою — через
`smontirovat-fajly` по воротам. Юниты: положить в `/etc/systemd/system/` (drop-in — в свой каталог `*.service.d/`),
`systemctl daemon-reload`, `systemctl enable --now <имя>.timer`.

Помощник следа ставится в свой каталог: `install -d -o root -g root -m 0755 /usr/local/libexec/vypusk-tegom`. Сторож меток
мимо ворот включается в таком порядке, от root:

```
install -d -o root -g root -m 0755 /var/lib/vypusk-tegom
/usr/local/sbin/metki-mimo-vorot-watch --snimok        # ОДИН раз: снимок исторических меток
systemctl enable --now metki-mimo-vorot-watch.timer
```

Снимок `--snimok` пишет `/var/lib/vypusk-tegom/istoricheskie-metki.tsv` (0444) — все метки деревьев реестра на эту минуту. Без
снимка сторож слепнет. Второй `--snimok` отказывает (код 1): переснять — значит узаконить всё, что легло после журнала.

Снятие юнита — `systemctl mask` (правило фермы 9): наш юнит с файлом в `/etc/systemd/system` mask не примет —
файл в страховку (`mv`), `daemon-reload`, `mask`; вернуть — `unmask` и файл назад.

## Область выпуска npm-пакета (B-N-1823)

`vypusk-tegom <каталог>` читает `plugins` и `services` из `/etc/agent-registry/plugins.yaml`
(подмена для кандидата: `VYPUSK_REESTR=<абсолютный путь>`). Каталог копии у записи `plugins` —
её `path`; у записи `services` — `path`, если это абсолютный каталог с `package.json`, иначе
`source.address` при `source.type: local-dir` (адрес-файл — его каталог). Запись `services`
без такого каталога считается отдельной строкой «не копии пакета», а не «не судимы».
Семья — все записи, у которых `package.json.name` по каталогу копии совпадает с именем выпуска.
Id, имя каталога и уже установленная версия семью не определяют. Отсутствующий
`path/package.json` (включая путь файла/описательный путь) и не абсолютный путь
названы поимённо как «не судимы». Ошибка доступа/чтения metadata или повреждённый
JSON дают слепоту, код 2. Явный выбор несудимой записи также даёт слепоту.

По умолчанию выпуск относится ко всей семье. Частичный выпуск задаётся явно:

```json
{"package":"dsh-tool-bridge","version":"1.3.38-b1825","copies":["dsh-tool-bridge-varvara"]}
```

```bash
VYPUSK_KOPII=/absolute/path/copies.json vypusk-tegom /absolute/path/release
```

Перечень привязан к имени и версии; его SHA256 напечатан в выводе и аннотации.
Неизвестный, повторный, чужой или несудимый id, пустой список и неверная привязка
дают слепоту. Копия, чей каталог — сам каталог выпуска, тоже даёт слепоту: сверка
с собой ничего не доказывает. Исключённые члены семьи названы поимённо. Каталоги
обходчика область равенства выпуска не назначают; какие стенды он гоняет — см.
«Область стендов выпуска» ниже. После поведенческого прогона тарбол и стенды дерева
сверяются с каждой выбранной копией. Стенды сверяются в обе стороны. Несовпадение
байтов — отказ, код 1. `STENDY_INACHE` пропускает поведенческий обход с честным
доводом, но не сверку копий. Все советы аннотированного тега содержат область.
Читатели — выпускающая рука и приёмщик; аннотацию читает `git show <тег>`.

Границы: незарегистрированные копии, правомерность выбранного subset, дополнительные
файлы боя вне тарбола и образцов стендов, права/владелец файлов, импорт живым процессом
и поведение каждой среды не проверяются. Запись без metadata не считается доказанно
чужой копией. Режим пакета дерева без `package.json` работает по прежнему `derevo`.
Один проход, без повторов; пределы: 4096 записей `plugins` и `services` вместе, 256 выбранных копий,
16384 файла тарбола. Ворота ничего не монтируют и метку сами не ставят.

Пробы копий: `python3 test/stend-vypusk-kopii.py <путь ворот>`. Монтажный путь
стенда — `/usr/local/libexec/stend-vypusk-kopii.py`; его зовёт штатный
`stend-vorot-vypuska.sh` из `dsh-obhod-stendov`, подмена кандидата — `STEND_KOPII`.
Монтировать ворота, новый стенд копий и адаптацию штатного стенда одним окном;
в `derevo.files` реестра добавить новый монтажный путь. Установка/учёт —
назначенная монтажная рука после приёмки.

### Выпуск по местам (запись `derevo`, с 1.0.13)

Если копий-каталогов нет и `VYPUSK_KOPII` не задан, но в реестре есть запись `derevo`, чей
`subdir` совпадает с концом пути каталога выпуска, ворота сверяют исполняемое по местам:
каждый `files.local` побайтно с `files.remote` дерева выпуска; файлы из `expected_diff_files`
пропускаются. Расхождение — ОТКАЗ с перечнем «remote → local», код 1. Запись называет файл,
которого в дереве нет, или все места пропущены — СЛЕПОТА, код 2. Записей `derevo` на этот
каталог больше одной — тоже слепота. Записи нет — прежняя слепота «нет зарегистрированных
копий». Аннотация тега: `derevo=<id>; files=N; registry_sha256=…`. Режим и владелец мест не
сверяются, только байты.

### Метапакет (с 3.1.3)

Если `VYPUSK_KOPII` не задан, копий-каталогов нет и записи `derevo` нет, а имя пакета есть в закрытом
перечне метапакетов ворот (сейчас только `dsh-pamyat`; пополнение — только правкой ворот), копией выпуска
служит архив полки `/opt/agent-plugins-tarbally/<имя>-<версия>.tgz`. Копий в бою у метапакета нет по
построению: зонтик набора на машину не ставится. Архив открывается без перехода по ссылке и обязан быть
обычным файлом root, который не пишется группой и прочими, не больше 256 МБ. Архив не распаковывается:
члены читаются в памяти и сверяются с тарболом ворот в обе стороны.

- Сошлось — «МЕТАПАКЕТ <имя> <версия>: копий в бою нет по построению; копия выпуска — архив полки
  <путь> SHA256=…; файлов N из N», дальше ворота идут прежним ходом.
- Член архива не обычный файл или каталог (символьная или жёсткая ссылка, устройство, FIFO), с абсолютным
  путём, с «..», вне `package/` или повтор — ОТКАЗ с именами членов, код 1.
- Архив ≠ тарболу ворот — ОТКАЗ «… ≠ тарболу ворот: различаются / лишние в архиве / нет в архиве: …», код 1.
- Архива нет, он не открылся без перехода по ссылке, не обычный файл, хозяин не root, пишется группой или
  прочими, больше 256 МБ, не читается или в нём больше 16384 файлов — СЛЕПОТА, код 2.

Аннотация тега: `polka=<путь архива>; sha256=…; files=N; registry_sha256=…` (при подмене полки ещё
`podmena_polki=…`). Имени нет в перечне — прежняя слепота «нет зарегистрированных копий».

Подмена полки `VYPUSK_POLKA_DIR` — только для стенда. Задана без `VYPUSK_ZHURNAL_DIR` или с ним, ведущим
(по `realpath`) в боевой `/var/lib/vypusk-tegom`, — ОТКАЗ в самом начале ворот, код 2: ничего не сверено,
следа нет. Задана пустой — СЛЕПОТА на пути метапакета. При подмене печатается «ПОДМЕНА полки: …».

Ворота не ловят подмену архива на полке рукой с `NOPASSWD ALL` до прогона и не судят состав членов
набора — это `stend-sostava` в тех же воротах.

### Область стендов выпуска (с 1.0.14)

Перед обходчиком ворота строят план тем же отбором копий:
- `VYPUSK_KOPII` задан — стенды гоняются только на выбранных копиях, а не в боевой области
  обходчика. Перечень — стенды дерева выпуска на каждой копии. Копия чужой учётки — под этой
  учёткой (владелец каталога), корень платформы `/opt/<учётка>/app`; его нет — СЛЕПОТА.
  План по `VYPUSK_KOPII` не построен (неизвестный id и т. п.) — сразу СЛЕПОТА, ни один стенд не
  гоняется.
- пакет по местам (запись `derevo`) — гоняются стенды дерева выпуска; их нет — СЛЕПОТА «в
  дереве выпуска стендов нет».
- метапакет — прежние область и перечень обходчика (план «OBYCHNO», архив полки при построении плана
  не читается): стенды зонтика гоняются обычной областью.
- иначе — прежние область и перечень обходчика.

Область и перечень уходят обходчику переменными `OBLAST_STENDOV` и `PERECHEN_STENDOV`.
Учётка отдельного стенда берётся из строки области самого обходчика (`путь @учётка корень`).

### Как ворота гоняют обходчик (с 1.0.15)

Обходчик идёт не в процессе зовущего, а отдельной службой:

```
sudo -n systemd-run --wait --pipe --collect -p User=<зовущий> -p UMask=0022 -p RuntimeMaxSec=3000 …
```

Группы — свежие по учётке (лишние группы зовущего печатаются строкой «среда стендов» и в стенды
не попадают). Среда — вся среда юнита `vse-stendy-boevye.service` плюс подмены обходчика,
заданные зовущим; среда юнита главнее. Значения уходят в argv `sudo` и видны в `ps` и `/proc`
всем учёткам, пока идёт прогон: секреты не класть ни в Environment юнита, ни в подмены.

- Нет `sudo -n systemd-run` — СЛЕПОТА, в процессе зовущего ворота стенды не гоняют.
- Обходчик вернул 1 без итоговой строки «ПОКРЫТИЕ:» — СЛЕПОТА «обходчик оборван» (так
  systemd-run отвечает и на гибель по пределу, сигналу или OOM). Подмена предела
  `VYPUSK_OBH_PREDEL_SEK` — только для стенда ворот, печатается.
- Когда область стендов выпуска задана (копии или места), ворота до прогона проверяют, что
  `$VREM` и пути области видны службе: устройство:inode у зовущего должно совпасть с
  `/proc/1/root<путь>`. Нет права на `sudo -n stat /proc/1/root` или вход не читается у самого
  зовущего — СЛЕПОТА; не совпало — СЛЕПОТА «/tmp зовущего ≠ /tmp службы» (зовущий под
  PrivateTmp). Совет — задать `TMPDIR` на общий путь вне `/tmp` и `/var/tmp`.

### След ворот (с 1.0.17)

Ворота метку не ставят — её ставит рука по «✅». Прямо перед «✅» (в обоих режимах) ворота
зовут через `sudo -n` помощник `/usr/local/libexec/vypusk-tegom/zhurnal-zapis`. Он сам (root)
находит репозиторий каталога выпуска, вычисляет коммит, tree каталога и чистоту; git зовёт от
владельца `.git` через `setpriv`, без записи индекса. Строку следа он дописывает в
`/var/lib/vypusk-tegom/zhurnal.tsv` (0644), полный вывод прогона кладёт копией в
`/var/lib/vypusk-tegom/vyvod/`, его сумму — в строку следа. Файл вывода помощник принимает только обычным файлом, хозяин
которого — сам зовущий (`SUDO_UID`), и открывает без перехода по ссылке; иначе — слепота. Перед помощником ворота дожидаются,
пока вывод допишется: не дописан за 10 с — «СЛЕПОТА: вывод ворот не дописан…», следа нет.

| исход помощника | код помощника | что делают ворота | код ворот |
|---|---|---|---|
| след записан | 0 | «✅ можно ставить ЛОКАЛЬНЫЙ тег» | 0 |
| каталог выпуска ≠ HEAD (грязный) | 3 | «🔴 ОТКАЗ … Закоммить и повтори» | 2 |
| каталог вне git (прогон на копии) | 4 | «✅ ПРОБНЫЙ ПРОГОН, метку по нему сторож не примет» | 0 |
| слепота: нет каталога журнала, он не root или пишется группой/всеми, `.git` у root, git не ответил | 2 | «СЛЕПОТА: след ворот не записан», «✅» нет | 2 |

Код ворот 2 здесь бывает и при отказе (грязный каталог): общее «отказ = 1» к следу не
относится. Подмены `VYPUSK_ZHURNAL_ZAPIS` (путь помощника) и `VYPUSK_ZHURNAL_DIR` (каталог
журнала) — только для стенда. Граница: у учёток с `NOPASSWD ALL` подделка следа возможна —
цель «метка мимо ворот видна», а не «невозможна».

Коды `vypusk-tegom` в целом: 0 — метку ставить можно (или пробный прогон без следа); 1 — отказ
(в том числе: обходчик не зелёный, выпуск ≠ копии, месту или бою; в режиме дерева — метка уже
есть); 2 — слепота, а также отказы «каталог грязный» и «подмена полки при боевом журнале».

## Сторож меток мимо ворот (`metki-mimo-vorot-watch`, с 1.0.17)

Сторож судит каждую метку деревьев `derevo.address` реестра (`plugins` и `services`) и каждую
метку `derevo.ref`: у метки должен быть след ворот с той же версией и тем же пакетом, а tree
каталога в метке — равен tree из следа. Красное называется по имени:
- «МИМО ВОРОТ» — следа на метку нет;
- «НЕ ТО, ЧТО СУДИЛИ» — след есть, а содержимое каталога в метке другое;
- «ПЕРЕНЕСЕНА историческая метка» — метка из снимка теперь указывает на другой объект;
- «РЕЕСТР ССЫЛАЕТСЯ НА МЕТКУ, КОТОРОЙ НЕТ» — `derevo.ref` указывает в пустоту.

Исторические метки (поставлены до журнала) берутся из снимка `--snimok` (см. установку): с тем
же объектом — не красное, считаются числом с разрезом по пакетам в сводке. Без снимка сторож
слепнет.

Голос — `agent-alert --plain`; сказанное помнится в `/var/lib/metki-mimo-vorot-watch/skazano.txt`
и повторно не кричит, отметка ставится только после доставки. Итог — `itog.json` там же.
Коды: 0 — красных нет; 1 — красные есть, все уже сказаны; 3 — новые красные (сказано или нет —
в выводе и в `itog.json`); 2 — слепота (реестр не разобран, нет снимка, журнал или его каталог
не root либо пишутся группой/всеми, метки дерева не прочитаны). Неизвестный довод — отказ, код 2.

Переменные — для проб: `MMV_REESTR` (`/etc/agent-registry/plugins.yaml`), `MMV_ZHURNAL_DIR`
(`/var/lib/vypusk-tegom`), `MMV_ALERT` (`/usr/local/bin/agent-alert`), `MMV_STATE` (иначе
`STATE_DIRECTORY` юнита, иначе `/var/lib/metki-mimo-vorot-watch`).

Юнит: oneshot от root (рабочие деревья агентов закрыты 750), `SuccessExitStatus=1 3` — падением
юнита считается только слепота; `StateDirectory=metki-mimo-vorot-watch`, `ProtectSystem=strict`,
`ProtectHome=read-only`, `PrivateTmp=yes`, `TimeoutStartSec=5min`. Таймер — `*:0/15`, разброс 60 с,
`Persistent=true`. Не ловит: подделку следа рукой с `NOPASSWD ALL`, метку, поставленную и снятую
между прогонами, метки вне деревьев реестра, верность самих ворот.

## B-N-2043 Ш2 — окно целой копии (3.1.24)

Ш2 покрывает обычную ветку сравнения VOW через точный `copy:<repo>:<subdir>:<root>` без номера версии. Новый JS при старом manifest сохраняет адрес копии. Baseline отката helper снимает сам: учитываемые прежние файлы с полным SHA256, правами и владельцами, root identity, отсутствие новых путей и прежние ref/version/fingerprint реестра. После восстановления из страховок всех выбранных корней вызывай `montazh-okno otkat-proveren ID` без своего плана. Неполный или изменённый caller baseline не принимается; source-only/ручной copy-plan через `otkryt` не заменяет автоматическую подготовку. Helper проверяет возврат, сам файлы не восстанавливает. Если новая tag отсутствовала до открытия, возврат требует её отсутствия; существовавшую tag удалять нельзя.

Чистый прибор `copy-compare.sh` принадлежит пакету `dsh-vypusk-watch`. Результаты: 0 совпало, 1 разошлось, 2 слепота; JSON без канала/ledger/4. Закрытие дополнительно проверяет все файлы настоящего npm-тарбола, права/владельцев, registry и refs/tags. Npm при закрытии не запускается. Общий барьер повторно снимает полные учитываемые имена и поколения после внешних config/tag проверок.

Проверенный copy-откат доказывает точное прежнее физическое состояние и SHA256 полной прежней записи реестра, включая отсутствие добавленных полей. Старые installed_check/health callbacks при этом не исполняются. `rolled_back` не означает здоровье старой копии; yunit-читатель не превращает такой snapshot-откат в зелёную приёмку. Forward close и ordinary VOW продолжают строгую проверку действующего состояния. / Copy rollback proves the exact old physical snapshot and full registry-entry digest, without executing old installed_check/health callbacks. It does not establish health; unit readers cannot treat it as a healthy release. Forward close and ordinary VOW retain strict current checks.
