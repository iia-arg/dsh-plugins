# ОПИСЬ ПРЕДМЕТА: канарейка шлюза подписки.
#
# ЗАЧЕМ. Координатор замораживает предмет перед приёмкой ПО ЭТОЙ ОПИСИ, а не по
# перечислению из памяти: перечень-копия отстаёт от источника всегда.
#
# ГРАНИЦА. Опись замораживается ВМЕСТЕ с предметом одним замером; её сумма
# называется наравне с остальными. Описи описи не заводим: неполнота ловится не
# перечислением, а свойством — стенд слепнет или предмет не собирается.
#
# 🔴 ПЕРЕНОСИМОСТЬ. Ни в одном файле предмета нет вшитого каталога агента:
# боевая установка задаётся снаружи (KANAREJKA_DOM у канарейки,
# KANAREJKA_ISHODNYJ_DOM у стенда), инструменты берутся относительно себя.
# Умолчания «мой каталог» нет намеренно: отсутствие переменной даёт слепоту с
# причиной, а не тихий поиск чужого пути.

kanarejka-shlyuza.sh                       предмет: сама проба
edinstvennye-sushchnosti-shlyuza.json      данные предмета: что подменять и почему
podmeny-shlyuza.py                         строит подмены ИЗ списка
ostatki-shlyuza.py                         проверка РЕЗУЛЬТАТА: не уцелело ли боевое значение
stend-kanarejki-shlyuza.sh                 приёмка: едет вместе с предметом, потому предмет
zayavlennye-proverki-kanarejki-shlyuza.json данные приёмки: заявленный состав проверок
opis-predmeta-kanarejki-shlyuza.txt        этот файл
