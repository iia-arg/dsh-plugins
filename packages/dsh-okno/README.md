# dsh-okno — инструменты окон обновления

**Версия:** 3.1.3

Служебный софт sadik для окон обновления: допуск к шагу Ш5 и атомарный обмен имён при смене SDK-слоя, опись слоя
по составу, перепаковка журналов сессий перед DSH 0.2, создание ключа службы OMEGA. Юнитов нет — ручные приборы окна.

Пакет служебный (группа Д): публикуется исходниками, без npm, после общих ворот секретов (`vorota-obezlichivaniya`).

**Временное правило (Вениамин, 07.10.2026):** пока у новых пакетов нет читателя «бой ↔ метка», любой файл пакета
меняется только вместе с новым номером пакета в том же окне.

Пакет — исходники без `package.json`: каталоги `libexec/`, `sbin/` повторяют пути под `/usr/local/`. Номер —
заголовок CHANGELOG и метка `dsh-okno-v<номер>`. Перенос с боя: сумма каждого файла в дереве равна сумме боя.

## Вызов и коды выхода

Доводы и коды сняты с кода. Неизвестный довод у всех пяти — отказ без действия.

| команда | доводы | коды выхода | что меняет на диске |
|---|---|---|---|
| `dopusk-sh5.sh <T1> <T2>` | `T1` — время обмена Ш1, `T2` — `daemon-reload` Ш2, оба — unix-секунды (10 цифр) | 0 — допуск; 1 — нет (юнит поднят раньше порога, не `active` или время подъёма не снято); 2 — вызов неверен | ничего: только `systemctl show` |
| `obmen-imyon.py <имя1> <имя2>` | два существующих имени в одном каталоге, ключей нет | 0 — обменяны; 2 — вызов неверен, имени нет, имена в разных каталогах или ядро отказало (`ничего не изменено`) | атомарно меняет местами два имени (`renameat2 RENAME_EXCHANGE`) |
| `opis-sloya.py <каталог> [--spisok]` | настоящий каталог (ссылку подают её целью); `--spisok` — печатать опись строками | 0 — опись снята; 2 — вызов неверен, пути нет или это не каталог; 3 — нет прав на файл или подкаталог | ничего: печатает строку на объект `путь · вид · значение · режим` — вид `f` (файл, значение — sha256), `l` (ссылка, значение — цель), `o` (прочее, значение — тип: `fifo`, `sock`, `chr`, `blk`, `inoe`; с 1.0.3, прежде такие объекты молча пропускались) — и итог `объектов N · опись sha256 …`; файл `.sostoyanie.json` в корне пропускает |
| `perepak-okna --progon \| --v-boj \| --otkat <агент> [--agent <имя>]… [--strahovka <кат.>] [--koren <кат.>]` | ровно один режим; `--agent` сужает перечень агентов реестра; `--strahovka` — умолчание `/var/backups/montazh/B-N-738-zhurnaly`; `--koren` — проба на копии (корень, ведущий к боевым путям, — отказ). Только root | 0 — все агенты прошли; 1 — хотя бы один агент отказан (остальные идут дальше); 2 — вызов неверен, не root или реестр не годен (не прочитан, не разобран, нет списка `agenty`, у агента нет `namerenie.sluzhba`) — «НИЧЕГО не сделано» до любого `systemctl` | `--progon` — ничего, только план и счёт; `--v-boj` — переписывает `session.jsonl.zstd` агента через временное имя и `rename`, прежний файл кладёт в страховку, 10 неоткрываемых каталогов переносит в `<страховка>/neotkryvaemye/<агент>/`; `--otkat` — возвращает из страховки побайтно |
| `sozdat-klyuch-omega` | доводов нет; только root | 0 — ключ создан или уже был (не трогает); 2 — отказ | создаёт `/etc/omega/mcp-klyuch.env` 0600 root, каталог `/etc/omega` 0755; значение не печатается и не идёт в argv |

**Зашито под sadik.** `dopusk-sh5.sh` проверяет поимённый список юнитов sadik (`dopusk-sh5.sh:21–23`: четыре
`claude-oauth-gateway@…` и пять шлюзов кодеров); `perepak-okna` переносит 10 неоткрываемых сессий из списка
`NEOTKRYVAEMYE` в `perepak-okna` (агент · путь · sha256). На другой машине оба списка бессмысленны: их правят под
свои юниты и свои журналы до запуска, иначе `dopusk-sh5.sh` даст «нет» по чужим именам, а `perepak-okna` не найдёт
неоткрываемых и пропустит их перенос.

## Зависимости

- Программы: bash, GNU coreutils (`date -d`, `install`, `stat`), systemd (`systemctl`), python3. Для `obmen-imyon.py`
  нужны Linux ≥ 3.15 и glibc ≥ 2.28: обёртка `renameat2` появилась в glibc 2.28 (`man 2 renameat2`, раздел HISTORY). На
  старой glibc вызов падает трассой `AttributeError` с кодом 1, а не отказом с кодом 2. Для `perepak-okna` ещё `zstd` и модуль python `yaml` (PyYAML), доступ к `/proc`. `sudo` утилиты
  не зовут: их запускает рука root.
- Предметы окон — SDK-слой платформы, журналы сессий DSH, служба OMEGA — в пакет не входят.

## Установка и снятие (руками root)

Установка файла: `install -o root -g root -m <режим из таблицы> <файл в пакете> <путь на диске>`; в бою — через
`smontirovat-fajly` по воротам. Юнитов нет. Снятие — файл в страховку (`mv`); зовущих нет, кроме руки в окне.

## Проверка

Сумма каждого файла пакета = сумма боя (`sha256sum`), права = таблице (`stat -c '%a %U:%G'`).
