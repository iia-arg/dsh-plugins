# Сторожа и проверки · Guards and checks — dsh-pamyat-kompakt-dsh

Пакет не молчит: каждая беда, которую он умеет различить, превращается в строку журнала службы агента (stderr процесса) или в тревогу владельцу через внешнюю команду `agent-alert`. Ниже — сторожа внутри кода и стенды рядом с ним. Для каждого сказано, что он ловит, чего НЕ ловит и как читать его сигнал.

The package does not stay silent: every problem it can tell apart becomes a line in the agent service journal (process stderr) or an alert to the owner via the external command `agent-alert`. Below are the guards inside the code and the stands next to it. For each: what it catches, what it does NOT catch and how to read its signal.

Все строки начинаются приставкой `[dsh-pamyat-kompakt-dsh <версия>]` (подключение движка) или `[kompakt-dsh <версия>]` (работа); строки отметки продолжения — `[continuation-marker] {…}` или `continuation …`.

All lines start with the prefix `[dsh-pamyat-kompakt-dsh <version>]` (engine connection) or `[kompakt-dsh <version>]` (operation); continuation marker lines — `[continuation-marker] {…}` or `continuation …`.

## Как читать тревогу · How to read an alert

- **«ожидание usage затянулось»**: после сжатия на маршруте Codex три хода прошло без отчёта провайдера. Сжатие DSH заблокировано, от переполнения окна страхует только сам Codex. Проверьте шлюз подписки и сессию агента; когда usage придёт, будет один отбой.
- **"usage wait too long"**: three turns passed after a Codex-route compaction without a provider report. DSH compaction is blocked; only Codex itself protects against window overflow. Check the subscription gateway and the agent session; when usage arrives there will be one all-clear.
- **тревога отметки продолжения** (`held_error`, `lost_on_dispose`, «restart: …»): агент мог остаться посреди задачи без продолжения. Автоматического повтора нет — решение за человеком: посмотреть последнюю сводку и при необходимости дать агенту указание продолжить.
- **continuation marker alert** (`held_error`, `lost_on_dispose`, "restart: …"): the agent may have been left mid-task without continuation. There is no automatic retry — a human decides: look at the latest summary and, if needed, tell the agent to continue.
- **«restart audit unavailable»**: пакет не смог прочитать журнал своей службы — он слеп к потерянным отметкам прошлого запуска. Чаще всего это права: учётке агента нужен доступ к журналу своей службы напрямую или через `sudo -n`.
- **"restart audit unavailable"**: the package could not read its own service journal — it is blind to lost markers of the previous run. Most often this is permissions: the agent account needs access to its own service journal directly or via `sudo -n`.

## Стенды · Stands

Каждый стенд — отдельный исполняемый файл `node stend-<имя>.mjs`. Код выхода: 0 — сошлось, 1 — расхождение (или исключение `assert`), 2 — слепота (предмет или соседний пакет не загрузился). Стенды, загружающие `marker-step.mjs` (`stend-otmetki`, `stend-pisma-prodolzheniya`, `stend-stop-komandy`, `stend-pustogo-audita`, `stend-dostupa-audita`, `stend-nastrojki-i-rezolva`), требуют установки платформы рядом: без `@deepseek-ai/dsh-llm` — слепота, код 2. Стенды не ходят в сеть и не тратят денег: провайдеры, каналы тревог и внешние команды подменены, кроме оговорённых случаев.

Each stand is a separate executable `node stend-<name>.mjs`. Exit code: 0 — passed, 1 — mismatch (or an `assert` exception), 2 — blindness (the subject or a sibling package did not load). Stands loading `marker-step.mjs` (`stend-otmetki`, `stend-pisma-prodolzheniya`, `stend-stop-komandy`, `stend-pustogo-audita`, `stend-dostupa-audita`, `stend-nastrojki-i-rezolva`) need a platform installation next to them: without `@deepseek-ai/dsh-llm` — blindness, exit 2. Stands do not use the network and cost nothing: providers, alert channels and external commands are replaced, except where stated.

### Окружение стендов · Stand environment

Стенды ждут соседства пакетов в общем `node_modules`: рядом должны лежать `dsh-pamyat-kompakt`, `dsh-pamyat-core`, `dsh-pamyat-restore` и `@deepseek-ai/*`. Стенды, которым нужен движок платформы, берут его только из установки, указанной в `DSH_TEST_APP`; не задана — СЛЕПОТА стенда, код 2 (прежде у семи стендов в коде был прибит путь к установке одного из агентов). `stend-pustogo-audita` читает настоящий журнал systemd и требует права на это; `stend-sostava` вызывает `npm pack`. `stend-svezhego-usage` без соседа `dsh-pamyat-core` — названная СЛЕПОТА стенда, код 2, а не трассировка `ERR_MODULE_NOT_FOUND`.

Stands expect package neighbourhood in a shared `node_modules`: `dsh-pamyat-kompakt`, `dsh-pamyat-core`, `dsh-pamyat-restore` and `@deepseek-ai/*` must be next to the package. Stands that need the platform engine take it only from the installation in `DSH_TEST_APP`; unset — stand BLINDNESS, exit 2 (previously seven stands hard-coded a path to one agent's installation). `stend-pustogo-audita` reads the real systemd journal and needs permission for that; `stend-sostava` runs `npm pack`. `stend-svezhego-usage` without the sibling `dsh-pamyat-core` — a named stand BLINDNESS, exit 2, not an `ERR_MODULE_NOT_FOUND` stack trace.
