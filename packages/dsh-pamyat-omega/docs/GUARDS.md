# Проверки и читатели · Guards and readers

| Защита · Guard | Ловит · Detects | Не ловит · Does not detect | Кто читает/предел · Reader/bound |
|---|---|---|---|
| Проверка адреса/ключа · Endpoint/key validation | Отсутствующий адрес/слэш и пустое значение заданного ключа · Missing endpoint/slash and empty value for a named key | Сетевую доступность до запроса · Network health before a call | Строка подъёма/`dostupna`, конечная проверка · Startup/service, finite check |
| MCP transport timeout | Зависший отдельный запрос · A stalled request | Общий срок всего конвейера · Total pipeline duration | Вызывающий получает udalos=false · Caller receives a refusal |
| Read-back Source | Несовпадение id/начала образца · ID/content-prefix mismatch | Полный текст и его семантическую истинность · Full-text or semantic truth | Ядро и очередь читают состояние · Core/queue consume the state |
| Разделение unknown · Unknown outcome classification | Неизвестную запись после начала запроса · Ambiguous writes after a request starts | Потерянный вызывающий очередь · A missing queue caller | Без-id требует руки; с-id требует чтения · No-ID needs operator, known-ID needs read-back |
| Scope root + degradation | Негодный root/keyword-only · Missing root/degraded search | Неподдержанный будущий формат ответов · Future unsupported response formats | Выдача и модель получают отказ · Retrieval/model receive refusal |
| Доверие ядра · Core trust | Мёртвые знания, нет связи для auto · Dead records and unlinked auto candidates | Незамеченную ложь без события · Undetected falsehood without an event | Превью/пометка или отсев · Annotation or rejection |
| Guest handling | Недоверенный root в общем поиске · Untrusted root in multi-root search | Неверный guest-root реестр · Incorrect guest-root inventory | Рамка данных или отсутствие запроса · Data framing or no query |
| Исключение сессии · Session exclusion | Префикс через метод ядра · Prefix from core method | Отсутствующий метод запрещает запись/выдачу · Missing core method rejects writes/delivery | PAMYAT_POLITIKA_NEDOSTUPNA в stderr · PAMYAT_POLITIKA_NEDOSTUPNA on stderr |
| Регистрация инструмента · Tool registration | Недоступные tools/defineTool · Missing registry/tool factory | Фактическое обращение модели · Actual model use | До 30 проверок по 1 с, затем stderr · At most 30 one-second checks then stderr |

Пакет не создаёт systemd-сторожа или повторную network-запись. Retry-правила управляются локальным ядром и его вызывающим. Registration и присутствие имени в descriptor проверяются отдельно от вызова модели; строка «зарегистрирован» не доказывает выполнение.

The package creates no systemd monitor or repeated network write. Retry policy belongs to the local core and its caller. Registration and descriptor presence are checked separately from model invocation; a registered message does not prove execution.

```sh
npm test
node test/stend-svyazi.mjs
node test/stend-podtverzhdeniya.mjs
node test/stend-vydachi.mjs
```

Стенды используют подставной транспорт и должны запускаться на копии. `0` — зелёное, `1` — расхождение, `2` — слепота. Внешний OMEGA не надо отключать для порчи; подставь отказ транспорта и докажи, что исход unknown отличается от подтверждённого отсутствия.

Stands use fixture transport and should run on a copy. `0` is success, `1` mismatch, and `2` insufficient visibility. Do not disable an external OMEGA service for a mutation check; inject transport refusal and prove that ambiguity differs from confirmed absence.

## Недоступная политика ядра · Unavailable core policy

Нет sessiyaIsklyuchena — отказ до обращения к памяти; следующая исправная проверка снимает отказ. Сам агент продолжает ход. Предупреждение подавляет повтор, но не кеширует запрет.

A missing sessiyaIsklyuchena refuses before memory access; the next healthy check removes the refusal. The agent continues its turn. Warning suppression does not cache the prohibition.

Стенд stend-bez-isklyucheniya проверяет реальные hooks, отсутствие обращения и восстановление. stend-zapisi-bez-politiki отдельно проверяет sohranit с выключенной выдачей. Это не доказательство корректности всех правил ядра.

stend-bez-isklyucheniya checks actual hooks, lack of memory calls and recovery. stend-zapisi-bez-politiki separately checks sohranit with retrieval disabled. This does not prove every core policy rule correct.

Предел запрета: новая запись, автоматическая/ручная/прямая выдача и aktivnye. proverit проверяет доставку ранее известного id и может читать его без политики; он не создаёт запись и не подаёт память агенту.

Scope: new writes, automatic/manual/direct retrieval and aktivnye. proverit may read an already known id to verify earlier delivery without policy; it neither creates a record nor delivers memory to the agent.

SDK-стенд использует DSH_TEST_APP или STEND_APP, уже заданные ночным юнитом; без обеих переменных — слепота, код 2. Принятый отказ отсутствующей политики проверяется новыми ранее принятыми стендами без изменения.

The SDK suite uses DSH_TEST_APP or STEND_APP, already supplied by the nightly unit; with neither variable it reports blindness, exit 2. Previously accepted tests continue checking missing-policy refusal unchanged.
