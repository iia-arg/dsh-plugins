# Проверки, вызывающие и ограничения · Guards, callers and limits

| Проверка · Guard | Что проверяет · Subject | Чего не гарантирует · Limitation | Читатель/предел · Reader/bound |
|---|---|---|---|
| Read availability | Служба, доступность, массив · Service, availability, array | Само отсутствие сводки не доказывает поломку · Missing summary alone is not failure | pre-step stderr / core lookup, конечный вызов · Finite pre-step check |
| Compaction evidence | Успешный end/id/time/scope · Success, id, time, scope | Не семантическую свежесть/истину сводки · Not semantic freshness/truth | .compaction-ok JSON / operator |
| Date/confidence | Измеренный timestamp и численная вера · Measured time/confidence | Произвольный ввод вне ядра, все нечисловые формы · Arbitrary unvalidated input outside core | decide → labels / log counts |
| Trust precedence | Отмена/опровержение/уточнение/подтверждение · Trust events | При unknown-time предшествующая ветка уже verify · Unknown-time branch precedes trust | Model annotations / core history |
| Model-source trust | Две полные helped-подписи kem · Two full helped kem signatures | Независимые #v без протокола ядра/истинность · Independent #v without core protocol/truth | Model instruction / ratings |
| Budget controls | Rank-list и текстовые строки · Ranking / text lines | Строгий cap всего сообщения · Strict whole-message ceiling | Counters/operator |
| Welcome frequency | Process set плюс timestamps · Process set plus disk timestamps | Коррупция/ошибка файла/межпроцессная атомарность · Corruption / write failure / cross-process atomicity | Per-session mark; default 24 h |
| Core exclusion | Метод sessiyaIsklyuchena · Core exclusion method | Нет метода → отказ чтения/подачи · Missing method rejects reading/delivery | PAMYAT_POLITIKA_NEDOSTUPNA в stderr · PAMYAT_POLITIKA_NEDOSTUPNA on stderr |
| Issuance trace | ID секций и касание · IDs and accesses | Durable message commit после возврата · Post-return durable commit | Core DB / session event / operator |

Встроенные проверки вызываются session/event и agent/pre-step. Внешнего systemd-сторожа в пакете нет; оператор должен назначить сборщик stderr и читать причины/счётчики. Один существующий logger не означает, что строку кто-то увидит.

Built-in checks run from session/event and agent/pre-step. The package has no external systemd monitor; assign stderr collection and a reader for reasons/counters. A logger's existence does not establish an observer.

Строка `выдача` сверяет число use + verify + ignore + непоместившихся с исходным перечнем; она не подтверждает успешный ответ модели. Противоречивые пороги веры кричат, но не исправляются автоматически. Все проверки конечные; ожидания автономного цикла/повтора сетевых запросов здесь нет.

The issuance line reconciles use+verify+ignore+non-fitting counts against the input list; it does not confirm a model's successful response. Incompatible thresholds are diagnosed, not repaired. Checks are finite; there is no autonomous polling or network-retry loop here.

```sh
npm test
node test/stend-readme.mjs
node test/stend-kasaniya-podannyh.mjs
node test/stend-sleda-vydachi.mjs
```

Стенды запускай на копии с подставным ядром/сессией. Слепота/code 2 отличается от зелёного; условия соседних модулей и внешнего журнала читай в комментариях выбранного теста. Порча должна меняться именно на проверяемом свойстве, а возврат восстанавливать зелёный результат.

Run stands on a copy with fixture core/session. Blindness/code 2 differs from success; inspect each test's adjacent-module and external-journal prerequisites. Mutations must change the property being tested, and restoration must return to green.

## Недоступная политика ядра · Unavailable core policy

Нет sessiyaIsklyuchena — отказ до обращения к памяти; следующая исправная проверка снимает отказ. Сам агент продолжает ход. Предупреждение подавляет повтор, но не кеширует запрет.

A missing sessiyaIsklyuchena refuses before memory access; the next healthy check removes the refusal. The agent continues its turn. Warning suppression does not cache the prohibition.

Стенд stend-bez-isklyucheniya проверяет реальные hooks, отсутствие обращения и восстановление. Это не доказательство корректности всех правил ядра.

stend-bez-isklyucheniya checks actual hooks, lack of memory calls and recovery. This does not prove every core policy rule correct.
