# dsh-pamyat-secretary

Секретарь компакции: снимает знание с того, что вот-вот станет недостижимым.

## Зачем

Компакция заменяет кусок истории одной сводкой — затёртое агенту больше не
видно. Среди затёртого бывают решения владельца, ограничения и обещания.
Секретарь ловит событие сводки и кладёт её в память **с verbatim-ссылкой** на
затенённый диапазон, чтобы знание можно было потом проверить по журналу сессии,
а не верить ему на слово.

Пакет **наполняет** память. Пока его нет, слои чтения показывают пустоту —
и эту пустоту легко принять за работающую память.

## Шов: события сессии, а не отдельные хуки

По типам платформы (`dsh-compaction`, `SessionEventMap`) события
`compaction/start|summary|end` приходят как события **сессии**. План описывал их
как самостоятельные хуки — неточность пересказа, проверено чтением `.d.ts`.
Подписка идёт на `session/event` с отбором по типу.

🔴 **`inject` обязателен.** На боевом контексте (плагин под runtime) чтение
`ctx.<служба>` без объявления в `inject` **бросает**: `cannot get property "X"
without inject`. На голом контексте — молча отдаёт пустоту, поэтому проба,
поставленная на корневом Context, зелена по неверной причине.

## Что записывается

| поле | откуда |
|---|---|
| содержимое | `summary` события, только текстовые блоки |
| ссылка на источник | `<сессия>#<первый>-<последний>` из `shadowedSeqs` |

Событие **отвергается**, если в нём нет текста сводки или нет номеров
затенённых записей. Довод: знание без ссылки на источник непроверяемо, а
непроверяемому знанию цена ниже, чем его отсутствию. Пустая строка вместо
знания — худший исход: пустое знание неотличимо от отсутствующего.

## Что пакет НЕ делает

* **не пишет в сессию** — только читает события и берёт идентификатор сессии;
* не делает своей компакции и не трогает штатную;
* не дистиллирует отдельной моделью: кладёт готовую сводку платформы, потому что
  она уже написана и второй раз платить за неё незачем.

## Вывод сообщений

Пакет пишет в **обычный поток**, а не в службу логгера. Причина замерена:
`ctx.logger` у платформы есть и без `inject`, вызов `.error` проходит без ошибки,
но сообщение **не появляется** в стандартном потоке — у службы свой транспорт.
То есть «доложил» и «услышали» расходятся молча. У службы stdout попадает в
системный журнал, так что ничего не теряется.

## Настройка

| ключ | умолчание | смысл |
|---|---|---|
| `klass` | `svodka-kompakcii` | класс, которым записывается сводка |
| `vklyuchen` | `true` | выключение — законное состояние, но ГРОМКОЕ |

## Проверка

    npm test

Три стенда, 17 проб. Стенд шва работает на **настоящем** Context платформы
(cordis версии стенда, не из реестра): заглушка слепа к запретам платформы —
она отдаёт любую службу и не знает про `inject`.

Подписка считается рабочей **только по полученному событию**, а не по факту
подписки без ошибки.

## Посылки

**Доказан МЕХАНИЗМ:** подписка получает событие, разбор снимает знание, запись
уходит в память; исключение внутри обработчика не рвёт поток событий других
подписчиков; выключение и пропуск объявляются вслух.

🔴 **СОДЕРЖАНИЕ не доказано.** Живой компакции на стенде не было: все события
собраны по типам платформы. Что настоящее событие имеет ровно такую форму —
принято по `.d.ts`, а не по наблюдению.

## Границы

* Ссылка на источник указывает диапазон, а не подтверждает, что по нему что-то
  найдётся: журнал сессии живёт своей жизнью и может быть усечён.
* Пакет ничего не пишет в сессию, поэтому проверка «переживёт ли перезагрузку
  сессии» к нему не относится; для базы памяти её выполняет ядро.
