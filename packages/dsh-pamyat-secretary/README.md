# dsh-pamyat-secretary

Секретарь компакции: снимает знание с того, что вот-вот станет недостижимым.

## Зачем

Компакция заменяет кусок истории одной сводкой — затёртое агенту больше не
видно. Среди затёртого бывают решения владельца, ограничения и обещания.
Секретарь ловит событие сводки и кладёт её в память **с verbatim-ссылкой** на
затенённый диапазон, чтобы знание можно было потом проверить по журналу сессии,
а не верить ему на слово.

Пакет **наполняет** память. Пока его нет, слои чтения показывают пустоту —
и эту пустоту легко принять за работающую память.

## Шов: события сессии, а не отдельные хуки

По типам платформы (`dsh-compaction`, `SessionEventMap`) события
`compaction/start|summary|end` приходят как события **сессии**. План описывал их
как самостоятельные хуки — неточность пересказа, проверено чтением `.d.ts`.
Подписка идёт на `session/event` с отбором по типу.

🔴 **`inject` обязателен.** На боевом контексте (плагин под runtime) чтение
`ctx.<служба>` без объявления в `inject` **бросает**: `cannot get property "X"
without inject`. На голом контексте — молча отдаёт пустоту, поэтому проба,
поставленная на корневом Context, зелена по неверной причине.

## Что записывается

| поле | откуда |
|---|---|
| содержимое | `summary` события, только текстовые блоки |
| ссылка на источник | `<сессия>#<первый>-<последний>` из `shadowedSeqs` |

Событие **отвергается**, если в нём нет текста сводки или нет номеров
затенённых записей. Довод: знание без ссылки на источник непроверяемо, а
непроверяемому знанию цена ниже, чем его отсутствию. Пустая строка вместо
знания — худший исход: пустое знание неотличимо от отсутствующего.

## Что пакет НЕ делает

* **не пишет в сессию** — только читает события и берёт идентификатор сессии;
* не делает своей компакции и не трогает штатную;
* не дистиллирует отдельной моделью: кладёт готовую сводку платформы, потому что
  она уже написана и второй раз платить за неё незачем.

## Вывод сообщений

Пакет пишет в **обычный поток**, а не в службу логгера. Причина замерена:
`ctx.logger` у платформы есть и без `inject`, вызов `.error` проходит без ошибки,
но сообщение **не появляется** в стандартном потоке — у службы свой транспорт.
То есть «доложил» и «услышали» расходятся молча. У службы stdout попадает в
системный журнал, так что ничего не теряется.

## Дистилляция знаний (выключена по умолчанию)

Штатная сводка компакции — **оперативная** запись: она кладётся как есть и остаётся
локально. Дистилляция — другая работа: с того же затенённого среза дешёвая модель
снимает **знания** (решения, уроки, ограничения, ошибки, порядок, наблюдения, факты)
и пишет каждое отдельной записью своего класса. Одно другого не заменяет.

Две ступени, а не одна: сперва выбор тем, потом статья на каждую. Слитая выдача даёт
«дайджест дня» вместо знаний — решение, урок и порядок действий по одному предмету
это три разных знания.

🔴 **Выключено по умолчанию**, потому что механизм ходит к платному чужому API.
Включённый молча у получателя, он тратил бы его деньги без спроса.

🔴 **Ключ никогда не идёт аргументом команды**: argv виден в `/proc` любому на машине.
Источника два, оба без argv — файл с правами 0600 или запись `pass`.

**Затенённый срез берётся из события, а не вычисляется.** `compaction/summary.data`
несёт `shadowedSeqs` — точный список записей — и `shadowedTokenCount`. Вычисленная по
времени граница расходится с настоящей молча.

### Что здесь измерено, а не предположено

| замер 03.09.2026 | число |
|---|---|
| журнал сессии многокадровый; `zstdDecompressSync` на всём файле | **126 байт из 27 922 455**, без ошибки |
| разбор по кадрам вручную | 27 922 455 байт, сошлось с `zstd -dc` байт в байт |
| затенённый срез настоящего компакта | 67 записей из 67, 43 790 токенов, 168 361 знак |
| ступень «выбор тем» при бюджете 8000 | `stop_reason: max_tokens`, блока text НЕТ |
| она же при 32000 | 9 тем, 72 с, вход 57 631 токен |
| одна статья | 18 с, 1027 знаков при пределе 1000 |

🔴 Первая строка — грабля, стоящая отдельного слова: штатная распаковка отдаёт
огрызок и **не сообщает об этом**. 126 байт вместо 27 мегабайт выглядят как короткий
журнал, а не как отказ. Потоковый разжиматель хотя бы кричит «Unknown frame
descriptor»; синхронный молчит.

### Отказ называет причину

«Нечего извлекать» и «не смогла дочитать» — разные новости, и подавать их одинаково
нельзя. Исходы разведены машинно:

| исход | когда |
|---|---|
| `ok` | пришёл блок `type: text` |
| `ne-dochitala` | блока text нет И `stop_reason: max_tokens` — бюджет кончился на рассуждении |
| `pusto` | блока text нет при ином `stop_reason` — он называется дословно, причина не выдумывается |
| `ne-sprosili` | сеть, таймаут, HTTP не 2xx — вызов не состоялся |

Пустота по существу — точная строка `НЕТ РЕЛЕВАНТНОГО`, а не короткий ответ: без
машинного признака пустой ответ неотличим от сбоя вызова.


### Повтор захода по одному срезу не делается

Пакет монтируется в одном процессе **несколько раз** (замер 04.09.2026: трижды на одном
узле, дважды на другом — записи журнала различны по монотонному времени, то есть это разные
вызовы, а не дубль показа). Обработка события пока одинарная, но **почему — не установлено**:
защита держится на неизвестном нам свойстве платформы.

Механизм ходит к платному API, поэтому удвоение обнаружилось бы по счёту за месяц. Заход
считается по срезу; повторный по тому же диапазону **не делается** и называет себя:

    🔴 заход по срезу <сессия>#<от>-<до> УЖЕ БЫЛ (это 2-й): пакет смонтирован несколько раз…

⚠️ Это **не лечение причины**. Счёт видит удвоение НАШЕГО вызова и не увидит удвоения записей
в память, если оно пойдёт другим путём, — разные беды одного корня. Счёт живёт в памяти
процесса: перезапуск обнуляет его, и это верно — после перезапуска тот же срез не придёт.

## Проверка

    npm test

Пять стендов, 45 проб. Стенд шва работает на **настоящем** Context платформы
(cordis версии стенда, не из реестра): заглушка слепа к запретам платформы —
она отдаёт любую службу и не знает про `inject`.

Подписка считается рабочей **только по полученному событию**, а не по факту
подписки без ошибки.

## Посылки

**Доказан МЕХАНИЗМ:** подписка получает событие, разбор снимает знание, запись
уходит в память; исключение внутри обработчика не рвёт поток событий других
подписчиков; выключение и пропуск объявляются вслух.

🔴 **СОДЕРЖАНИЕ не доказано.** Живой компакции на стенде не было: все события
собраны по типам платформы. Что настоящее событие имеет ровно такую форму —
принято по `.d.ts`, а не по наблюдению.

## Границы

* Ссылка на источник указывает диапазон, а не подтверждает, что по нему что-то
  найдётся: журнал сессии живёт своей жизнью и может быть усечён.
* Пакет ничего не пишет в сессию, поэтому проверка «переживёт ли перезагрузку
  сессии» к нему не относится; для базы памяти её выполняет ядро.
