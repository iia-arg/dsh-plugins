Пакет не устанавливает внешнего systemd-сторожа непрочитанных заданий. Назначь читателя `putOtklonennyh` и stdout/stderr в своей установке; `komandaTrevogi` — выбранная команда, а не доказанный канал доставки. Код проверяет её завершение, но подтверждение чтения оператором требует отдельного механизма.

The package installs no external systemd monitor for unread tasks. Assign readers for `putOtklonennyh` and stdout/stderr; `komandaTrevogi` selects a command rather than proving delivery. The code checks command completion, but operator receipt needs a separate mechanism.

Readiness и startup probe ключа не должны считаться гарантией будущих API-вызовов. Отозванный ключ, другая роль, баланс или сеть изменяются после загрузки; каждый вызов возвращает собственный исход. Каталог с сохранённой прозой содержит производные разговорные данные и требует той же защиты, что журнал сессии.

Key readiness/startup probes do not guarantee future API calls. Revoked keys, roles, balance and networking can change after startup; each call has its own result. Saved prose is derived conversation data and needs protection comparable to session logs.

```sh
npm test
node test/stend-readme.mjs
node test/stend-flaga-distillyacii.mjs
node test/stend-hodovogo-zova.mjs
```

Перед запуском выбранного стенда прочти его предусловия. Подставные API и базы отделяют исправное, внесённый сбой и возврат; внешнюю платную модель ради порчи не зови. `0/1/2` означают зелёное/расхождение/слепоту, а код всей оболочки без списка реально выполненных файлов недостаточен.

Read stand prerequisites before running it. Fixture APIs and databases separate healthy, injected failure and restoration; do not invoke a paid model just to test a mutation. `0/1/2` mean success/mismatch/insufficient visibility, and the shell result alone is insufficient without the executed file list.

## Новые пробы · Added tests

stend-bezopasnosti-shova проверяет настоящие HTTP-запросы и SQLite: оба суда, отказ маски, обрыв и нулевой бюджет. stend-vody-otkaza проверяет первичную воду, её порчу/возврат и отказ rename/write. Маска знает только свои классы секретов, не произвольные способы скрыть секрет; guard не подтверждает истинность вердикта модели. Эти проверки запускает полный пакетный обход, результат читает приёмщик.

stend-bezopasnosti-shova checks actual HTTP requests and SQLite: both judgments, mask refusal, truncation and zero budget. stend-vody-otkaza checks primary watermark corruption/recovery and rename/write failure. The mask recognizes its own secret classes, not arbitrary obfuscation; the guard does not establish model verdict truth. The full package suite invokes these tests and the reviewer reads their results.

SDK-путь stend-distill-srez передаётся DSH_TEST_APP либо STEND_APP. При отсутствии путь неизвестен, результат 2; боевой ночной юнит уже задаёт оба ключа, новых pluginConfig не нужно.

DSH_TEST_APP or STEND_APP supplies the stend-distill-srez SDK path. Without either path, the subject is unknown, result 2; the production nightly unit already supplies both keys and needs no new pluginConfig.
