The cause is now told apart by the head of the SYSTEM journal (`journalctl --system -n +1`): not obtained — "the journal is unreadable"; head later than the window — "the journal is shorter than the start", with both dates; otherwise — "the service does not print Started?". Exit codes unchanged: 2 (or 1 when a divergence was already found). No `| head`: units run with `IgnoreSIGPIPE=yes`, and journalctl behind `head` kept reading until the deadline (probe: 120 s, code 124). The "does not print Started" branch is not probed — nothing to stand in for it.

## 3.1.2 — 2026-10-14 · B-N-2048 · npm-sostav — разбор вывода npm одним правилом для npm 11 и 12 · one parsing rule for npm 11 and 12

- Новый прибор `bin/npm-sostav` (бой `/usr/local/bin/npm-sostav`, `0755 root:root`): только разбор stdin, npm не зовёт. `--files` — пути `files[].path` по строке, `--filename` — имя архива, `--view` — объект `npm view … --json` одной строкой. Правило одно с записями реестра (Альфа + ступень против пустого, решение Забавы 14.10): вход целиком и ровно один JSON-документ; массив из 1 или объект из 1 ключа без `error`; `files` — массив. Иначе ОТКАЗ, код `2`, stdout пуст, причина называет тип, длину и ключи. Повод: успех `npm pack --json` в npm 11 — массив, в 12 — объект с ключом-именем; `npm view --json` наоборот.
- Новый стенд `test/stend-npm-sostav.py` с фикстурами `test/fiks-npm-sostav/` (17 файлов; формы сняты npm 11.17.0 и 12.2.0): 30 проб против разбора Python без jq, канарейка на число проб. Режим `--reestr ФАЙЛ [ID…]` гоняет jq-строку из записей реестра (и внутри `sudo bash -c`) на тех же фикстурах и сверяет исход с помощником — одно правило держится одним набором входов.
- Ворота Вениамина 14.10 (LOW, приняты Забавой до монтажа): `--files` отказывает на элементе `files` без строкового `path` (прежде печатал `null`) — тем же текстом, что встраивается в записи реестра; `--help` пишет справку в stderr и выходит с кодом `2`, чтобы в конвейере не стать «путём» или тихим нулём. Пустой `files` — 0 строк при коде `0`, принято как есть. · Gate LOWs: `--files` refuses a `files` element without a string `path` (previously printed `null`), same text as in registry entries; `--help` writes to stderr with code `2`. An empty `files` stays 0 lines with code `0`.
- New tool `bin/npm-sostav` (production `/usr/local/bin/npm-sostav`, `0755 root:root`): parses stdin only and never calls npm. `--files` — `files[].path` one per line, `--filename` — the archive name, `--view` — the `npm view … --json` object on one line. One rule shared with registry entries: the whole input must be exactly one JSON document; an array of 1 or an object of 1 key without `error`; `files` must be an array. Otherwise a REFUSAL, code `2`, empty stdout, the reason names type, length and keys. Why: a successful `npm pack --json` is an array in npm 11 and an object keyed by name in npm 12; `npm view --json` is the other way round.
- New stand `test/stend-npm-sostav.py` with fixtures `test/fiks-npm-sostav/` (17 files; shapes captured with npm 11.17.0 and 12.2.0): 30 probes against a Python parse without jq, a probe-count canary. `--reestr FILE [ID…]` runs the jq string from registry entries (also inside `sudo bash -c`) on the same fixtures and compares the outcome with the helper.
