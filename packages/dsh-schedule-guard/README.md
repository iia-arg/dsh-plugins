# dsh-schedule-guard 3.1.3 — сторож расписания

English: [README.en.md](README.en.md). Поддерживаемая линия платформы — DSH **0.2.0-rc.2**, служба `schedule`; линия 0.1 с выпуска 0.6.0 не поддерживается. Текущий свой прогон: Node 24.19.0, Cordis 4.0.4, schemastery 3.18.4. Номер 0.6.4 → 3.1.1 намеренный по правилу владельца 10.10; это не публикация в npm.

Плагин ограничивает кооперативные самопробуждения и сообщает о них владельцу. Он не останавливает уже начавшийся ход модели, не управляет целями или фоновыми заданиями и не является границей безопасности от агента с полными правами.

## Граница Петровича

Слово владельца **30.09 02:26 «Б»**: расписание Петровича **без предела**, его не выключать и предел не навязывать. Не включать сторож для этого профиля. Если сторож уже указан, настройка **именно dsh-schedule-guard**:

```yaml
- insert:
    - name: '@deepseek-ai/dsh-schedule'
      id: schedule
    - name: dsh-schedule-guard
      config:
        enabled: false
        limitOneShotWakeups: false
```

`enabled: false` оставляет плагин расписания включённым: сторож не ставит хуки, не удаляет напоминания, не регистрирует `heartbeat_close`. Новый предел одноразовых `limitOneShotWakeups` по умолчанию **false** и включается только для отдельно выбранных ограниченных профилей. Сам этот пакет не переписывает профили Петровича или других агентов.

## Зависимости и установка

Нужны `@deepseek-ai/dsh-schedule` и `@deepseek-ai/dsh-tools` линии 0.2.0-rc.2, schemastery; сервисы `agents`, `sessions`, `tools`, `schedule` должны быть видны в одной области Cordis. Профиль должен включать `@deepseek-ai/dsh-schedule`: установка файла npm сама службу не включает. На этой линии доступны четыре инструмента: `schedule_create`, `schedule_list`, `schedule_delete`, `schedule_update`; собственный минимум платформы для every — **60 с**, а 1800 с ниже — дополнительная настройка сторожа.

`inject` требует все четыре службы. Без `schedule` Cordis держит плагин неактивным, **apply не вызывается**, строка подъёма сторожа не появляется. Импорт модуля без разрешимой библиотеки и отсутствие активной службы — разные случаи. Проверять надо состав профиля и службы, а не ждать обещанной «одной громкой строки». Живую пересборку выполняет назначенная рука окна.

Локальный артефакт из выбранного дерева:

```bash
cd "$GUARD_SOURCE"
npm pack --ignore-scripts --pack-destination "$ARTIFACTS"
# Для pnpm-профиля — локальный архив, а не голое имя из registry:
cd "$PROFILE_DIR"
pnpm add /absolute/path/dsh-schedule-guard-3.1.3.tgz
```

Пакет выходит в npm под именем `dsh-schedule-guard`; до выхода — локальный проверенный архив. Проверить версию, SHA архива и импорт `src/index.js`, затем включить профиль со своими настройками. `dsh --dump-config` переписывает `cordis.yml`, это не read-only проверка. После изменения runtime необходим перезапуск движка; собственных служб/systemd unit у пакета нет.

## Настройки

| Ключ | Умолчание | Договор |
|---|---|---|
| enabled | true | false полностью отключает сторож, оставляя расписание платформы |
| limitOneShotWakeups | false | opt-in: streak/day admission и гашение одноразовых при этих пределах |
| maxConsecutiveWakeups | 6 | admission при >=6 только с opt-in; idle при >6 снимает повторы, с opt-in — все виды |
| maxPerDay | 48 | аналогично за календарные сутки, не скользящие24ч |
| maxPerHour | 4 | admission в скользящем часе; maxPerHour <= 0 выключает только этот потолок |
| minRepeatingIntervalSeconds | 1800 | минимум every для сторожа, не значение платформы |
| resetKinds | [user, a2a] | user/message этих источников обнуляет полосу; пустой массив означает умолчание |
| dayBoundaryOffsetMinutes | 0 | UTC;180 означает UTC+3 |
| notifyCmd | unset | доверенный исполняемый файл; сообщение идёт в stdin, shell не используется |
| notifyTimeoutSeconds | 90 | notifyTimeoutSeconds <= 0 подменяется90; таймаут SIGKILL только прямому потомку |

Счёт: user/message с source.kind schedule на0.2 и старый schedule/change dispatch на0.1. Человек/a2a не считаются schedule dispatch. Порог часа и новый opt-in работают на родном `tools/execute`; вызов тела инструмента мимо реестра ими не закрывается, его догоняет обработчик простоя.

## Отказы, обновление и простой

| Код | Причина |
|---|---|
| SCHEDULE_TOO_FREQUENT | every_seconds меньше настроенного минимума |
| SCHEDULE_HOURLY_CAP | часовой бюджет исчерпан |
| SCHEDULE_CRON_NOT_ALLOWED | cron задан на родном create/update; уже стоящий cron считается нарушителем шага |
| SCHEDULE_SOURCE_UNAVAILABLE | при требуемом admission журнал сессии нечитаем |
| SCHEDULE_STREAK_CAP | opt-in и полоса достигла maxConsecutiveWakeups |
| SCHEDULE_DAILY_CAP | opt-in и сутки достигли maxPerDay |

Без изменения времени `schedule_update` может исправлять текст даже при полном бюджете. Удлинение существующего every разрешается, если оно не сокращает прежний интервал и не переносит исходную цель раньше; сокращение и непроверяемая смена вида остаются ограниченными. Платформа всё равно проверяет id, аргументы и принадлежность задачи.

На idle нарушение шага снимает только слишком частые/cron повторы. Полоса/сутки снимают все повторы; с `limitOneShotWakeups:true` — и одноразовые. Одновременные причины перечисляются вместе. Если ничего не снято, это **не подтверждение остановки**; сообщение не говорит «остановился». Одно неизменившееся состояние не дублируется в stderr. Отказавший канал пробуется снова на следующем idle с сохранённым исходным сообщением; успешный канал уведомляется один раз на эпизод. Зависший канал не повторяется до снятия превышения.

Нечитаемый журнал: активный сторож снимает **все активные** напоминания этой сессии, включая одноразовые, поскольку пределы не вычислить. Отключённый сторож этого не делает. Проверяется одна асинхронная sweep на агента; latch снимается в finally. Backend list/delete собственного deadline здесь не имеют: зависший backend удерживает sweep, это не доказательство успешного удаления.

## След, приватность и heartbeat_close

До удаления полная запись дописывается в `<DSH_HOME>/schedule-guard-snyatye.jsonl`, затем fsync. При создании файл0600; существующие права не ужесточаются автоматически. Файл без ротации и лимита размера — файл хранит **полный текст** prompt/title, место и доступ проверяет оператор. DSH_HOME не задан — используется os.homedir()/.dsh. Записать не удалось: **НЕ снимаю** задачи, предупреждение владельцу; память для пересоздания не заменяется догадкой.

В stderr попадают причины/числа, id и длины prompt/title (кодовые точки), а не полный текст напоминаний или summary. Полный текст остаётся в приватном файле и письме владельцу. Уже стоящий файл с чужими правами, злонамеренная подмена и агент с полными правами не становятся безопасными от этой поведенческой защиты.

На0.2 delete идёт через службу schedule: подтверждение `{deleted:true}`, строка stderr и JSONL — след; событие schedule/change delete не обещается. Через session.append удаляются **только старые** записи0.1. Offset унаследованного префикса передаётся foldScheduleEvents; чужой префикс не превращается в своё расписание.

`heartbeat_close` — необязательный инструмент каждого наблюдаемого корневого агента: summary в одно-два предложения, результат `{ok,chisla,otpravleno}`. Он отправляет резюме и числа, не удаляет задачи и не обнуляет события; внешнее слово меняет счёт, автоматического резюме по нему нет. Родная регистрация/исполнение проверяются отдельным стендом на настоящем ToolRuntime.

Подписки принадлежат plugin scope и снимаются при teardown; ожидание list после teardown не должно начинать запись/удаление. Уже начавшийся delete сервисом не отменяется; отключение не восстанавливает ранее удалённые задачи. Для восстановления нужен архив и новый create самого агента.

## Журнал и стенды

Код пишет по-русски. Пример тегов (значения и `(настройка)/(умолчание)` снимаются при старте):

```text
schedule-guard [подъём]: пределы: enabled=true, limitOneShotWakeups=false, maxConsecutiveWakeups=6, maxPerDay=48, minRepeatingIntervalSeconds=1800, maxPerHour=4, resetKinds=user,a2a, dayBoundaryOffsetMinutes=0, notifyTimeoutSeconds=90, notifyCmd=unset (log only)
```

Это схема полей, а не verbatim строка конкретного процесса. Строка содержит каждый ключ и происхождение значения. На остановке лог называет факт `снято N`; одного наличия слова «предел» недостаточно для доказательства удаления.

`npm test` запускает **только test-preemptive-refusal.mjs**: 13 именованных проб плюс assert-проверки описания/render/execute настоящим defineTool. Нужен dsh-tools; не загружается — **СЛЕПОТА 2**, не rc1. Код0 — проверки прошли,1 — расхождение,2 — проверить нечем.
