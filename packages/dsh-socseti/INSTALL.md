# Установка dsh-socseti

Пакет — исходник Node-приложения. Подготовленный runtime отличается от npm/git-архива: он также содержит зависимости из закреплённого package-lock.json. Собирают runtime на копии вне рабочих /opt/socseti и /opt/socseti-anna, затем монтируют принятый состав. На бою npm не запускают.

Полный исходный архив Git/source.tar.gz содержит package-lock.json. npm pack исключает lockfile по своему договору, поэтому npm tarball отдельно не является основанием для воспроизводимого npm ci. Для сборки брать полную исходную копию из передачи или Git.

## Подготовка копии

Нужны Node24+, npm, Python3 и sudo -n для root-owned настройки тестовых фикстур. Команды каталога сборки:

```sh
npm ci --ignore-scripts
npm test
```

Тесты создают синтетические ключи/owner/settings и SQLite в /tmp. SOCSETI_WATCH_SOURCE необязателен: соседний сторож находится в дереве автоматически; без него пропускаются только именованные внешние подпробы сторожа и канала dsh-telegram-multiagent. После проверки в runtime переносят src, manifest, lockfile и подготовленный node_modules. Полный состав исходника — PAKET.md. Тестовые ключи и базы не переносят.

## Две установки

| профиль | runtime | шаблон unit | конфигурация | состояние/рука из шаблона |
|---|---|---|---|---|
| Варвара, поле profile отсутствует | /opt/socseti | systemd/socseti.service | /etc/socseti/config.json | /var/lib/socseti; socseti |
| Анна, profile=anna | /opt/socseti-anna | systemd/socseti-anna.service | /opt/anna/.config/socseti/config.json | /var/lib/socseti-anna; anna |

Обе копии получают один принятый пакет; конфигурации, ключи, SQLite/WAL и зависимости не берутся из другой установки. Обновление приложения не включает дополнительные площадки. У Анны выключенный писатель — отсутствие vk.writer; enabled=false внутри него отвергается. Не добавлять writer при монтаже аудиторской правки.

Шаблон Варвары требует /usr/local/bin/node и обязательный read-only bind /opt/nodejs. Для другого расположения Node назначенная рука готовит и проверяет собственный unit. Шаблон Анны — Type=simple; не переносить в него notify/flock/namespace Варвары автоматически. Файл ExecStart не запускают как проверочный прибор: используют подставу и проверку копии unit.

## Настройка и монтаж назначенной рукой

1. До замены сохранить суммы и страховки runtime, настройки и unit, права и прежние ref/версию; сохранить SQLite/WAL/SHM согласованным способом. Данные после публикации не заменять старым снимком при откате.
2. Подготовить учётку, свой stateDir0700 и приватные конфигурацию/ключи. Читаемый файл принадлежит root или учётке службы, без execute/групповой записи/прав остальным, symlink/hardlink. Серверные ключи — разные64hex, не в argv/журнале. Каталог и БД также проходят проверку своего владельца и точных прав.
3. Для новой Варвары есть deployment/provision-keys.py. Его запускает root с именами каталога и service-user; каталог уже имеет точные owner/group/mode. Повтор сохраняет существующие ключи. Этот скрипт не создаёт комплект anna/monitor/channel; у Анны его и token/pass references готовит её монтажная рука.
4. Сохранить действующие owner/approvers и приватные ключи. etc/socseti/approvers.json.example — пустой пример, не список боя. Схема config — REFERENCE.md. Писатели ВК включаются отдельным явным решением по профильным документам.
5. Смонтировать весь принятый состав штатным проверяльщиком: .new рядом → mv. Отдельно сверить суммы, режимы/владельцев и учёт пакета. Затем systemd-analyze verify и daemon-reload назначенной рукой. Живой start/restart — отдельный шаг её окна после ворот.
6. При живой приёмке сопоставить manifest.version с новой строкой журнала живого PID и MCP initialize; status читает monitor. Type=notify Варвары посылает READY короткоживущим systemd-notify после bind и попытки preflight, NotifyAccess=all. Гипотеза потери датаграммы не воспроизведена автором аудита; verify unit не доказывает READY живого процесса.

## Внешняя интеграция

Реестр машины, профиль агента, EnvironmentFile клиентского ключа и channel/poller не входят в этот npm-пакет. Старые пути integration/* и varvara.service.d/98-socseti.conf здесь не поставляются и не являются исполнимыми шагами установки. Назначенная рука строит профиль и запись реестра штатными инструментами своей машины со свежей основой. Снимок чужого agents.yaml не заменяет живой реестр. Модель не получает monitor/channel/Telegram/VK токены.

Пилот Варвары — PILOT.md, её тестовые цели и port8381. Для Анны отдельно проверяют /channel, владельца polling, приём и разрешённые писатели. npm test и подставной процесс не доказывают доставку на настоящую площадку.

## Откат

Назначенная рука возвращает прежний runtime и совместимую настройку пакетным составом со сверкой cmp/сумм. Состояние отправок, approvals, receipts, offsets и unknown сохраняется. Прежнее приложение должно понимать нынешнюю схему SQLite1/2/3. Старую БД поверх новой после отправки не накатывают, unknown не очищают ради повтора. Для выключения — mask штатным способом, не только disable; unit и состояние сохраняются в страховке. Уже отправленное автоматически не удаляют.

Миграционные пробы прежней очереди используют закреплённую SHA-фикстуру test/fixtures/telegram-queue-r1.mjs, без git show. Межпакетные проверки канала Анны требуют соседнего dsh-telegram-multiagent; в самостоятельном архиве они дают именованные пропуски. Проверка восстановления владельца самого worker выполняется и без этого соседа.
