# Живой пилот профиля Варвары — только назначенная рука после ворот

Предусловие: внешний зелёный Вениамина, монтаж единым окном, конфигурация только
с тестовыми IDs. По подписанному замеру Забавы 15:04:29Z Анфиса administrator
в группе -1004416192741 и канале -1004451262289; can_post_messages=true.
Автор эти факты сетевым вызовом не перепроверял — токен кладёт Забава при монтаже.
Боевые группа/канал запрещены, VK/IG/Threads вне такта.

Пилотный `test/live-pilot.mjs` жёстко использует port=8381. До вызова сверить этот порт с конфигурацией; иной порт требует отдельного клиента, не молчаливого повторения. Этот пилот не проверяет профиль Анны и её доставку/писатели ВК.

Ожидания ДО запуска: ровно одна карточка, одно человеческое решение, один пост
с message_id на стороне test channel. Повтор callback и restart не добавляют пост.

1. От Варвары в её проверенном каталоге вызвать draft_post:
   platform=telegram, request_id=уникальная строка минимум8знаков, text=короткая
   явно тестовая реплика. Убедиться, что MCP вернул published=false, draft_id/version;
   токен draft не копировать в отчёт. Альтернативный независимый клиент:

   systemd-run --wait --pipe --collect -p User=varvara -p EnvironmentFile=/etc/socseti/varvara-mcp.env /usr/local/bin/node /opt/socseti/test/live-pilot.mjs <request_id>

   Запуск root через systemd, процесс под varvara; это только создание черновика, не подмена вызова модели.
   Фактический каталог Варвары и журнал шлюза всё равно проверяются отдельно.
2. В test approval group увидеть карточку именно этой версии/текста и две кнопки.
   Получить inline «Опубликовать» от владельца из /etc/vladelec/telegram-id, ID из /etc/socseti/approvers.json.
   Координатор не подменяет actor в локальной БД; человек нажимает реальную кнопку.
3. Проверить на стороне тестового канала ровно один пост/полный текст; записать
   channel message_id. В приватной БД root сверяет draft state=published и
   tg_actions publication result_json.message_id, не печатая payload/capabilities.
4. Нажать ту же кнопку ещё раз, повторить тот же request_id и перезапустить
   socseti штатно. Ещё одного поста/карточки быть не должно; offset сохранён.
5. Второй тестовый draft отклонить allowlisted человеком. В канале новых постов
   нет, draft=rejected. Третий — изменить через revise_draft до одобрения:
   старая кнопка не публикует, новая публикует только новую версию.
6. Записать имена проверок, UTC, account/chat IDs и message IDs без секретов.
   При неверном target/неожиданном повторе/unknown немедленно остановить worker;
   ничего не повторять автоматически. Unknown сверяет человек, штатного
   разрешающего CLI в этом выпуске нет. Не редактировать SQL, чтобы "попробовать ещё".

Порчи низкоуровневых callback/CAS/timeout безопасно проверены на подставе.
Не делать сетевую порчу в боевом канале и не передавать бот-токен в argv.
Пилот не проверяет отдельную доставку/писатели Анны, VK/IG/Threads и остальные каналы. Старый этапный протокол не является универсальной приёмкой всего пакета.
