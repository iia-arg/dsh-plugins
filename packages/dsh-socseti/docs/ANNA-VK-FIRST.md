# B-N-2027, первая часть: приёмник ВК Анны

Версия пакета — manifest (3.1.8). Прежние номера кандидатов и протоколы ниже — история этого участка; старые замеры не являются нынешней живой приёмкой. Общий текущий договор очереди, эхо, настройки и статуса — [REFERENCE](../REFERENCE.md).

Кандидат `1.3.0-b2027-vk1`. Основание — подписанное письмо Забавы
18:12:39Z 13.10.2026. Idle Острова с11:35:20Z принят по её замеру.
Код и стенды Беты находятся на sadik; состояние aclaude Бета не меняет.

`main.mjs` зовёт `startVkSubsystem` только для явно включённого `vk` в профиле
`anna`. `armed=true`, фиксированные группа127999849 и `idleAt` обязательны.
При старте получается свой `groups.getLongPollServer`; начальный `ts` сохраняется,
при рестарте новый key используется с подтверждённым курсором собственной БД.
Key LP остаётся в памяти. `pass` выполняется от пользователя службы: ссылка
на запись передаётся аргументом, значение токена — только в памяти и HTTP-body.
Файл токена также допустим с проверкой прав и типа; значений в образце нет.

События LP, курсор, очередь Анны, карточка и метаданные приёмника фиксируются
одной транзакцией. Повтор объекта LP/API не создаёт второй доставки.
Идентичность — объект провайдера и SHA256 текста/описания вложений; доступная
новая редакция становится новым событием. Сохраняются исходное время и время
приёма. Draft остаётся ограничен4096символами; Anna ingress допускает65536
Unicode codepoints/262144байта без обрезки. Ответ HTTP ограничен8MiB.

Поддержаны `message_new`, `message_edit`, `wall_reply_new`, `wall_reply_edit`,
`wall_post_new`, `wall_post_edit`, `group_join`. Другие LP-типы этой частью
не передаются Анне. ЛС идентифицируется `peer_id/conversation_message_id`;
глобальный `message.id=0` допустим. Сообщение группового чата, поступившее LP,
принимается. Получить его историю ключом сообщества нельзя: REST-обход явно
пишет `group_chat_history_unavailable`, результат становится partial.

Окно перехода: `[2026-10-13T11:25:20Z, T_on+600с]`, включительно. `T_on` — первая
успешная обработка собственного LP-ответа; до него верхняя граница неизвестна.
Приём продолжается во время догрузки. До наступления верхней границы результат
не complete; после неё выполняется финальный обход. Данные и позиции задач
обхода сохраняются в SQLite и переживают restart.

- `messages.getConversations`: `all` и `archive`; `messages.getHistory` — по
  доступным беседам с полной пагинацией.
- `wall.get(domain=naostrov)`: полный доступный перечень постов, включая старые
  родительские посты комментариев за окно.
- `wall.getComments`: все страницы комментариев каждого поста и отдельные
  страницы каждой ветки; preview не считается полной веткой.

Повтор страницы, изменение count, пустая страница при ненулевом остатке и
неверный объект не объявляются EOF. Обход одной итерации ограничен100страницами
и120секундами, HTTP —30секундами, запросы одного API-client разделены350мс.
Для одного REST-job после3отказов — partial без бесконечного повтора. Count
выше100000 отвергается; это предел кандидата, а не утверждение о нагрузке.

`failed=2` обновляет key и сохраняет свой подтверждённый `ts`. `failed=1/3`
записывает gap и требует новой догрузки; текущий `ts` не выдаётся за доказательство
сохранности. Расширение gap требует нового финального обхода после его верхней
границы. После3не-ёмкостных ошибок LP останавливается с phase=halted. При заполнении
очереди курсор стоит, phase=backpressure; после освобождения места приём возвращается.

`receiver.status()` даёт поимённый список provider IDs и позиции обхода для
проверяющей руки. MCP `status` роли monitor даёт только состояние, окно и счётчики.
`coverage.complete` относится к доступным REST-объектам этого окна;
`transition_verified=false`: старый журнал Острова этим кодом не сверялся.
Не покрыты group_join в перерыве, удалённое до догрузки, промежуточные редакции
и unknown-ответы Острова. Живые права ключей и настройки LP пока не измерены.

Все ВК writes этой частью отвергаются до HTTP. Внешний writer ещё не реализован.
Посты и ответы в общей политике уже допускают одобрение любого из трёх текущих
людей из root-настройки; отправка не происходит без отдельного допуска writer.
Будущий ВК writer обязан закрепить owner_id=-127999849/group_id=127999849,
from_group=1; произвольного адресата модель ему не передаёт.

Изоляция Codex снята словом владельца, поэтому прежний статус удержания заменён
`pending_anna_dispatch`. В этой части записи лишь стоят в устойчивой очереди.
Доставка в настоящий ход Анны, группировка уведомлений3500UTF-16, граница HTTP
00:00:00МСК, writers, Meta и refresh — следующие части B-N-2027. В образце
Telegram disabled, writer закрыт; этот образец предназначен для первой части.

Монтаж выполняет назначенная рука. Отдельные каталог пакета, БД, ключи и port8382
предотвращают подмену legacy-профиля. Config/key-файлы должны читаться пользователем
anna с private mode; dependency node_modules — из принятого lock. Новый юнит
добавляет группе процесса `socseti` доступ к каталогу root:socseti0750 с approvers;
постоянные группы пользователя и права `/etc` этой правкой не меняются.
