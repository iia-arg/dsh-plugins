# B-N-2027 — текстовые посты ВК, vkpost4

Версия пакета — manifest (3.1.8). Прежние номера кандидатов и протоколы ниже — история этого участка; старые замеры не являются нынешней живой приёмкой. Общий текущий договор очереди, эхо, настройки и статуса — [REFERENCE](../REFERENCE.md).

Зовущий — `main` Анны, только при явно включённом `vk.writer`. Его timer каждые 5 секунд читает одобренные текстовые черновики ВК. Задание привязано к draft ID/версии/hash; в очереди один write-action на такую версию. Без поля writer отправка закрыта; прежний anna-vk.config.example.json оставляет writer закрытым. Ни один установленный конфиг/юнит Бета не меняла.

В существующий блок `vk` для отдельного принятого включения добавляется только:

```json
"writer": {"enabled": true, "token": {"passRef": "vk/user-token-miniapp"}}
```

Ссылка расшифровывается учёткой службы. Значение остаётся в памяти и HTTPS-body; в argv/лог/пакет не записывается. Для wall.post нужен user token; его scopes/admin-права приняты по слову координатора, живой проверки в этой работе нет. Сервисный/community reader token не подставляется вместо writer token. [Официальная схема wall API](https://github.com/VKCOM/vk-api-schema/blob/333481bd082ad747d4873ef4a77f9247097eeef0/wall/methods.json).

Перед HTTP обязательны точные `owner_id=-127999849`, numeric `from_group=1`, текст одобренной версии и её устойчивый guid. Иные owner/flag, дополнительные параметры/вложения, чужой/неизвестный метод отказывают до HTTP. Этот writer **только текстовый wall.post**. Фото/видео, wall.createComment и messages.send не реализованы. Для комментария в официальной схеме from_group обозначает ID группы, для поста — флаг; уточнение условий передано Забаве отдельным письмом, комментарии удерживаются.

Требуется существующее точное одобрение через карточку Telegram: draft ID, версия, hash, valid approve, действующий человек из owner-reader + принятой root-настройки делегатов. Самостоятельных постов нет. После ожидания общей API-очереди эти условия проверяются снова; TTL проверяется **после** чтения текущего допуска, перед fetch. Удалённый делегат/сменившийся owner возвращает черновик на одобрение с прежним сроком, не пересылает прежнее разрешение. Изменённые hash/версия/цель или истёкший срок отказывают. Разбор одного таймерного такта ограничен очередью до 100 одобренных черновиков и одним выбранным действием.

Клиенты одного фактического токена делят одну очередь. Между завершением предыдущей операции и следующей стоит 350 мс, включая медленный preflight; это консервативнее промежутка между HTTP-запросами. Process-local map содержит только hash токена/clock/promise. Бюджет вызова до 30 секунд включает ожидание очереди/запрос; отменённая queued-операция не начинает поздний HTTP. Долгий синхронный owner-reader ограничен своим 3-секундным пределом; TTL/deadline перепроверяются после него. LP использует свой сервер и отдельный запрос.

Устойчивые исходы:

- queued → sending перед попыткой записи;
- wall.post с положительным post_id означает `accepted_pending_verify`, **не published**;
- отдельный wall.getById читает ровно `-127999849_<post_id>`; только совпадение ID, owner, автора сообщества и текста делает published;
- проверка имеет максимум 3 устойчивые попытки; после неподтверждения либо аварии на третьем счётчике — verification_held, без нового POST;
- sending после restart — unknown; неизвестный transport/ответ, включая malformed/противоречивое поле error, удерживается без повтора записи;
- только типизированный error_code без response — известный отказ. Автоматического повтора POST нет и для него;
- отмена до настоящего запроса — known unsent: возвращается queued; уже начатый запрос при отмене может иметь unknown;
- отказ чтения текущего допуска до claim ограничен 3 тактами, затем worker halted до отдельного перезапуска/разбора.

Reader результата — тот же worker: отдельно verify/recover и обработка исхода call. Статус monitor содержит `vk_post.scope=vk_text_posts_only`, ready/halted и поимённые состояния со счётчиками; журнал содержит draft ID и исход без текста/ключей. Legacy socseti-watch стережёт старый Telegram-instance; этим кандидатом он **не** превращён в полную защиту Анны. Назначение автоматического читателя всего B-N-2027 (включая VK/Meta/доставку/refresh) остаётся частью наряда; ручной журнал не выдаётся за него.

Пробы настоящих Store/TelegramQueue/Api/child main на изолированной SQLite и подставном HTTPS: полные перечни — evidence/VK-POST-COVERAGE.md корня наряда. Независимый review — evidence/REVIEW-VK-POST.md. Вне проверки: live-токен/права/ВК/модель, смонтированный процесс, старые unknown-ответы Острова, формальные ворота и монтаж. Обычные builtins Codex остаются по варианту (а) владельца; эти гарантии относятся к программному writer, не к произвольному стороннему исполнению в движке. Новый отдельно одобренный draft с другим ID — новый intent; межсистемная сверка старых unknown этим модулем не заменяется.
