# Настройки и контракты · Settings and contracts

## Окружение instance · Instance environment

Переменные читаются при загрузке процесса, кроме credential-файла, который проверяется при запросе. Изменение EnvironmentFile требует restart экземпляра; новое значение на диске не меняет окружение живого PID. Таблица описывает текущий код, а не предполагаемый интерфейс vendor SDK.
Environment variables are captured at process load except credential files checked per request. Changing EnvironmentFile requires an instance restart; disk changes do not change a running PID's environment. The table describes current code, not an assumed vendor-SDK interface.

`sdkCompat` в манифесте — ещё два обязательных интерфейса helper: Claude SDK `>=0.3 <0.4`, Codex SDK `>=0.154 <1.0`. Helper берёт npm latest и устанавливает его только при попадании в sdkCompat; если latest вне диапазона или запрещённый prerelease, отказывает и не ищет более старую совместимую версию. Попадание в диапазон не гарантирует отсутствие breaking поведения; после обновления нужны vendor integration tests. SUDO_USER/USER используются только для operator update audit, не для request identity.
The manifest's `sdkCompat` supplies two helper contracts: Claude SDK `>=0.3 <0.4`, Codex SDK `>=0.154 <1.0`. The helper takes npm latest and installs it only if it meets sdkCompat; an out-of-range latest or prohibited prerelease is refused without searching older compatible versions. Meeting a range does not guarantee behavioral compatibility; vendor integration tests are required after upgrades. SUDO_USER/USER are operator-update audit fields, not request identity.

`systemd/gateway@.service` задаёт User/Group instance, token supplementary group, EnvironmentFile, ExecStart, Restart=on-failure/5 seconds. Он намеренно не содержит строгого filesystem sandbox; это должен выбрать оператор под конкретный engine route. `60-journal-read.conf` расширяет права процесса на журнал — не ставить автоматически.
`systemd/gateway@.service` defines instance User/Group, token supplementary group, EnvironmentFile, ExecStart and Restart=on-failure/5 seconds. It intentionally has no strict filesystem sandbox; operators must choose one for their engine route. `60-journal-read.conf` grants journal access to the process and must not be installed automatically.

Гостевой шаблон `systemd/95-gost.conf` очищает группы и окружение, требует net и guest runtime с NoNewPrivileges. `LoadCredential=` в нём сброшен (B-N-1621): гостю отдаётся одна подписка. `ExecStartPre=+/usr/local/libexec/gost-podpiska-vybor %i` от root кладёт копию токена в `RuntimeDirectory=claude-oauth-gost-%i` (`RuntimeDirectoryMode=0500`, systemd удаляет каталог при остановке), а `Environment=CREDENTIALS_DIRECTORY=%t/claude-oauth-gost-%i` указывает launcher на этот каталог. Launcher принимает только token-podpiska-1/2/3; новую selection он громко отвергает. UnsetEnvironment OMEGA_MCP_API_KEY/OMEGA_GOST_KLYUCH/GATEWAY_MCP относится к gateway, не к DSH-service регистрации MCP.
The guest template `systemd/95-gost.conf` clears groups/environment, requires net and a guest runtime with NoNewPrivileges. It resets `LoadCredential=` (B-N-1621): the guest gets one subscription. `ExecStartPre=+/usr/local/libexec/gost-podpiska-vybor %i` runs as root and copies the token into `RuntimeDirectory=claude-oauth-gost-%i` (`RuntimeDirectoryMode=0500`, removed by systemd on stop), and `Environment=CREDENTIALS_DIRECTORY=%t/claude-oauth-gost-%i` points the launcher at that directory. The launcher accepts token-podpiska-1/2/3 only and explicitly rejects new selections. UnsetEnvironment OMEGA_MCP_API_KEY/OMEGA_GOST_KLYUCH/GATEWAY_MCP applies to the gateway, not DSH-service MCP registration.

Помощник `systemd/gost-podpiska-vybor` (в бою `/usr/local/libexec/gost-podpiska-vybor`, root 0755) принимает ровно один довод — имя гостя (`%i`, образец `[a-z][a-z0-9_-]*`). Читает `instance-<гость>.env` из `GOST_ENV_DIR` (умолчание `/etc/claude-oauth`); там должна быть ровно одна строка `GATEWAY_TOKEN_FILE`, и её значение — обычный файл `<GOST_TOKEN_DIR>/token-podpiska-[123]` (`GOST_TOKEN_DIR`, умолчание `/etc/claude-oauth`). Каталог назначения — `RUNTIME_DIRECTORY` юнита (ровно один). Помощник очищает его и кладёт туда `token-podpiska-<N>` (root:<группа каталога> 0440). Любое иное — отказ, код 2, шлюз не стартует. Граница: текущий токен учётка гостя читать может (шлюзу он нужен) — правило «одна из трёх», а не «ни одной».
The `systemd/gost-podpiska-vybor` helper (installed at `/usr/local/libexec/gost-podpiska-vybor`, root 0755) takes exactly one argument, the guest name (`%i`, pattern `[a-z][a-z0-9_-]*`). It reads `instance-<guest>.env` from `GOST_ENV_DIR` (default `/etc/claude-oauth`); that file must contain exactly one `GATEWAY_TOKEN_FILE` line whose value is a regular file `<GOST_TOKEN_DIR>/token-podpiska-[123]` (`GOST_TOKEN_DIR`, default `/etc/claude-oauth`). The destination is the unit's single `RUNTIME_DIRECTORY`. The helper empties it and installs `token-podpiska-<N>` there (root:<directory group> 0440). Anything else is a refusal with exit code 2, and the gateway does not start. Boundary: the guest account can still read the current token (the gateway needs it) — the rule is "one of three", not "none".

Continuation allowlist и mode-file задаются env ключами ниже. Изменённая настройка применяется при новом процессе; marker route требует и явного allowlist, и включения ключа в version 1 mode JSON. Пусто/негодно — прежний mailbox route.
Continuation allowlist and mode file use the environment settings below. Changes require a new process; the marker route requires both explicit allowance and inclusion in the version 1 mode JSON. Empty/invalid input preserves the mailbox route.

Canonical cwd здесь означает lexical path.resolve: без fs.realpath и проверки существования каталога. Разные alias/symlink пути могут получать разные identity keys; не приписывайте этому host filesystem isolation.
Canonical cwd here means lexical path.resolve, without fs.realpath or directory-existence checks. Different alias/symlink paths can produce different identity keys; this is not host filesystem isolation.

## Контракт optional backend · Optional backend contract

Требуются функции stupenZanjatosti, putSessii, fizicheskiyKompakt, porogIzPreseta, reshitKompakt, polnayaZanyatost, vedraPoImeni, zanyatostIzZhurnala; Map STUPEN_SESSII, положительный конечный KOMPAKT_POROG и непустой массив конечных долей KOMPAKT_STUPENI (0 < доля < 1). Reader возвращает положительный porog либо явную prichina при неизвестном пороге. Его поздняя ошибка становится prichina, не аварией транспорта. Флаги KOMPAKT_SHLYUZOVOJ/KOMPAKT_PLATFORMENNYJ сохраняют прежнюю семантику, включая необъявленное значение.
Required functions: stupenZanjatosti, putSessii, fizicheskiyKompakt, porogIzPreseta, reshitKompakt, polnayaZanyatost, vedraPoImeni, zanyatostIzZhurnala; Map STUPEN_SESSII, positive finite KOMPAKT_POROG and a nonempty array of finite KOMPAKT_STUPENI fractions (0 < fraction < 1). The reader returns positive porog or explicit prichina for an unknown threshold. A later reader failure becomes prichina rather than a transport crash. KOMPAKT_SHLYUZOVOJ/KOMPAKT_PLATFORMENNYJ retain legacy semantics, including undeclared values.

Недоступный backend означает: физическое сжатие отказывает; usage buckets, занятость и поиск rollout этим backend недоступны (null), сводки SDK не передаются в memory DB. Встроенное сжатие vendor SDK этим флагом не выключается. Это не изоляция произвольного кода: import и код доверенного backend не имеют отдельного deadline, зависший модуль может задержать старт. Автоповторов import нет; после исправления operator запускает новый процесс.
An unavailable backend means physical compaction refuses; backend usage buckets, occupancy and rollout lookup are unavailable (null), and SDK summaries are not forwarded to memory DB. This does not disable vendor SDK native compaction. It does not isolate arbitrary code: import and trusted backend code have no separate deadline, so a hung module can delay startup. Import has no automatic retries; the operator starts a new process after correction.

## Публичные шаблоны и конфигурация машины · Public templates and machine configuration

Нейтральные /etc/subscription-gateway и /srv/subscription-gateway использует только `systemd/gateway@.service`. Гостевой `systemd/95-gost.conf` несёт пути развёртки: `/etc/claude-oauth/instance-%i.env`, `/opt/subscription-gateway-guest/systemd/guest-launch.sh`, `/opt/subscription-gateway-guest/gateway.mjs`, `/usr/local/libexec/gost-podpiska-vybor`; умолчания `gost-podpiska-vybor` — тоже `/etc/claude-oauth`. Нейтральные значения — для новой установки, а не команды замены существующих unit/drop-in. На машине с другими runtime/credential/config paths оператор задаёт собственные expanded файлы отдельно от npm-пакета. Сбросы groups/env/credentials и guest launcher сохраняют прежнюю семантику.
Only `systemd/gateway@.service` uses the neutral /etc/subscription-gateway and /srv/subscription-gateway locations. The guest `systemd/95-gost.conf` carries deployment paths: `/etc/claude-oauth/instance-%i.env`, `/opt/subscription-gateway-guest/systemd/guest-launch.sh`, `/opt/subscription-gateway-guest/gateway.mjs`, `/usr/local/libexec/gost-podpiska-vybor`; the `gost-podpiska-vybor` defaults are `/etc/claude-oauth` too. The neutral values describe a new installation, not replacement commands for existing units/drop-ins. Hosts with other runtime/credential/config paths maintain their expanded configuration separately from the npm package. Group/environment/credential resets and guest-launcher semantics remain intact.

Экспорт summaries вызывается после SDK compact. GATEWAY_MEMORY_MODULE читается при старте, apply-module импортируется лениво на первой summary и кэшируется до restart. Модуль доверен оператором; arbitrary зависший import/код не изолируется и отдельного deadline нет. Пустое/плохое значение отказывает этой функции; нет background retries. При восстановлении нужен новый процесс/summary вызов.
Summary export is called after SDK compaction. GATEWAY_MEMORY_MODULE is captured at startup; its apply-module imports lazily on the first summary and is cached until restart. It is operator-trusted code: arbitrary hanging imports/code are not isolated and have no separate deadline. Empty/bad configuration refuses this feature; there are no background retries. Recovery requires a new process/summary invocation.
