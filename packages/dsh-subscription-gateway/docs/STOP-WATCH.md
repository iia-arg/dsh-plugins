# Наблюдение после мягкого стопа · Watch after a soft stop (B-N-1577)

Зовущий — `progonAppServer`, ветка давления после успешного JSON-RPC `turn/steer`. Это инструкция модели, а не прерывание. Одно неошибочное транспортное подтверждение ещё не доказывает завершение хода.
The caller is `progonAppServer`, the pressure branch after a successful JSON-RPC `turn/steer`. It is an instruction to the model, not an interruption. One non-error transport acknowledgement does not yet prove that the turn completed.

Через 300000 мс (5 минут) после ответа RPC, если локальное ожидание ещё не закончено, выводится одна строка `STOP_WAIT_TIMEOUT`. Порог — выбранный срок уведомления оператора, не оценка времени завершения модели и не основание принудительного прерывания. Наблюдение различает `waiting-turn` и `closing-app-server`. `ack_bound` означает совпадение возвращённого turnId с ожидаемым. `completed_bound=null` означает отсутствие данных для привязки. Completion с другим turnId журналируется как completed_bound=false и завершает локальный ход, как в 1.4.36. Наблюдатель не вводит запрет на смену хода после steer или авто-продолжения; принадлежность нити проверяется прежним фильтром threadId.
300000 ms (5 minutes) after the RPC reply, if the local wait has not finished, one `STOP_WAIT_TIMEOUT` line is written. The threshold is the chosen operator-notification delay, not an estimate of model completion time and not a reason for a forced interrupt. The watch distinguishes `waiting-turn` and `closing-app-server`. `ack_bound` means the returned turnId matches the expected one. `completed_bound=null` means there is no data to bind. A completion with another turnId is logged as completed_bound=false and ends the local turn, as in 1.4.36. The watch adds no ban on a turn change after steer or auto-continuation; thread ownership is still checked by the existing threadId filter.

При штатном закрытии после тревоги пишется `STOP_WAIT_CLOSED`. Ошибка закрытия даёт `STOP_WAIT_ABORTED`: закрытие дочернего процесса не доказано. После выхода локального генератора таймер снимается. Поздний ответ RPC не взводит его заново. Неошибочный ответ с несовпавшим ID наблюдается с `ack_bound=false`; он не переименовывается в подтверждение нужного хода.
On a normal close after the alert, `STOP_WAIT_CLOSED` is written. A close error gives `STOP_WAIT_ABORTED`: closing the child process is not proven. The timer is cleared once the local generator exits. A late RPC reply does not re-arm it. A non-error reply with a mismatched ID is observed with `ack_bound=false`; it is not renamed into an acknowledgement of the expected turn.

По умолчанию предупреждение идёт в журнал шлюза. Без назначенного читателя журнала внешнее уведомление не обеспечено. Для внешнего канала установщик задаёт `GATEWAY_STOP_WATCH_ALERT` как полный путь к исполняемому файлу, а координатор назначает получателя и читателя тревоги. Команда получает одну строку через stdin, без аргументов. Это не shell-строка: доводы, перенаправления и составные команды не поддерживаются. Файл канала должен быть исполняем пользователем шлюза; конфигурация и её установка — назначенной рукой. Внешний executable получает только PATH и LANG (LANG по умолчанию C), без HOME, CODEX_HOME, GATEWAY_*, API-ключей, NODE_OPTIONS и прочего окружения Codex. Указанный путь executable и необходимые настройки самого канала должны быть самостоятельными: окружение Codex ему не передаётся.
By default the warning goes to the gateway log. Without an assigned log reader, external notification is not ensured. For an external channel the installer sets `GATEWAY_STOP_WATCH_ALERT` to the full path of an executable, and the coordinator assigns the alert recipient and reader. The command gets one line on stdin and no arguments. It is not a shell string: arguments, redirections and compound commands are not supported. The channel file must be executable by the gateway user; its configuration and installation belong to the assigned hand. The external executable receives only PATH and LANG (LANG defaults to C), without HOME, CODEX_HOME, GATEWAY_*, API keys, NODE_OPTIONS or the rest of the Codex environment. The executable path and the channel's own settings must be self-contained: the Codex environment is not passed to it.

Канал запускается один раз на мягкий стоп. Его предел — 30000 мс, затем SIGKILL прямому дочернему процессу; буфер stdout/stderr — 8192 байта. Вывод канала не печатается. Код завершения фиксируется, дальнейшая доставка не утверждается. Канал, порождающий своих потомков, должен сам обеспечивать их уборку: этот предел не убивает группу процессов. Существование боевого получателя локальный стенд не доказывает.
The channel runs once per soft stop. Its limit is 30000 ms, then SIGKILL to the direct child; the stdout/stderr buffer is 8192 bytes. Channel output is not printed. The exit code is recorded; further delivery is not claimed. A channel that spawns its own descendants must reap them itself: this limit does not kill the process group. A local test does not prove that a production recipient exists.

Предупреждение и новые поля очищаются существующим `secret-redact.mjs`: известные секреты процесса длиной от 16 знаков в буквальной, JSON и URI формах; provider IDs проходят список допустимых форм. Не ловятся иные кодировки, секреты других процессов или вывод канала напрямую мимо захваченных stdout/stderr.
The warning and the new fields are cleaned by the existing `secret-redact.mjs`: known process secrets of 16 characters or more in literal, JSON and URI forms; provider IDs pass an allowlist of valid shapes. Not caught: other encodings, secrets of other processes, or channel output written directly around the captured stdout/stderr.

Область прибора — локальный генератор шлюза и закрытие его app-server. Платформенный `turn/end`, получение продолжения агентом, зависание до ответа RPC, ход без pressure-stop, блокировку event loop, смерть или рестарт самого шлюза, внутреннюю причину зависания SDK/модели он не доказывает. Никакого автоматического `interrupt`, рестарта или повторного запуска нет.
The instrument's scope is the gateway's local generator and the closing of its app-server. It does not prove the platform `turn/end`, the agent receiving the continuation, a hang before the RPC reply, a turn without pressure-stop, an event-loop block, death or restart of the gateway itself, or the internal cause of an SDK/model hang. There is no automatic `interrupt`, restart or rerun.

Проверки: `test/stend-pressure-stop-watch.mjs` использует реальный генератор и подставной RPC peer; `test/stend-pressure-stop-watch-process.mjs` — настоящий JSON-RPC дочерний процесс и подменённый через переменную модуля канал. Срок тревоги в них ускорен до 30/50 мс; канал с зависанием проверяется при настоящем пределе 30000 мс. `test/stend-pressure-stop-review.mjs` проверяет completion после смены ID и фактическое окружение отдельного канала, который печатает process.env; пять секретов — синтетические. Полный пятиминутный срок на живой службе проверяет монтажная рука после ворот.
Tests: `test/stend-pressure-stop-watch.mjs` uses the real generator and a fixture RPC peer; `test/stend-pressure-stop-watch-process.mjs` uses a real JSON-RPC child process and a channel replaced through a module variable. The alert delay is shortened to 30/50 ms there; a hanging channel is checked with the real 30000 ms limit. `test/stend-pressure-stop-review.mjs` checks completion after an ID change and the actual environment of a separate channel that prints process.env; the five secrets are synthetic. The full five-minute delay on a live service is checked by the deploying hand after the gate.
