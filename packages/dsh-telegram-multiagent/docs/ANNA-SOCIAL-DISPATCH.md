# B-N-2027 — событие в обычный ход Анны

Зовущий: единственный Telegram-poller Анны, `ctx.effect`, только при `agentName=anna` и явно заданном `social`. Настройка `social` прежняя: serviceUrl loopback/порт Анны, root/anna private keyFile с ролью channel, существующие channelId/discussionId. Дополнительного getUpdates нет. `startSocialDispatch` опрашивает `/channel/pending` каждые 5 секунд, не дожидаясь рабочего часа отправки карточек. Максимум 20 событий за такт; при длительном такте второй не запускается.

Маршрут — тот же `marshrutChata(-1001659691422)`/`agentFor`, которым пользуются люди в «Маркетинге». Это обычная беседа, вариант (а) владельца; изоляция Codex не требуется. Внешний текст обёрнут как external_untrusted_data и приходит с source agent-message/social. Программные команды Telegram, цели, coordinator envelopes и ownerResume не вызываются. Данные и capability event_token лежат в приватном ledger/входе Анны; в общую память программно не записываются. Обычные инструменты движка доступны по решению владельца; этот адаптер не является их изоляцией и не доказывает соблюдение моделью всех инструкций об обработке чужого текста.

У socseti один event ID и отдельные устойчивые задания модели и часового уведомления. Модель получает ID/token, может сделать draft_reply/draft_post через свой MCP-principal. Социальный writer — отдельная часть; публикация/ответ требуют одобрения одного из троих. Обычный результат хода `expects_reply=0` не создаёт дополнительного сообщения Telegram. Черновик с кнопками отправляет socseti отдельно, уведомления группирует до 3500 UTF-16.

Доставка имеет стадии: receive → prepare stable DSH ID → queue → flush с подтверждением именно этого ID → ACK socseti → отдельное claim/turn/end. ACK означает устойчивый вход DSH, **не прочтение моделью и не выполненный ответ**. Исход ACK неизвестен — тот же receipt и повтор только ACK; исход native send неизвестен — общий ledger удерживает dispatch_unknown без слепого повторения. Изменённое тело того же outbox ID удерживается как конфликт. Payload hash сверяется до dispatch. Тело privateHTTP ограничено 8 MiB; это покрывает 20 максимальных разрешённых ingress-текстов. Остальные запросы social ingress ограничены 64 KiB.

После трёх попыток delivery соответствующий pending переходит в held. Если durable admission ещё нет, **общий receipt тоже blocked**, поэтому receiptTick не обходит этот предел. Уже flushed input при отказах ACK не блокируется: его обработка моделью правомерна, повтор входа запрещён. Три последовательных отказа чтения pending останавливают dispatcher; счётчик устойчивый. Возобновление после held — ручной разбор координатора, не бесконечный retry. Ключ и внешние тексты не выводятся в логи; там только outbox ID/стадия.

Второй монтаж той же учётки бота не создаёт второй timer; последний снятый монтаж clearInterval + run.alive=false. Lifecycle проверяется после чтения pending, после поиска агента и перед следующими dispatch/ACK. Уже начатые native/HTTP действия могут завершиться; автоматического отката принятого входа нет.

Проверки — семь поимённых стендов в evidence/SOCIAL-DISPATCH-FINAL-REGRESSION.log корня наряда, включая actual native DSH/jsonl, ReceiptRuntime/recovery/offset, queue/source, ingress и настоящий извлечённый index callback/effect. Порча ACK без flush → RED → исходный код GREEN, с отдельными SHA/count. Independent review в evidence/REVIEW-SOCIAL-DISPATCH.md. Вне проверки: live-модель, соцсети, токены/живой ключ, права Anna в бою, mounted PID, формальные ворота и монтаж.
