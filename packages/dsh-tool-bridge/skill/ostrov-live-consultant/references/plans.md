# Поля планов

ID ресурсов, доступные месяцы, вместимость, слоты, цены и правила берутся из catalog. Даты в примерах ниже — форма записи, не обещание доступности.

## Малая группа — group

plan:
- policyVersion:3;
- week: суббота начала недели YYYY-MM-DD;
- adults: взрослые участники без команды;
- teens: участники льготного возраста по настройкам;
- extraTeam: дополнительные организаторы без основных мастеров;
- group: adults+teens;
- foodDays:7;
- organizer, title: строки;
- housing: [{resource,occupancy,quantity}];
- activities: [{resource,day,slot,options}].

day — целое от 0 до 7: суббота заезда — 0, среда — 4, четверг — 5, суббота выезда — 7. В день 0 доступны только слоты с началом не раньше 12:00; в день 7 — только заканчивающиеся до 12:00 включительно. slot — ID из catalog.resources[].slots, не произвольная строка времени. Допустимость проверяет сервер. options — массив ID опций конкретного ресурса. Основные мастера добавляются по настройкам автоматически. Жильё должно покрыть всех участников и команду; при неполном расселении итог может быть не определён, а заявка отвергнута. Не исправляй недостаток мест только изменением счётчика людей.

## Большая группа — biggroup

plan: {policyVersion:3,week,adults,teens,extraTeam,organizer,title}.
Условия порога и скидок объясняй по актуальному quote/catalog; основные мастера и льготная часть команды учитываются сервером. Не переносить цену с человека на странице авторского ретрита в тариф центра.

## Резидентство — resident

Новый plan: {name,arrival,departure,adults,children,housing,bathVisits}.
children — возраста учитываемых детей на заезд, не количество: от catalog.residents.childFreeUnder до 17 лет включительно. Детей младше этой границы в payload не включать: API их отвергает; объясни гостю соответствующее правило бесплатного проживания из актуального каталога. housing — [{resource,occupancy}], по одной строке на комнату. Сумма occupancy равна adults+children.length. Сначала расселяются взрослые, затем дети в порядке children. Ребёнок получает скидку по своему возрасту на фактическое место и питание, не уменьшает число кроватей. bathVisits — посещения на каждого гостя.

Старые планы могут иметь resource и occupancy вместо housing. Сервер поддерживает их; не объявляй такую смету испорченной. У старого плана может отсутствовать name. Для сохранения заполни name (либо organizer у группы) и используй plan.create со свежей catalogVersion. Для редактирования сначала plan.read, затем plan.edit с непрозрачной строкой documentVersion и catalogVersion. Не меняй версии по догадке. Заявки и бронь этому инструменту закрыты.
