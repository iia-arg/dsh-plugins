### 2026-10-04 — понятный отказ без группы · a clear refusal without the group

- Новый `bin/proverit-ustanovku.sh`: до запуска проверяет, что на машине есть все группы из `Group=` и `SupplementaryGroups=` юнита; нет группы — отказ с её именем, код 1; юнит не прочитан или групп в нём нет — код 2. Вызов добавлен в шаг 4 установки перед `enable`. · New `bin/proverit-ustanovku.sh`: before start it checks that every group from the unit's `Group=` and `SupplementaryGroups=` exists; a missing group — a refusal naming it, exit 1; unreadable unit or no groups in it — exit 2. The call is added to install step 4 before `enable`.
- Почему не в юните: проба временным юнитом с несуществующей дополнительной группой — systemd отказывает `216/GROUP` («Failed to determine supplementary groups: No such process») раньше любого `ExecStartPre=`, даже с `+`. Строка журнала добавлена в раздел поломки `216/GROUP`. · Why not in the unit: a transient-unit probe with a nonexistent supplementary group — systemd refuses with `216/GROUP` ("Failed to determine supplementary groups: No such process") before any `ExecStartPre=`, even with `+`. The journal line is added to the `216/GROUP` troubleshooting section.
- Новый стенд `test/stend-gruppy.sh` (9 проб); в проверках приёмки — пункт 4б. Директивы юнита не менялись. · New stand `test/stend-gruppy.sh` (9 probes); acceptance check 4b. The unit directives are unchanged.
- Проверка читает и вставки юнита: путь к файлу — сам юнит и `<путь>.d/*.conf` по правилам systemd (последнее `Group=` побеждает, `SupplementaryGroups=` копится, пустое значение сбрасывает список, нечитаемая вставка — код 2); имя юнита — итог `systemctl show`. Прежде группа, заданная только во вставке, давала ложное «группы есть». · The check also reads the unit's drop-ins: a file path — the unit and `<path>.d/*.conf` by systemd rules (the last `Group=` wins, `SupplementaryGroups=` accumulates, an empty value resets the list, an unreadable drop-in is exit 2); a unit name — the `systemctl show` result. Before, a group set only in a drop-in produced a false "groups exist".

### 2026-10-04 — документация перенесена на боевой юнит · documentation moved to the production unit

- Строки юнита, исполняемые systemd, теперь те же, что в боевом юните: `Description=OMEGA memory server (omega-memory core)`, добавлены `SupplementaryGroups=omega-users`, `UMask=0002`, `Environment="OMEGA_DEDUP_THRESHOLDS=…"`. Комментарии к ним двуязычные и обезличенные. · Lines executed by systemd now match the production unit: `Description=OMEGA memory server (omega-memory core)`, added `SupplementaryGroups=omega-users`, `UMask=0002`, `Environment="OMEGA_DEDUP_THRESHOLDS=…"`. Their comments are bilingual and anonymized.
- Описана модель доступа через общую группу `omega-users`: группа и маска открывают служебные файлы движка, но не базу и не ключ (движок держит их с явными `600`/`700`). Установка дополнена созданием группы и setgid каталога данных. · Documented the shared-group access model `omega-users`: the group and mask open the engine's auxiliary files, not the database or the key (the engine keeps those at explicit `600`/`700`). Install gained group creation and the data directory setgid step.
- Описаны пороги склейки повторов `OMEGA_DEDUP_THRESHOLDS`: смысл, умолчания движка, отказ на неверном значении, влияние на пробную запись приёмки. · Documented the repeat-collapse thresholds `OMEGA_DEDUP_THRESHOLDS`: meaning, engine defaults, failure on a bad value, effect on the acceptance test record.
- Сказано прямо: ожидания готовности после старта (`ExecStartPost=`) в юните нет; drop-in'ы боевой машины (ключ через `EnvironmentFile=`, многоязычная модель, режим без сети) в пакет не входят. · Stated plainly: the unit has no post-start readiness wait (`ExecStartPost=`); the production machine's drop-ins (key via `EnvironmentFile=`, multilingual model, offline mode) are not part of the package.
- Новые разделы поломок: `216/GROUP`, агент из группы не видит служебные файлы, «Deduped» вместо новой записи. · New troubleshooting sections: `216/GROUP`, group member cannot see auxiliary files, "Deduped" instead of a new record.
