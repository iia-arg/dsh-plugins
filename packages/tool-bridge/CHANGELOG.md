# Изменения

История версий `dsh-tool-bridge`. Переехала сюда из README 03.09.2026: README
отвечает на вопрос «что это и как поставить», CHANGELOG — «что изменилось».

## Версия 0.3.1 — меняется поведение при пропаже источника событий

Ломающих изменений в составе нет: файлы те же. Меняется РЕШЕНИЕ модуля в одном
случае, и об этом надо знать заранее.

Все три предела самопробуждения (подряд, за сутки, за час) считаются из журнала
событий сессии. Раньше, если журнал не удавалось получить, модуль пропускал
проверку и ставил пробуждение с запрошенным интервалом — то есть отсутствие
источника означало РАЗРЕШЕНИЕ. Отказ был тихим: пределов не видно ни одного, а
снаружи всё выглядит исправным.

Теперь:

    источник есть, событий 0     -> законный ноль, пределы считаются
    источник не получен вовсе    -> ОТКАЗ: пробуждение отодвигается на сутки,
                                    и человеку уходит тревога

Тревога уходит один раз, дальше не чаще раза в сутки; подавленные считаются, а
при возврате источника модуль говорит об этом вслух с числом подавленных и
длительностью отказа. Без этого молчание после первой тревоги было бы
неотличимо от «всё починилось».

🔴 ГРАНИЦА: состояние выдержки живёт в памяти процесса. Перезапуск модуля его
сбрасывает, и первая тревога уйдёт снова — намеренно: молчание не должно
наследоваться от прошлой жизни процесса.

Путь к отправщику тревог — настройка `DSH_ALERT_CMD`, не константа. Отправщика
нет — модуль говорит об этом вместе с текстом самого события, а не молчит.

## Версия 0.3.0 — новое: резюме полосы самопробуждений

Ломающих изменений нет: добавлена способность, состав файлов только пополнился
(`test/stend-rezyume.mjs`).

Полоса автономных пробуждений кончается — модуль теперь говорит об этом. Раньше
не говорил, и это была настоящая дыра: одноразовое напоминание после
срабатывания исчезает само, снимать нечего, следа не остаётся. Человек,
вернувшийся к переписке, не мог узнать из журнала ни что полоса была, ни чем
она кончилась. Замер по журналу за десять суток: из пяти полос ни одна не
кончилась ни исчерпанием предела, ни снятием напоминания рукой — четыре оборвало
внешнее слово, одна кончилась молча.

    агент объявил итог сам      «полоса из N закрыта агентом: <итог>»
    объявления не было          «полоса из N оборвалась без объявления,
                                 с ЧЧ:ММ до ЧЧ:ММ»

Появился десятый инструмент — `heartbeat_close`. Им агент объявляет итог в
последнем автономном ходу; итог печатается немедленно. Вызов — соглашение, а не
обязанность: не позвали — резюме всё равно будет, только числами.

Настройка `rezyumirovatPolosu` (умолчание — печатать). Подробности механизма и
его границы — в `SAMOPROBUZHDENIE.md`, раздел «Резюме полосы».

## 🔴 Версия 0.2.0 — ЛОМАЮЩЕЕ ИЗМЕНЕНИЕ: файлы внутри пакета переименованы

Старые имена больше не действуют. Если вы ссылались на них — поправьте:

    было (0.1.1)              стало (0.2.0)
    src/parity.json           src/paritet.json
    src/schedule.json         src/raspisanie.json
    tools/extract-parity.mjs      tools/izvlech-paritet.mjs
    tools/extract-schedule.mjs    tools/izvlech-raspisanie.mjs
    test-heartbeat.mjs        test/stend-heartbeat.mjs
    test-startup-lines.mjs    test/stend-cel-mosta.mjs

Почему так. В версии 0.1.1 имена файлов и пояснения переводились на английский
вручную при каждом выпуске. Ручное преобразование не повторяется одинаково и не
переживает второго исполнителя: за неделю опубликованное разошлось с рабочим
кодом на семь функций, и заметить это было нечем. Теперь публикуется то, что
работает, без промежуточного шага. Один раз объявленное переименование дешевле,
чем перевод при каждом выпуске.
