ПОЧЕМУ cordis.patch.yml, README.md И CHANGELOG.md ЛЕЖАТ ЗДЕСЬ, ХОТЯ РАНЬШЕ ИХ НЕ БЫЛО

Раньше в этом каталоге лежала записка «их тут нет намеренно, они собираются при выпуске».
Она была неверна, и вот замер, которым это установлено 05.09.2026:

    npm pack из ЭТОГО каталога без файлов → 19 → 16 файлов, cordis.patch.yml НЕ вошёл
    npm при этом МОЛЧИТ: отсутствующий файл из files не даёт ни ошибки, ни предупреждения

То есть «собирается при выпуске» было обещанием без исполнителя: шага сборки нет ни в
scripts пакета, ни в обёртке публикации. Тарбол 0.3.5 в реестре содержит все три файла
только потому, что тогда они ещё лежали здесь. Следующий выпуск уехал бы БЕЗ образца
настроек — и посторонний, поставивший пакет, не получил бы блока для `dsh plugin add`.

ЧТО ИЗМЕНИЛОСЬ И ПОЧЕМУ ЭТО БЕЗОПАСНО
Платформа читает cordis.patch.yml СЛОЯ ПРОФИЛЯ ($DSH_HOME и профиль агента), а файл в
каталоге плагина не читает вовсе — проверено по коду загрузчика профилей. Значит наличие
образца здесь на работу моста не влияет: он нужен команде установки, а не платформе.

ЧТО ЭТО ДАЛО СВЕРХ ПОЧИНКИ СОСТАВА
Сумма рабочего каталога теперь может совпасть с тарболом — то есть предмет перестал быть
непроверяемым. Прежде он выпадал из ворот приёмки навсегда и молча: «намеренное отличие»
без механизма делает предмет несверяемым ни с чем внешним.

⚠️ ЕСЛИ РЕШИТЕ ВЕРНУТЬ ПРЕЖНИЙ ПОРЯДОК: сначала заведите настоящий шаг сборки (prepack или
явный шаг в обёртке публикации) и проверьте его тем же замером — числом файлов в тарболе.
Без этого исключение снова станет обещанием.
