# Канарейка шлюза

Проверяет, **поднимется ли шлюз после перезапуска**, — до того как перезапуск сделан.

Родственна `../kanarejka-restarta` (та же задача для платформы), но предмет иной:
шлюз держит подключение агента, и его отказ невосстановим изнутри — процесс агента
живёт в дереве шлюза, так что чинить сломанный шлюз будет некому.

## Зачем именно проба, а не проверка синтаксиса

```
порча:  вызов несуществующей функции перед созданием сервера
node --check   ->  чисто, порчи НЕ ВИДИТ
канарейка      ->  код 1, «процесс умер: ReferenceError: netTakojFunkcii is not defined»
```

`node --check` судит только грамматику и молчит о несуществующем методе или импорте:
отказ отложенный, файл выглядит исправным до первого боевого запуска. А импорт точки
входа проверкой быть не может — он **запускает службу**. Между этими двумя крайностями
и живёт канарейка: она поднимает КОПИЮ и смотрит, что та делает.

## Что считается успехом

Не «процесс стартовал» и не «порт открылся», а три вещи подряд:

1. процесс жив — и если умер, называется **первая** строка ошибки (причина), а не хвост стека;
2. порт занят — замером, а не ожиданием удачи;
3. `/health` отвечает **по существу** — читается тело ответа, а не факт соединения.

Третье не формальность: живой порт при `{"ok":false}` — обычный вид сломанного шлюза.

## Запуск

```sh
KANAREJKA_DOM=/путь/к/установке ./kanarejka-shlyuza.sh
```

Умолчания «мой каталог» нет намеренно: отсутствие переменной даёт слепоту с причиной,
а не тихий поиск чужого пути.

| код | значение |
|-----|----------|
| 0 | копия поднялась и отвечает по существу |
| 1 | **расхождение**: назван поимённо отсутствующий ключ или причина падения |
| 2 | **слепота**: проверить нечем |

## Стенд

```sh
KANAREJKA_ISHODNYJ_DOM=/путь/к/боевой ./stend-kanarejki-shlyuza.sh
```

⚠️ **Права:** стенд читает файл шлюза, поэтому запускается от того, кому этот файл
доступен (root либо владелец каталога установки). Под другим пользователем стенд
честно слепнет и называет нечитаемый путь — это верное поведение, а не отказ.

Стенд проверяет предмет **порчами**: синтаксис, падение при чистой грамматике,
`/health` не по существу, отсутствие сущности в списке, незнакомая настройка. Сверяет
исполненное с заявленным составом и отдельно сообщает пропущенное.

## Две ловушки, найденные при постройке

**Порча в чужом месте проверяет место, а не порчу.** Копия шлюза, положенная в
посторонний каталог, падала по отсутствию соседнего модуля — то есть стенд проверял
собственную фикстуру, а не предмет. Признак, которым это ловится: **диагноз не совпал
с внесённой порчей**. Поэтому фикстура кладёт рядом соседние файлы и данные предмета.

**Верный код исхода по чужой причине.** Случай «сущность убрана из списка» однажды дал
ожидаемый код при отключённой защите: копия не поднялась, потому что боевой порт был
занят — исход совпал случайно. Поэтому код исхода и содержание вердикта проверяются
**врозь**: отдельно код, отдельно то, что отказ называет ключ поимённо.
